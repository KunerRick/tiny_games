# 试玩-修复闭环：用子代理替掉「人工转发」

> 适用：需要反复「试玩出报告 → 开发修复 → 复核」时。
> **触发方式**：说 **「试玩循环」**（或「跑一轮试玩」「继续处理试玩报告」），
> 或直接用斜杠命令 `/playtest <范围>`（例：`/playtest fridge N34/N35`）。
> 本地入口：`.claude/skills/playtest-cycle/SKILL.md`（gitignored，只做指针）；
> 斜杠别名：`.claude/commands/playtest.md`。
> 本文是协议正文，改动请改这里。

## 0. 为什么不该再用两个会话

原来的流程里，人承担的是**传输层**：把报告粘给开发、把结论粘回试玩。这一步不产生任何判断，
却要求人全程在线。Claude Code 已经有够用的原语：

| 原语 | 在闭环里的角色 |
|---|---|
| `Agent`（fresh subagent） | 试玩者 / 复核者。干净上下文，且可用浏览器 + MCP |
| 主会话 | 调度者 + 开发者（读报告、改代码、跑自检） |
| 文件（`docs/plans/*-playtest-*.md`） | 交接协议。报告本身就是下一位的输入 |
| `SendMessage` | 需要让同一个子代理继续（保留它的上下文）时用 |

**不需要**：`/loop`（那是定时心跳，不是状态机）、`fork` 子代理（继承开发者结论，等于没复核）。

## 1. 硬约束（违反会白跑一轮）

1. **串行**：预览服务（`http://127.0.0.1:7456/`）与 Cocos MCP 都是单例，同一时刻只能有一个角色
   操作浏览器/编辑器。不要为了"省时间"把试玩和修复并行。
2. **在执行目录里改代码**：Cocos 编辑器只编译它启动时打开的工程目录，worktree 里的 `.ts`
   改动预览看不到。除非明确要求在 worktree 里做，否则一律在当前工作目录改。
3. **复核者必须是 fresh 上下文**：用 `Agent` 新建（`subagent_type: "claude"` 或 `"general-purpose"`），
   **不要用 `subagent_type: "fork"`** —— fork 继承开发者的上下文，会照着修复思路去找证据。
   试玩者同理。
4. **试玩者不改任何 `.ts` / 场景 / 预制体**，只产报告。修复是主会话的职责。
5. **子代理的简报必须自包含**：它看不到本会话历史。游戏名、场景名、上一轮报告路径、
   本轮范围、验收标准都要写全。
6. **收尾关浏览器**：子代理结束时必须 `browser_close`。后台跑完不关的 headless Chrome +
   软件渲染 Cocos 会烧到 600% CPU（已知事故）。

## 2. 角色分工

| 角色 | 谁扮演 | 能做什么 | 交付物 |
|---|---|---|---|
| 试玩者 | fresh 子代理 | 只读 + 浏览器操作 + MCP 只读查询 | `docs/plans/<日期>-playtest-round<N>-<范围>.md` |
| 开发者 | 主会话 | 改 `.ts`、MCP 改场景/预制体、跑自检 | 代码 + `git diff` + 修复记录 |
| 复核者 | fresh 子代理 | 只读 + 浏览器操作，只看上一轮报告和 `git diff` | 报告「复核」章节，或 `*-reverify.md` |

## 3. 报告格式（机读区是自动化的关键）

路径：`docs/plans/YYYY-MM-DD-playtest-round<N>-<scope>.md`，`<scope>` 用游戏 id 或 `all`。
**问题编号跨轮连续**（仓库现状已到 N35，下一轮从 N36 起，不要重编号）。

报告必须包含下面这个可机读表格，放在正文靠前位置：

```markdown
## 问题清单（机读区）

| ID | 级别 | 游戏 | 场景/入口 | 现象 | 复现步骤 | 期望 | 证据 |
|----|------|------|-----------|------|----------|------|------|
| N36 | P1 | fridge | 商店 → 半心商品 | 满血时可点击，提示「金币不够」 | 满血进入第 1 层商店，点半心 | 置灰或提示「血量已满」 | 探针 `_core.coins=…` / 截图 |
```

级别定义（沿用仓库口径）：

- **P0** 玩家会直接放弃（卡死、无法继续、白屏、必崩）
- **P1** 严重误导 / 主流程受阻（提示与判定矛盾、关键按钮无响应）
- **P2** 明显打磨问题（文案错、状态不同步、面板不刷新）
- **P3** 细节瑕疵 / 建议

另需三节：**方法与数据说明**（视口、坐标换算、是否改过状态）、**未复现/已排除的疑点**、
**复现配方**（能被下一个人照着重放的最小步骤）。

## 4. 试玩者简报模板

> 你是这个项目的**试玩玩家 / QA**，不是开发者。你没看过本轮的任何代码改动，
> 也不需要看 —— 你的价值就是"什么都不知道的玩家"视角。
>
> 项目：`/Users/kuner/work/code/github/tiny_games`（Cocos Creator 3.8.8 小游戏集合）
> 本轮目标：<游戏名 + 场景名>，重点验证：<上一轮 P0/P1 列表 / 新功能 / 新手前 3 分钟>
> 上一轮报告：`<路径>`（先读它，但**只把它当待验证清单**，不要相信它的结论）
>
> 规则：
> - 预览 `http://127.0.0.1:7456/`，先 `lsof -nP -iTCP:7456 -sTCP:LISTEN` 确认在跑；
>   没在跑就停下来报告，不要自己启动编辑器。
> - **每轮现场标定坐标**：`clientX = a + uiX × k` 这类换算每轮会变（实测出现过 1 / 2 / 1.225）。
>   在 Canvas 上挂 `TOUCH_START` 读 `getUILocation()` 反解，不要沿用旧公式。
> - 只走游戏自身的输入路径（真实点击 / 按钮绑定的方法），**禁止改金币、血量、道具、存档**
>   伪造进度；用页内探针读回状态做断言。
> - 桌面拖拽结束事件是 `TOUCH_CANCEL`；监听挂两个子树的共同父级。
> - 改过 `.ts` 之后要先 `project_refresh_assets` 再整页 reload，否则跑的是旧代码。
> - 结束时 `browser_close`。
>
> 产出：按 §3 格式写报告，**只写你实际复现过的**；没复现的放「已排除的疑点」。

## 5. 复核者简报模板

> 你是**独立复核者**。你只拿到：试玩报告 `<路径>`、开发者的 `git diff`、以及当前工程。
> 不要相信报告或 diff 里的自述，逐条用浏览器/MCP 读回状态验证。
> 重点回答三个问题：① 上轮每个 P0/P1/P2 是否真的修好（给证据）；② 修复有没有引入新问题
> （回归）；③ 报告里有没有"说法对但玩家实际遇到的是另一回事"的错位。
> 产出：在报告末尾追加「复核」章节，或另写 `<日期>-playtest-round<N>-reverify.md`。
> 结束时 `browser_close`。

## 6. 主会话的调度流程

```
1. 确认前置：预览服务在跑？（lsof）编辑器 MCP 在线？（server_get_server_status）
   任一不满足 → 告诉用户开哪一个，不要自己拉起编辑器
2. 若没有可用报告：Agent(试玩者简报) → 等报告落盘 → 读报告机读表
3. 按 P0 → P1 → P2 → P3 处理；每修一个：
   - 改完立刻跑 `npx tsc --noEmit`（或编辑器自带 tsc，见 AGENTS.md）
   - 有对应纯逻辑自检的跑 `node tools/verify-<game>-core.js`
   - 场景/预制体改动走 MCP，改完 `validate_scene`
4. P0/P1 清零后：Agent(复核者简报) → 读复核结论
5. 复核仍有 P0/P1 → 回到 3；否则停
6. 收尾：更新报告状态、`git diff --stat` 检查范围、按仓库规范提交
```

**退出判据**：连续一轮复核后无新增 P0/P1，且上轮 P0/P1 全部有证据关闭。
P2/P3 不阻塞退出，但必须在报告里留下"未处理 + 原因"。

**轮数上限**：默认 3 轮。超过就停下，把剩余 P1 列给用户决定（不要无限自我修复）。

## 7. 不该用这个流程的场景

- 只是想快速看一眼某个改动 → 直接改完自己验，不用起试玩者。
- 全站 20+ 款游戏的确定性大扫 → 适合 Workflow（需用户显式说"用 workflow"），
  但**仍然必须串行**，因为预览是单例。
- 定时轮询 → 那是 `/loop` 的事，不是状态机。

- [ ] `npx tsc --noEmit` 通过
- [ ] 对应 `verify-*.js` 通过
