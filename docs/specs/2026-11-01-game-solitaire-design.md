**日期**: 2026-11-01
**版本**: v1.0
**状态**: 设计中
**代号**: `solitaire` / 场景 `Solitaire` / 目录 `assets/games/game_solitaire/`

## 1. 概述

经典克朗代克接龙（Klondike）的单人版本，作为 Tiny Games 合集的第九款游戏。

**定位**：现有 8 款游戏要么靠操作、要么靠关卡内容；本作是第一款「**规则深、可暂停、随时拿起放下**」的游戏。耐玩性来自规则组合空间，内容成本为零。

**核心目标**

- **零美术**：全部用 `Graphics` + `Label` 绘制，不新增任何图片资源（与 7/8 款现有游戏一致）
- **经典规则**：7 列牌堆、4 个收牌区、抽 1 张 / 抽 3 张两档难度
- **单手竖屏**：所有操作在拇指可达区；支持拖拽与点击自动移动两条路径
- **不惩罚中断**：任何时候退出，回来接着打
- **决策友好**：无限撤销 + 提示，让玩家把注意力放在「走哪一步」而不是「我刚才点错了」

**非目标（v1 不做）**

- 蜘蛛纸牌、空当接龙（共用引擎，留到 v2）
- 可赢局发牌（需要求解器，见 §11）
- 排行榜、每日挑战、皮肤商店
- 音效与背景音乐（只做震动反馈）

## 2. 核心规则

### 2.1 牌与数据表示

| 属性 | 值 |
|------|-----|
| 牌数 | 52 |
| 花色 | `'S'` 黑桃 / `'H'` 红桃 / `'C'` 梅花 / `'D'` 方块 |
| 点数 | `rank` = 1–13（A=1，J=11，Q=12，K=13） |
| 颜色 | `isRed = suit === 'H' \|\| suit === 'D'` |
| 正面 | `faceUp: boolean`；牌堆区与收牌区的牌恒为正面 |

```ts
interface Card { suit: Suit; rank: number; faceUp: boolean; }
```

牌对象在整局内**不变（immutable）**，移动只改变它所在的数组；`faceUp` 变化时替换为新对象，避免撤销快照被就地修改污染（见 §2.8）。

### 2.2 发牌

1. 用种子随机数生成 52 张牌的洗牌序列（`mulberry32(seed)` + Fisher–Yates）
2. **按列发牌**：`for p in 0..6: for k in 0..p: 发一张到第 p 列`，共 `1+2+…+7 = 28` 张
3. 每列**最后一张**（`k === p`）翻正面，其余背面
4. 剩下 24 张进牌堆，全部背面，顺序即抽牌顺序

| 列号 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|------|---|---|---|---|---|---|---|
| 牌数 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| 正面 | 1 | 1 | 1 | 1 | 1 | 1 | 1 |

**种子必须存档**：同一个 `seed` + 同一个 `drawCount` 必须复现同一副牌，用于复盘和缺陷复现。调试接口 `deal(seed)` 可指定种子。

### 2.3 牌堆与废牌堆

| 模式 | 每次抽牌 | 重洗 | 计分 | 定位 |
|------|----------|------|------|------|
| 抽 1 张 | 1 张 | 每局最多 3 次 | 不扣分 | 默认，休闲 |
| 抽 3 张 | 最多 3 张 | 每局最多 3 次 | 每次重洗 −20 | 标准难度 |

- **数组约定**：`stock[0]` 是**下一张要抽的牌**；`waste[waste.length - 1]` 是**废牌堆顶**（唯一可操作的牌）
- **抽 3 张**：依次取 `stock[0]`、`stock[1]`、`stock[2]` 压入 `waste`，因此第三张在顶（与实体发牌一致）。剩余不足 3 张时抽完为止
- **重洗**：牌堆为空时点击牌堆，`stock = waste.slice()` 全部翻背面，`waste = []`。顺序**不反转**——实体上整叠翻面后，最早弃掉的牌回到顶部，这个顺序恰好等价于原数组
- **重洗上限**：一局最多 `MAX_RECYCLES = 3` 次（两种模式共用）。不设上限时抽 1 张可以无限翻牌，一局能拖到天荒地老且毫无决策压力；3 次也是纸牌接龙的常见约定。次数用完后点牌堆不产生任何状态变化，只弹提示「重洗次数已用完（每局 3 次），试试撤销或新开一局」
- **次数可见**：顶栏常驻「重洗 N/3」，每重洗一次就减 1。重洗次数进撤销栈，撤销一次即回退一次
- **不允许**在牌堆非空时重洗；重洗不消耗回合，但要计 `recycle` 次数

### 2.4 合法移动

| 来源 → 目标 | 规则 |
|-------------|------|
| 列 → 列 | 降序（差 1）+ **异色**；可整段移动（见下） |
| 列 → 收牌区 | 只能移**单张**，且是该花色的下一张（A 起） |
| 废牌堆顶 → 列 | 同「列 → 列」 |
| 废牌堆顶 → 收牌区 | 同上，单张 |
| 牌堆 → 废牌堆 | 抽牌（§2.3） |
| 收牌区 → 列 | 允许，单张，−15 分（防误点） |
| 空列 | **只接受 K**（任意花色） |

**可整段移动的判定**：从被拖起的牌到该列最底，必须是一段**全部正面**、逐张降 1 且颜色交替的连续序列。任何一张不满足 → 只能拖起它自己（若它自身是单张则允许）。

**空列的特殊约束**：把一整列（含牌堆底下的 K 段）拖到另一个空列属于无意义操作，`isLegalMove` 需返回 `false`（来源列只有这一段且目标列为空）。

### 2.5 翻牌

- 一次移动完成后，来源列新的最后一张若是**背面**，立即翻正
- 翻正不单独计一次操作，但计入 `+5` 分
- 撤销时要撤销翻正

### 2.6 自动收牌

两档，均为可关闭的设置项：

1. **自动收 A**（默认开）：任何 A 到达可操作位置时自动送进收牌区。A 永远没有留在场上的理由，误操作成本为零
2. **一键收牌**（条件触发）：当「牌堆与废牌堆为空」且「场上无背面牌」时，底部出现「收牌」按钮，点击后按点数从小到大把剩余牌逐张飞入收牌区

不做「随时自动收 2–K」——那会剥夺玩家的路线选择（例如把 5 收走导致 4 无处可放）。

### 2.7 计分与统计

采用 Windows 接龙的经典计分：

| 动作 | 分数 |
|------|------|
| 废牌堆 → 列 | +5 |
| 废牌堆 / 列 → 收牌区 | +10 |
| 翻开列底背面牌 | +5 |
| 收牌区 → 列 | −15 |
| 重洗牌堆（仅抽 3 张） | −20 |

分数**不允许低于 0**（钳制）。

统计项（独立于当前局存档）：

| 字段 | 含义 |
|------|------|
| `played` | 开局数 |
| `won` | 胜局数 |
| `best['1']` / `best['3']` | 各抽牌模式的最短用时 / 最少步数 / 最高分（抽 1 与抽 3 互不覆盖，见 §12.1 G1；旧存档的共用 `bestTime/bestMoves/bestScore` 会迁移到当前模式） |
| `streak` / `bestStreak` | 当前 / 最长连胜 |

**没有失败条件**：玩家可以随时开新局，旧局自动存盘，不设「死局判定」。

### 2.8 撤销

- **快照式撤销**，不做逆操作推导：每次提交移动前深拷贝一份紧凑状态（52 张牌 + 分数 + 步数，约 2 KB），压入 `undoStack`
- 上限 50 步；超出丢弃最旧的
- 撤销同时恢复分数、步数与 `faceUp`，**不恢复计时**
- 撤销栈只在内存中，**不存档**（跨会话撤销意义不大，且会让存档体积翻倍）
- 撤销后清空提示高亮

> 快照比逆操作可靠得多：抽 3 张、重洗、连锁翻牌、一键收牌的逆操作各不相同，逐个写逆函数是最容易埋 bug 的地方。

## 3. 交互设计（重点）

### 3.1 设计原则

1. **一次触摸只做一件事**：拖拽与点击互斥，由位移阈值判定，不允许「拖了一半又变成点击」
2. **任何操作都要有可逆结果**：拖错回弹、点错可撤销
3. **命中以「牌」为准，不以「槽位」为准**：手指落在哪张牌上就抓哪张
4. **不用 Unicode 花色字符**（`♠♥♦♣`）——与红线 10 同类风险，微信字体可能渲染成彩色 emoji 或方框，花色一律用 `Graphics` 画路径（§4.3）

### 3.2 手势表

| 手势 | 位置 | 行为 |
|------|------|------|
| 点击 | 牌堆 | 抽牌；牌堆空时重洗 |
| 点击 | 列顶正面牌 / 废牌堆顶 | **自动移动**（收牌区优先，其次合法列） |
| 点击 | 列中非顶的正面牌 | 无动作（该牌属于一段可拖的序列，只能拖） |
| 点击 | 背面牌 / 空槽 | 无动作 |
| 拖拽 | 列顶正面牌 / 可整段移动的正面牌段 / 废牌堆顶 / 收牌区顶 | 拿起并跟随手指；落到合法目标则提交，否则回弹 |
| 双指 | 任意 | **忽略**（不做缩放，避免误触） |

**点击与拖拽的分界**：位移 < `TAP_SLOP = 8` 设计像素且抬起 → 点击；超过即进入拖拽，之后**永不再回退为点击**。

> 这条边界对应教训 D 的「拖拽阈值 + 已消费标记会把轻触静默吃掉」。本作的修法是：**点击分支不依赖时长**，且拖拽如果最终落回**原位置**，视为一次点击（走自动移动）。不允许「拖了个空 → 什么都不发生」。

### 3.3 拖拽状态机

```
IDLE
 ├─ TOUCH_START(命中可拖牌) ──→ PRESSED    记录起点、抓取偏移、候选牌段
 │     ├─ TOUCH_MOVE, 位移 ≥ TAP_SLOP ──→ DRAGGING
 │     └─ TOUCH_END, 位移 < TAP_SLOP ──→ 点击回调 ──→ IDLE
 ├─ TOUCH_START(未命中) ──→ IDLE
 │
DRAGGING
 ├─ TOUCH_MOVE ──→ 更新牌段位置；计算并高亮候选落点
 ├─ TOUCH_END ──→ 命中合法目标 ? 提交(0.10s 吸附) : 回弹(0.14s)
 └─ TOUCH_CANCEL ──→ 回弹（桌面拖拽结束会派发 CANCEL，见教训 D）
        └── 若回弹终点与起点重合 → 触发一次自动移动
```

**监听挂载点**：事件必须挂在**所有子树共同父级**（`Board`），而不是单张牌节点上——拖拽时牌节点本身在被移动，挂在牌上会丢事件（教训 D）。

### 3.4 命中判定

**抓起**（`TOUCH_START`）：

1. 按渲染顺序从**上到下**遍历可交互牌（拖拽层 > 列 > 废牌堆 > 收牌区 > 牌堆），第一个包含触点的牌即为目标
2. 若命中的是列中正面牌，向上验证能否整段移动；不能则只抓它自己
3. 抓取偏移 = `触点 − 该牌左上角`，拖拽中保持偏移，避免牌「跳」到手指中心

**落点**（`TOUCH_END`）：

1. 先算被拖牌段**顶牌左上角**的位置（触点 − 抓取偏移）
2. 与 4 个收牌槽做矩形相交（外扩 12px），取交叠面积最大者
3. 否则若顶牌中心落在牌桌区（`y ≥ 列区顶 − 24`），按 **x 最近的列**作为目标
4. 目标是否接受由 `isLegalMove` 决定；不接受则回弹

> 落点用「顶牌位置」而非「手指位置」，否则手指粗、牌小时会系统性偏移半张牌。

### 3.5 点击自动移动

点击列顶正面牌 / 废牌堆顶时，按下列顺序找**第一个合法目标**：

1. 对应花色的收牌区
2. 点数与颜色可接的非空列（按列号从小到大，避免随机感）
3. 空列（仅当牌是 K，且来源列不是「只有一个空列且该列只有这张 K」的无意义情况）

找不到 → 牌原地**轻抖动**（0.12s），表示「无处可去」。

**不做双击**：单击即自动移动，双击会与拖拽起手冲突。

### 3.6 提示

点击「提示」按钮：

1. 枚举所有合法移动，按优先级排序（见下）
2. 高亮**来源牌段**（呼吸描边，线宽按正弦在 4–7 px 间脉动）与**目标槽位**（半透明填充 + 描边），持续 `HINT_SEC = 4` 秒
3. 同时在牌区底部浮出一条**中文说明**（如「提示：把 梅花3 拖到 红桃4 上」），4 秒后与高亮一起消失
4. 没有可走的牌但还能抽牌 → 高亮牌堆并提示「点左上角的牌堆抽一张」
5. 没有任何可走的牌、且重洗次数已用完 → 提示「重洗次数已用完（每局 3 次），试试撤销或新开一局」

> 说明文案必须**写清起止**（哪张牌 → 哪个落点），不能只说「按高亮位置移动」：光有高亮、玩家仍要自己猜是起点还是落点。
> 文案走独立浮层提示条（底栏上方 660×56），不再借用顶栏右侧那一行 —— 那里只剩几十像素，长句会被「?」按钮压住、根本读不出来。

**优先级**（高 → 低）：

| 序 | 移动类型 | 理由 |
|----|----------|------|
| 1 | 列 → 收牌区 | 直接推进 |
| 2 | 废牌堆 → 收牌区 | 直接推进 |
| 3 | 能翻开背面牌的移动 | 解锁信息 |
| 4 | 能腾空一列的移动 | 创造 K 的空间 |
| 5 | 任意合法列 → 列 | 常规整理 |
| 6 | 废牌堆 → 列 | 清空废牌堆 |
| 7 | 抽牌 / 重洗 | 兜底 |

提示**不限次数**，但同一局内连续点击间隔 ≥ 1.5 秒（防连点）。

### 3.7 新手引导

纸牌接龙的门槛不在操作，在**规则本身**（红黑交替、空列只放 K），第一次打开必须讲清楚，否则玩家只会乱点。

- **首次进入自动弹出「怎么玩」面板**：遮罩 + 620×860 面板，讲四件事 —— 目标、落牌规则、牌堆与重洗上限、拖拽/点按/提示怎么用；底部「开始游戏」关闭
- **只弹一次**：关闭后写 `tiny_games_solitaire_helpShown`，之后靠顶栏右侧「?」随时重看
- 面板打开期间**暂停计时**，且吞掉所有牌面触摸（防止隔着遮罩误操作）
- 顶栏左侧常驻「重洗 N/3」，把有限次数摆在明面上，而不是等用完了才让玩家发现

## 4. 界面与视觉

### 4.1 布局（设计分辨率 720 × 1280）

| 区域 | y 范围 | 说明 |
|------|--------|------|
| 顶栏 | 0 – 96 | 返回 / 标题 / 难度标签 |
| 上排（牌堆·废牌·收牌区） | 108 – 234 | 与下方 7 列共用同一套 x 中心 |
| 列区 | 256 – 1140 | 7 列牌堆 |
| 底栏 | 1150 – 1260 | 新局 / 撤销 / 提示 / 设置 |

**列栅格**：边距 `M = 15`，间距 `G = 10`，牌宽 `W = 90`，牌高 `H = 126`（1.4 比例）

```
x_i(中心) = 15 + i × 100 + 45 = 60 + 100i      i = 0..6
中心序列：60, 160, 260, 360, 460, 560, 660
```

**上排映射**：牌堆 → 列 0，废牌堆 → 列 1，收牌区 0–3 → 列 3–6（列 2 留空作视觉分隔）。

**纵向偏移**：

| 参数 | 值 | 说明 |
|------|-----|------|
| 背面牌露出 | 14 | 只需看见边缘 |
| 正面牌露出 | 30 | 需露出左上角点数的 1/2 以上 |
| 正面最小区间 | 18 | 超长列时压缩下限 |
| 废牌堆横向扇开 | 26（抽 3 张时展示 3 张） | |
| 牌堆厚度视觉 | 每张 2px，最多叠 4px | 只做厚度暗示 |

**超长列压缩**：可用高度 `= 1140 − 256 = 884`。

```
maxH = 1140 - columnTop
upCount = 正面牌数, downCount = 背面牌数
gap = clamp(18, 30, floor((maxH - H - FD × downCount) / max(1, upCount - 1)))
```

最坏情况（6 张背面 + 13 张正面）高度 `84 + 126 + 12×30 = 570`，余量充足。

### 4.3 卡牌绘制（Graphics 路径）

**每张牌 = 1 个节点**，包含：

```
CardView (Node, UITransform 90×126)
├── Body      (Graphics)  圆角矩形底 + 花色路径（角标小花色 + 中心大花色）
└── Rank      (Label)     左上角点数，anchor(0,1)，字号 28，粗体
```

一个 `Graphics` 同时画牌底和花色，避免同节点多渲染组件冲突。

| 花色 | 路径 |
|------|------|
| 方块 | 四点菱形：`(0,−r) (r,0) (0,r) (−r,0)` 闭合填充 |
| 红桃 | 两段三次贝塞尔（左右心瓣）+ 底部尖角，或 2 圆 + 三角近似 |
| 黑桃 | 红桃路径垂直翻转 + 底部小三角牌柄 |
| 梅花 | 3 个等半径圆（上、左下、右下）+ 向下小三角牌柄 |

尺寸：中心花色 `r = 23`，角标花色 `r = 7`（紧贴点数右侧）。

**绘制时机**：牌正面内容只在 `faceUp` / 花色变化时重绘，`Graphics.clear()` 后重画；布局变化只改 `position` 与 `setSiblingIndex`，**不重绘**。

> 反面牌不画花色，只画牌背纹理；52 张牌固定创建一次、整局复用，不销毁不重建。

### 4.4 动效与反馈

| 事件 | 表现 |
|------|------|
| 拿牌 | 1.04 倍缩放 + 阴影（同色深色偏移 3px） |
| 落到合法目标 | 0.10s ease-out 吸附 |

## 5. 场景与代码架构

### 5.1 文件结构

```
assets/games/game_solitaire/
├── scenes/
│   └── Solitaire.scene
└── scripts/
    ├── SolitaireConfig.ts    # 布局/配色/计分常量，无 cc 依赖
    ├── SolitaireCore.ts      # 纯规则：发牌、移动、翻牌、撤销、提示、序列化
    ├── SolitaireCard.ts      # CardView：单张牌的绘制与翻面
    └── SolitaireGame.ts      # 场景编排：输入、渲染、存档、HUD
tools/
└── verify-solitaire-core.js  # 纯逻辑回归自检（不启动 Cocos）
```

`SolitaireConfig.ts` 与 `SolitaireCore.ts` **不得 import `cc`**，否则无法在 Node 侧自检（与 `TetrisGesture.ts` / `MergeCore.ts` 同一模式）。

### 5.2 组件职责

| 文件 | 职责 | 预估行数 |
|------|------|----------|
| `SolitaireCore` | 状态持有、合法性判定、移动提交、撤销快照、提示枚举、存档序列化 | ~550 |
| `SolitaireConfig` | 常量与调参 | ~130 |
| `SolitaireCard` | 牌面绘制、翻面动画、高亮 | ~200 |
| `SolitaireGame` | 节点池、布局渲染、输入状态机、HUD、存档调度、胜负判定 | ~850 |

总计约 **1700–1900 行**，与 `砖块远征`(2032) 同级。

### 5.3 核心数据结构

```ts
type Suit = 'S' | 'H' | 'C' | 'D';

interface Card { suit: Suit; rank: number; faceUp: boolean; }

interface GameState {
    stock: Card[];          // stock[0] = 下一张
    waste: Card[];          // 末尾 = 顶
    foundations: Card[][];  // 长度 4
    tableau: Card[][];      // 长度 7
    score: number;
    moves: number;
    seed: number;
    drawCount: 1 | 3;
    recycles: number;
}

interface Move {
    type: 'tableau' | 'foundation' | 'draw' | 'recycle' | 'autocollect';
    fromPile: number;       // 0–6 列 / 7 废牌 / 8–11 收牌
    toPile: number;
    count: number;          // 移动张数
    scoreDelta: number;
    flipped: boolean;       // 是否触发了翻牌
}
```

**`isLegalMove(state, from, to, count): boolean`** 是唯一规则入口，渲染层与输入层都只能通过它判定，禁止各自写一套。

### 5.4 状态机

```
LOADING → DEALING → PLAYING ⇄ DRAGGING
                       ├→ MENU（设置/统计）
                       ├→ AUTOCOLLECT
                       └→ WON
```

- `DEALING`：发牌动画（0.8s），可点击跳过
- `PLAYING`：接受输入
- `MENU`：暂停计时，不接受牌桌输入
- `WON`：只接受「新局 / 返回」

### 5.5 节点树

```
Solitaire (Scene)
└── Canvas
    ├── Camera
    └── SafeArea                    [SafeAreaAdapter]
        ├── TopBar
        │   ├── BackButton          [BackButton]
        │   ├── Title               [Label] "纸牌接龙"
        │   └── ModeLabel           [Label] "抽 3 张"
        ├── Board                   [SolitaireGame]  ← 事件挂这里
        │   ├── BgLayer             [Graphics]
        │   ├── CardLayer           (52 张 CardView 动态创建)
        │   ├── DragLayer           (拖拽时临时挂载)
        │   └── FxLayer             [Graphics]
        └── BottomBar
            ├── NewGameBtn          [Node]
            ├── UndoBtn             [Node]
            ├── HintBtn             [Node]
            └── MenuBtn             [Node]
```

**所有按钮用 `@property({ type: Node })` + `TOUCH_END`**（红线 3），不用 `Button` 组件引用。

### 5.7 性能约束

- 52 个 `CardView` 固定创建，不随局面增删
- 拖动时**只更新被拖节点**的 `position`，不整体重排
- 整体重排（`_render()`）只在「提交移动 / 撤销 / 新局 / 窗口尺寸变化」时调用
- 计时标签每 **1 秒**更新一次，用 `update(dt)` 累加，不用 `schedule`
- `update()` 内不做遍历 52 张牌的查找
- 微信目标：60 FPS，绘制调用 ≤ 60

## 6. 存储

键前缀由 `StorageManager` 统一为 `tiny_games_solitaire_`。

| 键 | 内容 | 时机 |
|----|------|------|
| `save` | 当前局完整状态 + 种子 + 设置 | 每次提交移动后 500ms 节流；`Game.EVENT_HIDE`；切场景前 |
| `stats` | §2.7 统计项 | 胜局时、新局时 |
| `settings` | 抽牌模式、自动收 A、震动 | 变更时 |

**存档格式**（`v` 为版本号，便于日后迁移）：

```json
{
  "v": 1,
  "seed": 123456789,
  "drawCount": 3,
  "elapsed": 321,
  "moves": 47,
  "score": 210,
  "recycles": 1,
  "stock":   [{"s":"H","r":7}, ...],
  "waste":   [{"s":"C","r":13}, ...],
  "tableau": [[{"s":"S","r":9,"u":true}], ...],
  "foundations": [["S1","S2"], ...]
}
```

- 牌用紧凑编码（`"S9"` / `{s,r,u}`），压到 ~2 KB
- 解析失败 / 版本不识别 / 牌数不为 52 → **丢弃存档直接新局**，不弹错误
- **`onDestroy()` 里不做存盘**，也不访问任何 `@property(Node)`（红线 4）

**退出确认**：有进行中的对局时点「新局」，弹二次确认（「当前进度将丢失」）。从大厅返回不确认——已自动存盘。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 拖拽落点偏移，玩家觉得「放不进去」 | 致命手感问题 | 顶牌位置判定 + 收牌槽外扩 12px + 列按 x 就近；真机 4 种屏宽各验一遍 |

## 12. 本轮体验优化记录（2026-11-08）

按 [`docs/plans/2026-11-07-remaining-games-polish-plan.md`](../plans/2026-11-07-remaining-games-polish-plan.md) §2.1.8 / §3.1.8 执行。功能本来就完整，这一轮只动三处「玩家能感觉到不对」的地方 + 四处表现。

### 12.1 玩法收敛（G1–G3）

| # | 问题 | 改动 |
|---|------|------|
| G1 | `stats` 里 `bestTime / bestMoves / bestScore` 只有一份，抽 1 的成绩永远压住抽 3，抽 3 玩家永远刷不出记录 | 统计结构改为 `best: { '1': {time,moves,score}, '3': {...} }`，只在**同模式**内比较；旧存档的共用最佳值一次性迁移到玩家当前模式名下；设置面板拆成「抽 1：最快/最少」「抽 3：最快/最少」两行 |
| G2 | 最后一张牌归位后**立即**弹胜利面板，玩家来不及反应 | 新增 1.4s 胜利过渡：4 个收牌堆按 0.18s 间隔依次亮起（0→1→0 呼吸包络 + 外扩发光框），结束后才 `winPanel.active = true`；期间点撤销或开新局会 `_cancelWinFx()` 收掉过渡，面板不会串到新局 |
| G3 | 连点提示每 1.5s 就刷一条新 Toast，容易遮住牌面 | 冷却 1.5s → **3s**；冷却期内再点只把**当前**高亮续亮 1.2s，不换建议、不弹新 Toast（同一局面只有一条建议） |

### 12.2 美术（V1–V4）

| # | 改动 |
|---|------|
| V1 | 中心花色半径 23 → **27**、角标花色 7 → 8、点数 28 → **30px**；红/黑两色再拉开（`#E23A2E` / `#111827`）；牌背加**两层同心框**（越靠里越淡），缩略图下和空槽、和正面牌都能区分 |
