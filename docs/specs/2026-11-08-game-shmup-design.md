- 前置文档：[`../plans/2026-11-05-game-catalog-and-roadmap.md`](../plans/2026-11-05-game-catalog-and-roadmap.md)（§2 品类缺口的「动作射击 / 弹幕」）

---

## 1. 一句话玩法

拖动屏幕上的飞船左右躲弹，飞船自动开火；打掉 8 波敌机后迎战母舰，击沉即通关。

---

## 2. 为什么补这一款

合集里几何 / 解谜 / 消除已经饱和，**「动作射击」整类是空白**（见路线图 §2 的缺口表）。
弹幕射击是手游里手感最直接的一类：不需要关卡设计、不需要美术资源，靠**移动 + 弹幕图案**就能产生
持续紧张感，而且天然适合竖屏单手持机。

技术上同样干净：世界是**纯数字模拟**（无贴图、无随机数、无物理引擎），
所以能做到**完全确定性**——同一输入序列两次运行结果逐位相同，自检可以直接断言。

---

## 3. 规则

| 系统 | 规则 |
|------|------|
| 移动 | 拖动屏幕，飞船跟随手指（带按下时的偏移量，不会瞬移） |
| 边界 | `x ∈ [17, 703]`、`y ∈ [240, 1220]`（世界坐标，y 向下） |
| 开火 | **自动**，每 `0.12s` 一发，火力等级决定齐射弹数 |
| 火力 | 1 = 单发；2 = 双列；3 = 中间一发 + 两翼各一发（±0.16 rad 散射）；上限 3 |
| 生命 | 初始 3，上限 5；中弹掉 1 并进入 `1.6s` 无敌 |
| 无敌 | 期间不再掉血，机身照常可见，只多一圈闪烁提示环 |
| 判定 | 玩家**碰撞半径 9**（视觉半径 17），敌弹半径 7 —— 小判定、大观感 |
| 波次 | 当前波「全部生成 **且** 场上清空」→ 隔 `0.9s` 进下一波 |
| 通关 | 母舰被击沉（或母舰波清空）→ `phase = won` |
| 失败 | 生命归零 → `phase = lost` |
| 逃兵 | 敌机飞出屏幕底部**消失，不扣血也不给分**（波次照样推进） |

> 敌机不拦截、不追踪，玩家只要躲弹；「放走」也是一种策略，只是不加分。

## 4. 敌人与波次

四种敌人，全部参数化：

| 敌人 | HP | 半径 | 分数 | 下落速度 | 开火间隔 | 弹速 | 图案 |
|------|----|------|------|----------|----------|------|------|
| `grunt` 侦察机 | 2 | 20 | 10 | 130 | 1.8s | 230 | `aim` 瞄准 |
| `weaver` 编织者 | 3 | 20 | 20 | 110 | 1.5s | 210 | `spread3` 三向 |
| `tank` 重装 | 8 | 28 | 50 | 70 | 1.6s | 190 | `ring8` 环形 |
| `boss` 母舰 | 140 | 62 | 500 | 0 | 1.15s | 200 | `spiral` 螺旋 |

- `weaver` 横向做 `sin(t·2.1) × 92` 摆动；`boss` 先下降到 `y = 250` 就位，再横向摆动 ±210。
- **母舰不掉落到底**：`speed = 0`，只在固定高度往返。
- 波次共 **9 个**：侦察编队 → 蛇形突入 → 重装压境 → 两翼包夹 → 铁壁推进 → 交叉火网 → 双坦克 → 最后一波 → 母舰。
  每波的生成时刻、横坐标、并列个数都在 `SHMUP_WAVES` 里写成常量表，改关卡不用改逻辑。

### 4.1 弹幕图案

| 图案 | 实现 |
|------|------|
| `aim` | 1 发，`angleTo(敌, 玩家)` |
| `spread3` | 3 发，瞄准角 ±0.26 rad |
| `ring8` | 8 发均分一圈；每次开火整体转 `π/8`（`shotIndex` 驱动） |
| `spiral` | 3 发均分一圈 + 每次整体转 `0.42 rad`；**隔一轮再补一发 1.25 倍速瞄准弹** |

角度约定：`0 = 正下方（+y）`，顺时针为正，`angleTo` 只做 `atan2(dx, dy)`。

## 5. 道具

| 触发 | 掉落 |
|------|------|
| 母舰被击沉 | 必掉火力 |
| 每 7 个击杀 | 火力 +1（封顶 3） |
| 每 20 个击杀 | 生命 +1（封顶 5） |

道具以 `90 px/s` 下落，出屏回收；拾取判定半径 15 + 玩家碰撞半径 + 12（比视觉更宽松）。

## 6. 界面

720×1280 设计基准，全运行时 `Graphics` + `Label`，零贴图零音频。

**坐标约定**：世界坐标 `y` 向下（`0` 顶部 / `1280` 底部）；节点局部坐标
`localX = 世界X − 360`、`localY = 640 − 世界Y`。

| 区块 | 内容 | 位置 |
|------|------|------|
| 背景层 | 深空底色 + 三层星点（滚动） | 全屏 |
| 战斗层 | 飞船 / 敌机 / 双向子弹 / 道具 | 全屏（每帧 `clear()` 重画） |
| HUD 层 | 分数、火力、波次名、生命图标、波次进度条、母舰血条 | 顶部 118 设计像素内 |
| 返回键 | 圆形 `‹` | (58, 62) |
| 开始面板 | 标题、三行说明、最高分、「开始战斗」 | 全屏遮罩 |
| 结算面板 | 「母舰击沉！/ 飞船被击落」、得分、最高分、再来一局、返回大厅 | 580×560 居中 |

配色：飞船青 `#4FD1FF`、自弹黄 `#FFE27A`、敌弹红 `#FF5C7A`、
敌机按种类分红 / 紫 / 橙 / 深红，道具绿（火力）与粉（生命）。

> 生命图标与小飞船用**矢量三角**画，不用 emoji（红线 10：变体选择符在微信字体里变方框）。

### 6.1 星空的周期滚动

星点只在建场时画一次（固定 LCG 种子），之后靠**移动节点**滚动：

1. 同一批星点按 `FIELD_H` 为周期画 **4 份**（`k = -1..2`）；
2. 每帧 `_starScroll += dt × 24`，节点 `y = -(_starScroll % FIELD_H)`。

因为图案以 1280 为周期，回卷那一刻画面**逐点相同**，不会有跳变；四份拷贝保证
「可见区比 1280 高、上下各多约 140」的部分也始终有星星。

## 7. 输入

- 战斗层监听 `TOUCH_START / MOVE / END / CANCEL`，全部挂在**根节点**上（具名方法，红线 5）。
- 按下时记录 `player − 触摸点` 的偏移，移动时按偏移反推目标点 → **手指按下的位置不会让飞船瞬移**。
- `_designPoint()` 是项目通用写法：`getUILocation()` 拿到的是**视图坐标**，
  必须先减去父节点锚点偏移、`convertToWorldSpaceAR`、再 `convertToNodeSpaceAR`，不能直接喂给节点。
- 只有 `phase === 'playing'` 时才响应拖动；结算 / 开始面板打开时输入不动。

### 8.2 确定性

世界代码里**没有任何随机数**：波次是常量表，弹幕角度由 `shotIndex` 递增驱动。
因此自检可以断言「同一输入序列 → 完全相同的结果」，也能用「无敌 + 贴脸打 Boss」的
自动驾驶稳定跑出通关（150 秒内必赢）。

## 10. 验收用例

1. 开始面板 → 点「开始战斗」→ `phase = playing`、分数归零、敌机开始生成；
2. 拖动屏幕飞船跟手，且**按下点与飞船之间保持偏移**（不会瞬移）；
3. 自动开火，火力 1/2/3 的齐射分别是 1/2/3 发；拾取火力道具升级、封顶 3；
4. 中弹掉 1 命并进入无敌，无敌期间不再掉血；拾取生命封顶 5；
5. 清空一波后进入下一波，HUD 波次名与进度条同步；
6. 母舰就位、血条随扣血缩短；击沉后弹出「母舰击沉！」结算；
7. 生命归零弹出「飞船被击落」；两条路径都写出最高分；
8. 「再来一局」重置世界但**保留最高分**；「返回大厅」回 Lobby；
9. 大厅再进：开始面板显示上次最高分；
10. `node tools/verify-shmup-core.js` 全绿、`tsc --noEmit` 通过、预览 console 0 error。

## 12. 关键教训（本轮踩到的）

1. **根节点 UITransform 决定能不能收到触摸**
   复制场景得到的 `GameRoot` 是 `100×100`。Cocos 的 UI 触摸**先按 UITransform 命中测试**，
   尺寸只有 100×100 时屏幕边缘的按下根本到不了监听器 —— 表现是「拖拽完全没反应」，
   而不是报错。修法：`onLoad()` 里把根节点 UITransform 设成 `720×1280`。

2. **「无敌 = 只画一个环」等于让飞船隐身**
   第一版无敌帧直接 `return` 只画提示环，截图里飞船整个消失（只剩一个极淡的圆）。
   无敌是**不能被看见但必须被操作**的状态：机体照常画，只用光环闪烁做提示。

3. **按钮压住了标签**
   结算面板里「最高分」在 `y = 54`、按钮高 92 居中在 `y = 20`（占 `-26..66`），
   直接把最高分盖掉。面板内布局必须按**控件包围盒**算，不能按中心点算。

4. **画布是 fit-width，可见区比 1280 设计高**
   720×1280 设计被塞进 393×852 的画布时，缩放取 `393/720 = 0.5458`，
   纵向能显示约 **1561 设计像素**（上下各多约 140）。因此：
   背景必须铺满这块区域，否则会露出相机的灰色清屏色；
   星空滚动必须以 `FIELD_H` 为周期重复，否则滚到一半上半屏会变成纯黑。

5. **`MCP component_remove_component` 删不掉脚本组件**
   复制带脚本的场景后想换脚本，`component_remove_component` 会返回
   `Component cid '...' was not removed`。可行做法是
   **新建一个同名节点 → 设 layer → 挂新脚本 → 删除旧节点**（本轮即这么做的）。

### 13.1 本轮验证要点（供下次复用）

- 触摸失效时**先查根节点 UITransform 尺寸**，别怀疑坐标换算。
- 页面坐标一律用 `camera.worldToScreen(node.getWorldPosition())` 反算：
  `pageX = rect.x + sp.x`、`pageY = rect.y + rect.height − sp.y`（`sp` 的原点在画布左下角）。
- 想验证中后期内容，直接改私有字段跳波（`w.waveIndex = 8; w.waveTime = 0; w.entryIndex = 0`），
  不用真打 90 秒。
