# 守卫塔楼（`tower_defense`）玩法设计

- 日期：2026-11-06
- 状态：已实现（纯逻辑自检 21/21、场景可玩）
- 对应路线图：[`2026-11-05-game-catalog-and-roadmap.md`](../plans/2026-11-05-game-catalog-and-roadmap.md) §5.5（P1-3）
- 场景：`assets/games/game_tower_defense/scenes/TowerDefense.scene`

---

## 1. 一句话玩法

在固定塔位上建塔，沿路径拦截敌人；撑过 10 波（含 1 只 Boss），一只都不许漏进终点。

## 2. 目标体验

- 合集第一款**塔防**：一眼看懂「路 + 塔位 + 波次」，不需要教学。
- 单局 6–10 分钟，失败可以立刻重来；波次之间留有从容的决策时间。
- 决策乐趣来自「塔位覆盖了几段路」「这波该补输出还是补减速」「攒钱升级还是多铺一座」。
- 三张地图的路线形状不同（S 形、U 形、折返），同一套塔在不同地图上的价值不一样。

## 3. 规则

### 3.1 地图与路径

- 9 列 × 12 行网格，ASCII 定义：`S` 起点、`#` 路径、`E` 终点、`o` 固定塔位、`.` 空地。
- 路径由核心从 `S` 到 `E` 做 BFS 自动推导，因此地图只需要连通即可；`validateMap()` 会检查行宽、非法字符、塔位压路、路径穿过塔位。
- 敌人从 `S` 格心出发，沿折线走到 `E` 格心；到达终点即漏怪，按敌人类型扣生命。
- 塔位固定，不做自由放置；塔位不能建在路径上。

三张地图：

| # | 名称 | 形状 | 初始金币 | 生命 | 血量倍率 |
|---|------|------|----------|------|----------|
| 1 | S 形走廊 | 三段横向来回 | 200 | 10 | 1.15 |
| 2 | U 形回廊 | 外圈绕行 + 内部回折 | 190 | 10 | 1.30 |
| 3 | 折返栈道 | 中轴上下 + 左右折返 | 180 | 10 | 1.45 |

### 3.2 塔

四种塔，每种 3 级；造价与升级价见下表（金币），出售返还**累计投入的 50%（向下取整）**。

| 塔 | 定位 | 索敌 | 1 级造价 | 特点 |
|----|------|------|----------|------|
| 机枪塔 | 单体速射 | 最前 | 60 | 射速快、性价比高，主力输出 |
| 迫击炮 | 范围溅射 | 最近 | 110 | 溅射半径 1.15 格，专治成群 |
| 冰霜塔 | 减速 | 最前 | 90 | 减速 45% 持续 1.5s，溅射 0.9 格 |
| 狙击塔 | 点杀 | 最低血 | 140 | 射程 5.5–6.5 格，优先补刀残血 |

升级数值（伤害 / 射程格 / 间隔秒）：

| 塔 | Lv1 | Lv2 | Lv3 |
|----|-----|-----|-----|
| 机枪塔 | 12 / 2.8 / 0.35（+55） | 20 / 3.0 / 0.33（+80） | 32 / 3.2 / 0.30 |
| 迫击炮 | 24 / 3.2 / 1.20（+100） | 38 / 3.4 / 1.10（+140） | 60 / 3.6 / 1.00 |
| 冰霜塔 | 5 / 2.6 / 0.80（+80） | 8 / 2.8 / 0.70（+110） | 12 / 3.0 / 0.60 |
| 狙击塔 | 60 / 5.5 / 1.60（+130） | 95 / 6.0 / 1.50（+180） | 150 / 6.5 / 1.40 |

括号内为升到该等级的花费。

### 3.3 敌人

| 敌人 | 基础血 | 速度（格/秒） | 击杀金币 | 漏怪扣血 |
|------|--------|---------------|----------|----------|
| 小兵 | 55 | 1.6 | 8 | 1 |
| 疾行者 | 32 | 2.9 | 7 | 1 |
| 装甲兵 | 180 | 1.0 | 18 | 2 |
| 攻城车（Boss） | 2200 | 0.9 | 150 | 5 |

实际血量 = `round(基础血 × 地图倍率 × (1 + 0.16 × (波次 - 1)))`。

### 3.4 波次

10 波，配置在 `TD_WAVES`：每波由若干「敌人组」组成，组内间隔与首只延迟固定；清空本波额外奖励金币（25→120，Boss 波 120）。

```
1  小兵×6
2  小兵×8
3  小兵×6 + 疾行者×5
4  小兵×8 + 疾行者×8
5  小兵×8 + 装甲兵×2
6  疾行者×12 + 装甲兵×2
7  小兵×12 + 装甲兵×3
8  疾行者×10 + 装甲兵×4
9  小兵×14 + 疾行者×6 + 装甲兵×4
10 攻城车×1 + 疾行者×8 + 装甲兵×3
```

### 3.5 经济与胜负

- 建造 / 升级立即扣金币；击杀与清波给金币；出售返还 50%。
- 敌人抵达终点按类型扣生命；生命 ≤ 0 立即判负。
- 清空第 10 波判胜。
- 存档：每张地图的最远波次、上次游玩地图、累计击杀。

```
┌──────────────────────────────┐
│ ‹        守卫塔楼            │  标题 y=64，副标题 y=104
│  下一波 3/10   金币 240  生命 10 │  HUD y=156
│                              │
│   ┌──────────────────────┐   │
│   │   9×12 棋盘（594×792）│   │  棋盘中心 (360, 626)
│   │  路径 / 塔位 / 塔 / 敌人 │   │
│   └──────────────────────┘   │
│        准备阶段 · …           │  状态行 y=1046
│  [换图]   [开始第 N 波]  [1x] │  底栏 y=1120
│   点空塔位建塔 · 点塔升级/出售   │  提示 y=1232

```

- 点空塔位 → 底部弹出建造面板（2×2 四张塔卡 + 关闭），面板打开时暂停推进。
- 点已有塔 → 弹出塔详情（等级、伤害 / 射程 / 间隔、升级价、出售返还），同样暂停。
- 结算浮层：胜负、地图、到达波次、击杀数、剩余生命 +「再玩一次 / 换一张图 / 返回大厅」。

## 5. 交互流程

```
进入 → 读档 → 加载上次地图 → 准备阶段（可建塔 / 升级 / 出售 / 换图 / 2 倍速）
     → 点「开始第 N 波」→ 敌人沿路径推进、塔自动开火
     → 本波清空 → 奖励金币 → 回到准备阶段（循环 10 次）
     → 第 10 波清空 → 胜利结算；生命归零 → 失败结算
     → 再玩一次（同图重开）/ 换一张图 / 返回大厅
```

- 暂停语义：任何面板 / 结算浮层打开时 `paused = true`，`update` 不推进逻辑，但继续重绘。
- 倍速只影响固定步长的推进数量（1x 每帧最多 3 步、2x 最多 6 步），不改单步 `dt`。

## 6. 可玩性与难度

- 自检里的自动玩家策略（按路径覆盖度排序塔位，先铺机枪、再补冰霜 / 迫击炮 / 狙击，有余钱就升级）结果：

| 地图 | 结果 | 剩余生命 |
|------|------|----------|
| S 形走廊 | 通关 | 10 |
| U 形回廊 | 通关 | 10 |
| 折返栈道 | 通关 | 2 |

- 含义：**按合理策略打都能通关，但第三张图容错明显更低**；实际玩家操作比自动玩家粗糙，前两张图也不会变成无脑局。
- 血量倍率从 1.0 / 1.15 / 1.3 上调到 1.15 / 1.3 / 1.45 就是为了避免「前两张图一滴血不掉」的假难度。

## 7. v1 不做

- 英雄单位、主动技能、塔的攻击特化分支
- 无尽模式、每日挑战、排行榜 / 分享
- 自由放置塔位、地形装饰、动画骨骼
- 音效与音乐（项目当前无音频基建）

## 8. 技术方案

### 8.1 纯逻辑核心 `TDConfig.ts` / `TDCore.ts`（无 `cc` 依赖）

- `TDConfig.ts`：塔 / 敌人 / 地图 / 波次 / 存档的全部数值与解析（`parseTDSave` 坏档回落）。
- `TDCore.ts`：
  - `findPathCells(grid)`：BFS 求 `S→E` 最短路径；`validateMap(map)` 返回问题列表。
  - 构造时把路径格子转成折线点，并预计算累计距离 `pathLength` 与每段起点，供 `positionAtDistance()` O(段数) 定位。
  - `build / upgrade / sell`：校验金币、占用、满级、已结束；出售按累计投入 50% 返还。
  - `step(dt)`：固定步长入口（内部 `dt` 上限 0.1）——特效衰减 → 出场 → 移动（含减速）→ 塔开火 → 弹丸飞行 / 命中 / 溅射 → 清理 → 判波次完成。
  - 索敌三种模式：`first` 取路径进度 `dist` 最大、`closest` 取欧氏距离最小、`lowest` 取血量最低；只在射程内选择。
  - 事件队列（`build/upgrade/sell/shoot/kill/leak/boss/waveClear/won/lost`）由 `drainEvents()` 取走，逻辑层不依赖渲染。
- 为什么不用 A*：路径是预先用 ASCII 描述好的单条折线，BFS 只用于「把地图校验成一条合法路径」，运行期只做插值。

### 8.2 运行时 `TDGame.ts`

- 一个挂在 `GameRoot` 上的组件，所有 UI 在 `onLoad` 里用 `GameUIKit` 创建，不改场景。
- `update(dt)`：累加器 + 固定步长（`FIXED_DT = 1/60`）推进 `TDCore`，每帧一次棋盘重绘。
- 渲染：**单 `Graphics` 整盘重绘**（底板 → 路面 → 塔位 → 射程圈 → 塔 → 敌人 / 血条 → 弹丸 → 爆炸），和「午夜幸存者」同一套写法，不为每个单位建节点。
- 输入：棋盘 `TOUCH_END` → `convertToNodeSpaceAR` 换算格子 → 找 0.62 格内最近的塔位。
- 按钮回调用 `createButton(..., onTap)` 的闭包；节点事件 handler 全部具名，`onDestroy` 只清 JS 引用。
- 存读档走 `StorageManager`，键 `tiny_games_tower_defense_save`。

### 8.3 自检 `tools/verify-td-core.js`（21 项，全绿）

覆盖：3 张地图合法性、路径端点与长度、塔位不压路、建造扣金币 / 金币不足 / 占用与非法塔位拒绝、升级到 Lv3 与满级拒绝、出售返还 50%、`startWave` 仅在准备阶段、出场延迟与间隔、敌人移动连续且在盘内、漏怪扣血（装甲兵 -2、生命归零判负）、10 波全清判胜、三种索敌优先级、迫击炮溅射命中 ≥2、冰霜减速生效、弹丸击杀奖励、波次血量成长与地图难度序、10 波配置含 Boss、存档往返与坏档回落、1,000 局随机操作不变量（金币非负、生命 0–10、坐标有限、敌人数有界）、三张地图自动玩家均可通关。

```bash
node tools/verify-td-core.js
```
