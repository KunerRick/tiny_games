## 0. 评审摘要（先看这一页）

### 0.1 一句话

**单指移动、武器自动攻击、每升一级三选一，在 2400×2400 的暗色竞技场里撑过 8 分钟并击败 7:30 出现的 Boss。**

### 0.2 这份方案赌的三件事

| 赌注 | 为什么值得赌 | 怎么证伪 |
|------|--------------|----------|
| **移动本身就是决策** | 自动攻击把操作负担降到单手，但捡经验、绕怪群、躲自爆/弹幕让「往哪走」始终有代价 | 站桩测试：不动应在 6–8 秒内死亡；会走的人应能活到 4 分钟 |
| **三选一能撑起构筑感** | 4 把武器 + 4 个被动，3 武器槽 + 2 被动槽 → 24 种组合，且升级顺序本身是选择 | 5 局试玩后，玩家应能说出「下局想试什么」 |
| **单 Graphics 批量绘制能扛住 300 敌人** | 不给每个敌人建节点，逻辑与渲染分离，是微信小游戏性能的唯一可行解 | M1 纯逻辑压测 + M2 预览端 300 敌人 60 FPS 双重门槛 |

### 0.3 与路线图原案的差异（已确认，2026-11-02）

| 项 | 路线图原案 | 本方案 | 理由 |
|----|-----------|--------|------|
| 内容量 | 3 武器（飞刀/环绕/落雷）+ 3 被动 | **4 武器（+回旋镖）+ 4 被动（+体魄）** | 3+3 且槽位全开时，每局最终都会集齐 6 条线，构筑必然收敛；4+4 配 3+2 槽才有取舍 |
| 槽位 | 未写死 | **3 武器槽 + 2 被动槽** | 用「槽位稀缺」制造选择，比堆内容便宜 |
| 升级曲线 | 每 30 秒升级 | **按经验值升级，目标首次 10–15 秒，平均 20–30 秒一次** | 固定 30 秒会把「吃经验」变成无意义动作 |
| 单局时长 | 8 分钟 | **8 分钟逻辑时长 + 1x/2x/4x 倍速轮换** | 不压缩内容；想快的人自己加速，想稳的人 1x 玩 |
| 局内存档 | 未列入 MVP | **做本地存档（清空即失效）** | 8 分钟一局，切后台/退大厅后可继续；不接云端 |
| 特效 | 低特效开关（路线图风险对策） | **设置里提供特效开关，安卓默认关** | 低端机首帧更稳，高端机可开满 |
| 里程碑 | M1–M7 | 同 M1–M7，增加 **Gate B（M2 渲染门槛）** | 纯逻辑达标不代表画面达标，渲染必须单独设闸 |

### 0.4 成本结论

**约 26–29 人日**（含 3 人日缓冲）。相比路线图初始草案的 22–26 人日，增量来自：+1 武器/+1 被动（约 1.5 人日）、倍速系统（约 1 人日）、本地局内存档（约 2 人日）、性能与验收（约 1 人日）。

其中 **M1（纯逻辑 + 压测）和 M2（渲染原型）是 Go / No-Go 决策点**，任一门不通过就降规模，不进入内容期。

### 0.5 已拍板的 5 件事（2026-11-02）

| # | 决定 |
|---|------|
| 1 | 名字用**午夜幸存者** |
| 2 | 单局 **8 分钟**，HUD 提供 **1x / 2x / 4x** 倍速轮换 |

## 1. 概述

Tiny Games 的第十款游戏，也是合集里第一款「**同屏几百个活动对象**」的品类。

**定位**：现有 9 款游戏里，操作型（2048、贪吃蛇、方块坠落、合合、数值冲刺）要求持续盯屏；内容型（小小先锋、砖块远征）靠关卡续命；规则型（纸牌接龙）靠思考。《午夜幸存者》补的是第四种：**低操作门槛 + 高密度反馈 + 短周期构筑成长**，一局 8 分钟，随时暂停，失败没有惩罚。

**核心目标**

- **单手可玩**：左拇指导航，右手不需要；所有信息在一屏内
- **60 秒内建立「我在变强」**：第一次升级三选一必须在 15 秒左右出现，第一次武器质变在 90 秒内
- **满屏但不糊**：敌人用形状 + 颜色区分，200 个敌人时仍能一眼认出炸弹兵和 Boss
- **零美术**：全部 `Graphics` + `Label`，运行时生成，不新增任何图片
- **微信中低端安卓可玩**：300 敌人上限，特效关闭档 ≥ 50 FPS
- **节奏可调**：1x / 2x / 4x 倍速轮换，不改变单局内容
- **中断可续**：本地局内存档，清空 `localStorage` 即失效
- **失败可复盘**：结算面板写清死因、存活时间、击杀、等级，让玩家知道下一局改什么

**非目标（v1 不做）**

- 双摇杆、闪避、主动技能、冲刺
- 武器进化/合成树、局外养成、角色解锁
- 精英词缀、宝箱、事件房、商店、金币、皮肤
- 无尽模式、排行榜、每日挑战
- 音效与背景音乐（只做震动，可关）
- 云端存档、跨设备同步、存档版本迁移（旧版本存档直接丢弃）

## 2. 可玩性设计（评审重点）

> 这一节回答「为什么不是挂机」「8 分钟会不会腻」「玩第二局的理由是什么」。数值是基线，§3.11 给出全部调参旋钮。

### 2.1 核心循环

**30 秒微循环**

```
移动躲怪 → 武器自动清场 → 捡经验宝石 → 升级三选一 → 立刻感到变强 → 继续往人堆里走
```

**8 分钟宏循环**

```
1 分钟学会规则 → 2–4 分钟凑出构筑骨架 → 4–6 分钟承受第一次压力峰值
→ 6–7.5 分钟冲刺成型 → 7.5 分钟 Boss 检验 → 结算 → 换一种构筑再来
```

### 2.2 为什么移动不是「无脑绕圈」

自动攻击消除了瞄准，但保留了四类代价不同的移动决策：

| 决策 | 收益 | 代价 |
|------|------|------|
| 往宝石密集区走 | 升级更快 | 进入怪群，吃接触伤害 |
| 贴着怪群边缘绕 | 武器命中数最大化（环绕/落雷吃密度） | 自爆兵和远程弹的容错变低 |
| 优先清远程兵 | 移除持续弹幕威胁 | 放弃一侧的经验，可能被包夹 |
| Boss 战绕柱走位 | 躲弹幕、拉小怪 | 输出时间减少，Boss 战拖长 |

**关键设计**：武器全部是「自动索敌或环绕」，玩家的操作不会提高 DPS，只会提高**存活率**和**拾取效率**。这让「会走」直接等于「更强」，而不是「点得更快」。

### 2.3 三选一不是「随便点一个」

每级从候选池抽 3 张，候选来源与权重：

| 候选类型 | 出现条件 | 权重 |
|----------|----------|------|
| 已拥有武器升级 | 该武器等级 < 5 | 1.2 |
| 新武器 | 武器槽未满（< 3）且还有未拥有武器 | 1.0 |
| 已拥有被动升级 | 该被动等级 < 5 | 1.0 |
| 新被动 | 被动槽未满（< 2）且还有未拥有被动 | 0.9 |
| 回复 30 生命 | 始终可用 | HP < 70% 时 0.5，否则 0.15 |
| 淬炼（全局伤害 +8%） | 始终可用 | 0.4 |

规则：

- 同一张卡不重复；最多 2 张「新开一条线」，避免一次给太多信息
- **第一次升级**保证至少 1 张武器相关 + 1 张被动相关，用来教学
- 槽位满后，对应「新武器/新被动」退出池子，权重转向已有线升级
- 选择期间游戏逻辑完全暂停（不是减速），防止「一边选一边被咬死」

**构筑组合数**：4 选 3 武器 × 4 选 2 被动 = **24 种**。加上升级顺序，实际差异比数字更大：

| 构筑 | 打法 | 强项 | 弱项 |
|------|------|------|------|
| 飞刀 + 星环 + 落雷 | 贴身绞肉 | 清群最快 | 缺单体，Boss 慢 |
| 飞刀 + 回旋镖 + 落雷 | 中距离火力网 | 兼顾清群与单体 | 走位要求高，怕贴脸 |
| 星环 + 回旋镖 + 落雷 | 风筝流 | 边跑边打 | 前期清场慢，升级晚 |
| 飞刀 + 星环 + 回旋镖 | 纯物理 | 无弹道延迟 | 缺 AoE，怕人海 |

### 2.4 8 分钟节奏表（「每 30 秒必须有一件事发生」）

| 时间 | 发生什么 | 玩家感受 | 设计目的 |
|------|----------|----------|----------|
| 0:00–0:15 | 直冲兵缓慢靠近，飞刀自动清场 | 「原来不用点攻击」 | 教学，建立安全感 |
| 0:10–0:20 | **第一次升级三选一** | 「我可以选武器」 | 15 秒内给出成长承诺 |
| 0:45 | **兽潮 1**：一小圈敌人从一侧压来 | 「有点密了」 | 第一次密度冲击 |
| 1:00–2:00 | 绕行兵加入，掉落变多 | 「跑起来才吃得爽」 | 让移动与收益挂钩 |
| 2:00 | **精英 1** + 远程兵加入 | 「那个大个必须处理」 | 引入优先目标 |
| 2:00–4:00 | 武器槽逐渐填满，被动开始成型 | 「我的 build 有点样子了」 | 构筑骨架 |
| 4:00 | **精英 2 + 自爆兵** | 「不能硬撞」 | 第一次真正的死亡风险 |
| 4:00–6:00 | 同屏 150–220 敌人，屏幕开始被填满 | 「有点爽，也有点慌」 | 压力峰值 |
| 6:00 | **精英 3**，掉大量经验 | 「再升两级就成型」 | 冲刺动机 |
| 6:00–7:30 | 最大密度，等级从 14–18 升到 18–22 | 「Boss 快来了」 | 成型后的收割期 |
| 7:30 | **Boss 登场**（2 秒预警） | 「来了」 | 检验构筑与走位 |
| 7:30–8:30 | Boss 弹幕 + 召唤小怪 | 「别贪输出」 | 最终考试 |
| 击杀 Boss | 胜利结算 + 本局构筑回顾 | 「下局试试别的」 | 重开动机 |

> 8 分钟是「目标击杀时间」，不是硬性倒计时。Boss 未死则战斗继续，直到胜利或死亡。
> 倍速只改变真实耗时，不改变上表的逻辑节奏：1x 按 8 分钟体验，4x 约 2 分钟走完同一段内容；难度不因倍速下降。

### 2.5 失败设计：死得明白，重开得快

- **不做一击必杀**：Boss 接触 25 伤害，满血可扛 4 下；小怪接触 6–8，玩家无敌帧 0.5 秒
- **自爆有 0.5 秒预警**：先出现红圈收缩，再爆炸；给反应窗口
- **远程弹可见**：亮色小圆，速度 240–260，能被走位躲开
- **结算写死因**：存活时间、击杀数、等级、造成伤害前三的来源、死亡前 5 秒的伤害构成
- **不惩罚重开**：无体力、无金币、无冷却；结算面板直接「再来一局」
- **个人纪录**：最佳存活时间、最高击杀、最高等级，三项都会在结算页提示是否破纪录

### 2.6 可玩性红线（试玩时逐条打勾）

1. **首次升级 ≤ 20 秒**；否则玩家在形成「成长预期」前就流失
2. **站桩不动 6–8 秒内死亡**；否则移动没有压力，游戏退化成看动画
3. **每次三选一至少 2 张是玩家想要的**；如果经常 3 张都不想选，说明权重或内容有问题
4. **200 敌人同屏时，自爆兵与 Boss 仍可一眼识别**；否则难度来自「看不清」而不是「打不过」
5. **一局结束后玩家能说出「下一局我要试什么」**；说不出就是构筑感不足
6. **4 分钟前不出现「无解围杀」**；被围死必须能归因于此前的选择，而不是随机刷脸

### 2.7 试玩验证方法（M4 / M6 各做一轮）

每轮 5 局，至少换 3 个种子，记录：

| 指标 | 目标区间 | 调什么 |
|------|----------|--------|
| 首次升级时间 | 10–20 秒 | `XP_CURVE_BASE`、首批敌人密度 |
| 2 分钟等级 | 5–7 | 经验掉落量、`XP_CURVE_STEP` |
| 4 分钟同屏敌人数 | 120–180 | `SPAWN_RATE_BASE/SLOPE` |
| 6 分钟等级 | 14–18 | 经验曲线、精英经验 |
| 玩家首次死亡时间（新手） | 3:30–6:00 | 敌人伤害倍率、自爆预警 |
| Boss 战时长（成型 build） | 15–35 秒 | Boss HP、玩家满级 DPS |
| 一局总击杀 | 900–1600 | 刷怪率、武器清场效率 |

> 这些区间是**假设**，不是结论。M4 结束必须用真实试玩数据校准一次，再进入 M6 手感打磨。

## 3. 核心规则与数值

### 3.1 坐标系与地图

| 项 | 值 |
|----|-----|
| 设计分辨率 | 720 × 1280（沿用项目设置，`fitHeight + fitWidth`） |
| 竞技场 | 2400 × 2400，坐标范围 `[-1200, 1200]²`，玩家出生在 `(0, 0)` |
| 单位 | 设计像素、秒；所有逻辑在 `SurvivorCore` 内用同一套坐标 |
| 相机 | 跟随玩家，位置 = `-player`，并夹紧到竞技场边界；贴边时玩家偏离屏幕中心 |
| 背景 | 世界坐标网格（200 设计像素一格）+ 竞技场边框；静态绘制一次，随相机移动 |
| 障碍物 | v1 无。不做碰撞地形，避免寻路与卡位问题 |

### 3.2 单局状态机

```
INTRO（新手引导，暂停）
  └─ 点击继续 → RUNNING
RUNNING ──升级──→ LEVEL_UP（逻辑暂停，三选一）
        ←──选择───┘
RUNNING ──HP≤0──→ DEFEAT
RUNNING ──Boss 死亡──→ VICTORY
RUNNING ──点暂停 / 切后台──→ PAUSED → RUNNING
```

- `LEVEL_UP`、`PAUSED` 时**不推进任何逻辑**（不是 `timeScale=0` 的补间暂停，而是核心 `step()` 不被调用）
- 结算后核心停止推进，只保留渲染最后一帧
- 重开 = 丢弃核心实例、用新种子重建，不复用旧状态

### 3.3 玩家

| 属性 | 基线值 | 说明 |
|------|--------|------|
| 最大生命 | 100 | 体魄每级 +20 |
| 移动速度 | 220 px/s | 移速被动每级 +6%，最高 +30% |
| 碰撞半径 | 14 | 受击判定用圆 |
| 无敌帧 | 0.5 s | 受击后闪烁，期间不受伤 |
| 拾取半径 | 60 | 拾取被动每级 +30%，最高 150 |
| 初始武器 | 飞刀 Lv1 | 保证开局能清怪 |
| 移动方式 | 摇杆方向 × 速度，无惯性 | 响应优先；松手立即停 |

**受击规则**：敌人与玩家圆重叠 → 若玩家不在无敌帧 → 扣血、进入 0.5 s 无敌、敌人被击退 40 px 且自身进入 0.8 s 接触冷却（防止同一只怪连续判定）。玩家不因受击打断移动。

### 3.4 武器（4 把，各 5 级）

所有武器自动释放，不需要按键。攻击间隔受「攻速」被动影响（间隔 ÷ `(1 + 0.1 × 攻速等级)`）。

#### 3.4.1 飞刀（单体、直线、可穿透）

| 等级 | 数量 | 伤害 | 间隔 | 速度 | 穿透 | 索敌 |
|------|------|------|------|------|------|------|
| 1 | 1 | 10 | 1.00 s | 850 | 0 | 最近的敌人（≤ 460），否则朝移动方向 |
| 2 | 2 | 10 | 1.00 s | 850 | 0 | 同上，两把呈 ±6° |
| 3 | 2 | 14 | 1.00 s | 850 | 0 | 同上 |
| 4 | 2 | 14 | 1.00 s | 850 | 1 | 同上 |
| 5 | 3 | 14 | 0.85 s | 900 | 1 | 同上，三把呈 -8°/0°/+8° |

- 子弹生命周期 0.9 s 或飞出竞技场即回收
- 穿透计数：命中一个敌人减 1，减到 0 回收
- **DPS 参考**：Lv1 单目标 10；Lv5 单目标约 49（3 × 14 ÷ 0.85）

#### 3.4.2 星环（环绕、近身、吃密度）

| 等级 | 球数 | 伤害 | 半径 | 角速度 | 单敌命中冷却 |
|------|------|------|------|--------|--------------|
| 1 | 2 | 12 | 88 | 1.8 rad/s | 0.45 s |
| 2 | 3 | 12 | 88 | 1.8 rad/s | 0.45 s |
| 3 | 3 | 16 | 88 | 1.8 rad/s | 0.45 s |
| 4 | 3 | 16 | 108 | 2.2 rad/s | 0.45 s |
| 5 | 4 | 20 | 108 | 2.2 rad/s | 0.45 s |

- 球体均匀分布，整体绕玩家旋转；球半径 10，伤害判定半径 14
- 同一敌人可被**不同球**分别命中，但同一颗球对同一敌人有 0.45 s 冷却
- 球体不阻挡敌人、不被销毁
- **定位**：单目标 DPS 低（Lv5 约 28），但贴脸时能同时命中 5–10 只，是清群核心

#### 3.4.3 落雷（随机点、范围、高频）

| 等级 | 目标数 | 伤害 | 间隔 | 索敌半径 | AoE 半径 |
|------|--------|------|------|----------|----------|
| 1 | 1 | 24 | 2.2 s | 300 | 52 |
| 2 | 1 | 24 | 1.8 s | 300 | 52 |
| 3 | 1 | 34 | 1.8 s | 320 | 52 |
| 4 | 2 | 34 | 1.8 s | 320 | 52 |
| 5 | 2 | 34 | 1.4 s | 340 | 84 |

- 每道雷独立选目标：在索敌半径内**按权重随机**选敌人（越近权重越高），不总是打同一个
- 视觉：0.08 s 的竖直折线 + AoE 圆圈闪现；命中判定瞬时完成
- **定位**：自动清后排、处理远程兵；Lv5 是主要 AoE 来源

|------|------|---------|------|----------|------|------|

### 3.5 被动（4 个，各 5 级）

| 被动 | 每级效果 | 5 级总效果 | 设计意图 |
|------|----------|------------|----------|
| 攻速 | 攻击间隔 ÷ 1.10 | 约 1.61 倍攻击频率 | 直接放大所有武器，泛用 |

### 3.6 升级与三选一

#### 3.6.1 经验曲线

- 每级所需经验：`need(level) = 6 + 3 × (level - 1)`（初稿为 ×4，M1 实测后下调，见 §8.5.1）
- 从 1 级升到 20 级累计需要 **627 经验**
- 目标：8 分钟内达到 20–24 级；多出来的等级用「回复 30 / 淬炼」填充
- 首次升级只需 6 经验 ≈ 击杀 5–6 只小怪，目标 10–15 秒

#### 3.6.2 三选一流程

1. 经验达到阈值 → 核心进入 `LEVEL_UP`，生成 3 张 `UpgradeOffer` 并保存
2. 游戏层弹出面板，显示卡名、当前等级 → 下一级、效果描述、形状图标
3. 玩家点击（`TOUCH_END` + `@property({ type: Node })`）→ `core.chooseUpgrade(index)`
4. 核心应用效果、清空 offer、回到 `RUNNING`
5. 若一次获得多级经验，逐级弹面板，不合并（保留每次选择）

**卡面必须写「变化量」而不是「描述」**，例如「飞刀：伤害 10 → 14」，让玩家不需要记数值。

### 3.7 敌人

#### 3.7.1 基础敌人

| 敌人 | 形状/颜色 | 基础 HP | 速度 | 半径 | 接触伤害 | 经验 | 行为 |
|------|-----------|---------|------|------|----------|------|------|
| 直冲兵 | 红色三角，尖端朝玩家 | 14 | 62 | 13 | 8 | 1 | 直线追玩家，无转向延迟 |
| 绕行兵 | 黄色菱形 | 10 | 74 | 12 | 6 | 1 | 朝玩家移动，同时横向正弦摆动（振幅 40，频率 2 Hz） |
| 远程兵 | 紫色方块 + 中心点 | 16 | 48 | 13 | 8 | 2 | 维持 190–240 距离；每 2.6 s 射一发（速度 260，伤害 10）；太近时后退 |
| 自爆兵 | 橙色圆 + 外圈 | 12 | 105 | 14 | — | 1 | 追玩家；距离 < 26 时停下，0.5 s 红圈预警后爆炸（半径 64，伤害 18）；死亡也会爆炸 |

#### 3.7.2 精英

- 时间点：**2:00 / 4:00 / 6:00** 各一只，类型从当前已解锁敌人中随机
- 属性：HP × 8、体型 × 1.35、速度 × 0.9、接触伤害 × 1.5、经验 10
- 死亡时额外掉落 3 颗经验宝石（每颗 3 经验），并震动一次
- 精英不单独做血条，用更大的体型 + 描边 + 头顶小血条（`Graphics`）区分

#### 3.7.3 敌人成长与刷新

| 项 | 公式/值 |
|----|---------|
| HP 倍率 | `1 + t / 240`（8 分钟时约 3.0 倍） |
| 伤害倍率 | `1 + t / 480`（8 分钟时约 1.94 倍） |
| 速度倍率 | `1 + min(0.25, t / 4000)` |
| 刷新率 | `2 + 0.032 × t` 只/秒，上限 18 只/秒（60 s 约 3.9/s，300 s 约 11.6/s） |
| 刷新位置 | 距玩家 620–780 的圆环上随机角度；夹紧到竞技场后若距玩家 < 480 则重抽，最多 4 次 |
| 同屏上限 | **300**；达到上限时跳过本次刷新（不替换、不排队） |
| 组成权重 | 0–60 s：直冲 100%；60–120 s：直冲 70 / 绕行 30；120–240 s：50/25/25（含远程）；240–360 s：40/25/20/15（含自爆）；360 s+：35/20/20/25 |
| 兽潮 | 45 s 起每 45 s 一次，在玩家一侧的 120° 扇区生成 `8 + floor(t/60)×3` 只敌人；HUD 提前 2 s 提示「兽潮来袭」 |

> 刷新率是逐步逼近上限的。上限 300 是**性能护栏**，不是设计目标：正常情况下 6 分钟前不应长期顶满。

| 碰撞 | 处理 |
|------|------|
| 玩家 ↔ 敌人 | 圆判定；玩家无敌帧 0.5 s；敌人接触冷却 0.8 s |
| 玩家 ↔ 敌弹 | 圆判定；命中后弹丸回收；玩家无敌帧生效 |

### 3.12 倍速轮换（1x / 2x / 4x）

HUD 右上角放一个**倍速按钮**，点击循环 `1x → 2x → 4x → 1x`，按钮文字始终显示当前倍速。

| 项 | 规则 |
|----|------|
| 默认 | 每局开始为 **1x**；同一局内切换后保持，直到本局结束 |
| 可用时机 | 仅 `RUNNING`；`LEVEL_UP` / `PAUSED` / 结算时按钮隐藏或禁用 |
| 影响范围 | **只影响逻辑推进速度**（移动、攻击、刷怪、计时、掉血），不影响任何数值与掉落 |
| 计时显示 | HUD 显示**逻辑时间**：4x 下 8:00 用 2 分钟真实时间走完；最佳纪录也按逻辑时间 |
| 输入 | 摇杆仍按渲染帧采样（60 Hz），方向在多个逻辑子步之间保持不变 |
| 视觉效果 | 闪白、飘字、落雷/爆炸的视觉停留、震屏使用**真实时间**，不随倍速缩短；伤害判定仍在逻辑层瞬时完成 |
| 关卡事件 | 升级面板、精英、兽潮、Boss 按逻辑时间触发；升级面板出现时立即停止剩余子步，选择后继续 |
| 4x 性能 | 单帧最多追 `3 × 倍速` 步（1x=3、2x=6、4x=12）；追不上则丢弃累加器，不排队 |
| 低端机保护 | 4x/2x 下若连续 1.5 秒平均帧时间 > 22 ms，自动降一档并提示一次「已自动降速」；只自动降、不自动升，玩家仍可手动切回更高倍速（之后重新评估） |

**设计意图**：倍速是「省略等待」而不是「降低难度」。4x 下玩家反应窗口同比缩短，属于自愿挑战；逻辑时间纪录不受倍速影响，因此不存在刷纪录的不公平。

**实现要点**

- 倍速只改游戏组件的累加器输入，不进入 `SurvivorCore`：核心永远只收到固定 `dt = 1/60`
- 一次 `update()` 内若核心进入 `levelup` / `victory` / `defeat`，立即 `break` 并清空累加器，避免选择后瞬间连升多级或结算后继续扣血
- 视觉特效不存核心状态：核心只发事件（落雷命中、爆炸、受击），渲染层用真实时间播放
- 浏览器验收可直接用倍速按钮快进，不必只依赖 `debugAdvance`

## 4. 可行性设计（性能与工程）

> 这是项目第一款「同屏几百对象」的游戏。结论：**逻辑层风险低，渲染层是唯一真正的未知数**，所以 M1 与 M2 分开设闸。

### 4.1 性能预算

| 对象 | 上限 | 说明 |
|------|------|------|
| 敌人 | 300 | 含 Boss 与精英；达到上限停止刷新 |
| 子弹（玩家） | 120 | 超出回收最旧 |
| 敌弹 | 120 | 与玩家子弹共用上限池 |
| 宝石 | 320 | 超出直接结算经验 |
| 特效（落雷/爆炸/升级） | 60 | 超出覆盖最旧 |
| 飘字 | 24 | `Label` 池；特效关闭时不生成 |
| 每帧图元 | ≤ 800 | 敌人 300 + 宝石 320 + 子弹 120 + 特效 60 |
| 纯逻辑单帧 | < 2 ms（均值），< 4 ms（p99） | Node 侧 300 敌人 × 600 帧实测 |
| 4x 逻辑负载 | 每秒 240 个逻辑步，单步仍 < 2 ms | 300 敌人满场时 4x 不得拖垮渲染帧 |
| 存档序列化 | < 8 ms，存档 < 100 KB | 20 秒一次 + 关键节点；低端机可放宽到 30 秒 |
| 预览端帧率 | 60 FPS（桌面） | 300 敌人 + 320 宝石 + 120 子弹；1x |
| 微信低端安卓 | ≥ 50 FPS（特效关闭档），≥ 30 FPS（特效开） | 6 分钟压力场景；4x 允许自动降速 |
| 内存 | 连续 3 局无明显增长 | 对象池复用，无逐帧 `new` |

### 4.2 架构原则：逻辑与渲染分离

```
SurvivorConfig.ts   纯常量（无 cc 依赖）
SurvivorCore.ts     纯逻辑（无 cc 依赖）：状态、步进、碰撞、掉落、升级、事件
SurvivorGame.ts     Cocos 组件：输入、固定步长、渲染同步、UI、存档
SurvivorRenderer.ts 渲染（可选拆分）：从快照绘制 Graphics
```

- `SurvivorCore` **禁止** `import { ... } from 'cc'`，可在 Node 里直接编译运行
- 渲染层只读快照，不反向修改核心状态
- 所有随机数来自核心内部的 `mulberry32(seed)`，**核心内禁止 `Math.random`**
- 固定时间步 `1/60`，渲染帧率与逻辑解耦

### 4.3 固定步长与倍速

```ts
private _acc = 0;
private _fixedDt = 1 / 60;
private _speed = 1;                          // 1 | 2 | 4

update(dt: number) {
    if (this._phase !== 'running') return;   // LEVEL_UP / PAUSED / 结算都停
    this._acc += Math.min(dt, 0.25) * this._speed;
    const maxSteps = 3 * this._speed;        // 1x=3, 2x=6, 4x=12
    let steps = 0;
    while (this._acc >= this._fixedDt && steps < maxSteps) {
        this._core.step(this._fixedDt, this._input);
        this._acc -= this._fixedDt;
        steps++;
        // 升级/胜负必须立刻中断，不能在同一帧继续推进
        if (this._core.getSnapshot().phase !== 'running') break;
    }
    if (steps >= maxSteps || this._core.getSnapshot().phase !== 'running') {
        this._acc = 0;                       // 丢弃余量，防死亡螺旋/选择后连升
    }
    this._syncRender();
}
```

- `SurvivorCore` 不知道倍速存在，永远只收到 `1/60`
- 倍速只放大累加器输入与单帧步数上限
- 低端机保护：游戏组件统计真实帧时间，连续 1.5 秒均值 > 22 ms 时把 `_speed` 降一档（4→2→1），并派发一次「已自动降速」提示

### 4.4 空间分桶

- 竞技场 2400×2400，桶边长 **80** → 30×30 = 900 个桶
- 每帧重建敌人桶（300 次插入）；子弹与落雷只查自身所在桶及相邻 8 桶
- 桶内用数组存索引，不创建临时对象
- 查询上限：每个桶最多检查 32 个敌人，超出部分跳过（防止极端聚集时的平方复杂度）

### 4.5 单 Graphics 批量绘制

**主方案**：所有敌人、子弹、宝石、特效画在 **1 个 `Graphics`** 上，每帧 `clear()` 后重画。

| 层 | 是否每帧重画 | 说明 |
|----|--------------|------|
| 背景网格/边框 | 否 | 场景加载时画一次，随 `World` 节点移动 |
| 敌人/子弹/宝石/特效 | 是 | 单 Graphics，按层依次绘制（宝石 → 敌人 → 子弹 → 特效） |
| 玩家 | 是 | 独立 Node + Graphics，方便旋转 |
| HUD 条 | 变化时 | 血条/经验条/Boss 条只在数值变化时重画 |

**图元成本控制**：

- 敌人只用 `fill()`，不用 `stroke()`；精英/Boss 才加描边
- 宝石用 4 顶点菱形；子弹用小圆（8 段）
- 落雷用 2–3 段折线 + 一个圆，不画粒子
- 爆炸只用 1 个圆 + 1 个外环

**已知风险**：`Graphics` 每帧重建几何体，图元多时 CPU 组装成本可能超过逻辑本身。因此：

- M2 必须实测 800 图元的 `_syncRender()` 耗时
- **备选方案 B（渲染不达标时启用）**：运行时用 `Graphics` 生成 4 张小纹理（三角/菱形/方块/圆），改用池化的 `Sprite` 节点；同纹理自动合批，300 个 Sprite 仍只有 4 个 draw call，代价是 300 次节点变换
- **备选方案 C（最后手段）**：敌人上限降到 150，体型放大 1.2 倍，视觉密度靠体型维持

> 不选「按对象建 Graphics 节点」：每节点一次 draw call，300 个必然崩。

### 4.6 对象池

| 池 | 预分配 | 复用策略 |
|----|--------|----------|
| 敌人 | 300 | 死亡后标记 inactive，刷新时取空槽 |
| 玩家子弹 | 120 | 命中/超时后回收 |
| 敌弹 | 120 | 同上 |
| 宝石 | 320 | 拾取后回收 |
| 特效 | 60 | 生命周期结束回收 |
| 飘字 Label | 24 | 取最旧覆盖 |

- 核心内部全部用**预分配数组 + active 标记**，`step()` 内不 `new` 对象、不 `push` 到新数组
- 事件队列复用同一个数组，每帧先清空再写入

### 4.7 后台、暂停与存档

- `game.on(Game.EVENT_HIDE)` → 立即 `PAUSED`，清空累加器，并**同步写一次局内存档**
- `game.on(Game.EVENT_SHOW)` → 保持暂停，等玩家点「继续」（避免回来就死）
- 暂停面板显示当前时间、等级、击杀，并提供「特效 / 震动」开关
- 局内存档写入 `StorageManager`（底层 `localStorage` / `wx.setStorageSync`）；清空存储即视为没有存档
- 存档时机：每 20 秒**真实时间**（与倍速无关）、每次升级生成三选一、暂停、切后台、返回大厅
- 胜负结算或开新局时删除存档；损坏/版本不匹配的存档直接删除并开新局（见 §7）

### 4.8 微信小游戏适配

|----|------|

### 4.9 压测与 Go / No-Go

**Gate A（M1 结束）**：`node tools/verify-survivor-core.js` 通过，且 300 敌人 × 600 帧纯逻辑 **均值 < 2 ms、p99 < 4 ms**；额外跑一轮 4x 负载（240 步/秒 × 60 秒），单步预算不退化。不通过就优化数据结构（桶内数组、减少临时对象），仍不通过则把上限降到 200。

**Gate B（M2 结束）**：桌面预览端在 300 敌人 + 320 宝石 + 120 子弹下稳定 60 FPS，`_syncRender()` 均值 < 5 ms；1x/2x/4x 下渲染帧率不因逻辑步数增加而跌破 50 FPS。不通过 → 启用备选方案 B；再不过 → 方案 C。

**Gate C（M7 结束）**：微信中低端安卓（至少一台）特效关闭档 6 分钟压力场景 ≥ 50 FPS，连续 3 局内存无增长；4x 下允许触发自动降速，但不得崩溃或卡死。

### 6.3 核心数据结构

```ts
export type Phase = 'running' | 'levelup' | 'victory' | 'defeat';

export interface Vec2 { x: number; y: number; }

export interface PlayerState {
    x: number; y: number;
    hp: number; maxHp: number;
    speed: number;
    pickupRadius: number;
    iframe: number;
    facing: number;              // 弧度
    level: number;
    xp: number;
    xpNeed: number;
}

export interface EnemyState {
    active: boolean;
    kind: EnemyKind;             // 'chaser' | 'weaver' | 'shooter' | 'bomber' | 'boss'
    x: number; y: number;
    hp: number; maxHp: number;
    speed: number; radius: number;
    damage: number;
    xp: number;
    elite: boolean;
    hitCooldown: number;         // 对玩家的接触冷却
    flash: number;
    // 行为专用
    phase: number;               // 绕行兵正弦相位 / 自爆倒计时
    shootTimer: number;
    volleyTimer: number;
    summonTimer: number;
}

export interface BulletState {
    active: boolean;
    fromPlayer: boolean;
    x: number; y: number;
    vx: number; vy: number;
    damage: number;
    radius: number;
    pierce: number;
    life: number;
    kind: 'knife' | 'boomerang' | 'enemy';
    // 回旋镖
    originX: number; originY: number;
    traveled: number; maxDistance: number; returning: boolean;
    hitIds: number[];            // 本次投掷已命中的敌人 id，防止往返重复计数
}

export interface GemState {
    active: boolean;
    x: number; y: number;
    value: number;
    magnet: boolean;
}

export interface UpgradeOffer {
    kind: 'weaponUpgrade' | 'newWeapon' | 'passiveUpgrade' | 'newPassive' | 'heal' | 'temper';
    track: string;               // 'knife' | 'orbit' | ... | ''
    currentLevel: number;
    nextLevel: number;
    title: string;
    detail: string;              // 「伤害 10 → 14」
}

export interface CoreEvent {
    type: 'levelup' | 'boss' | 'wave' | 'elite' | 'victory' | 'defeat' | 'hit' | 'pickup';
    data?: number;
}

/** 渲染层只读快照；数组为预分配池的只读视图 */
export interface SurvivorSnapshot {
    phase: Phase;
    time: number;
    kills: number;
    player: Readonly<PlayerState>;
    enemies: readonly Readonly<EnemyState>[];
    bullets: readonly Readonly<BulletState>[];
    gems: readonly Readonly<GemState>[];
    boss: Readonly<EnemyState> | null;
    offers: readonly UpgradeOffer[];
}
```

> 敌人 `id` 用槽位索引 + 代际计数器，防止回旋镖「命中记录」误伤复用槽位的新敌人。可用 `generation` 字段实现。

### 6.4 `SurvivorCore` API

```ts
export interface SurvivorInput {
    moveX: number;   // -1..1
    moveY: number;   // -1..1
}

export class SurvivorCore {
    constructor(seed: number);

    /** 固定步长推进；内部不检查时间，由调用方保证 dt = 1/60 */
    step(dt: number, input: SurvivorInput): void;

    /** 当前 3 张升级卡；非 levelup 阶段返回空数组 */
    getOffers(): readonly UpgradeOffer[];

    /** 选择第 index 张；应用后回到 running */
    chooseUpgrade(index: number): void;

    /** 只读快照，供渲染层遍历；不要在外部修改 */
    getSnapshot(): Readonly<SurvivorSnapshot>;

    /** 取出并清空本帧事件 */
    drainEvents(): CoreEvent[];

    /** 序列化当前局（纯数据）；phase 由游戏层按暂停状态覆写 */
    serialize(): RunSaveV1;

    /** 从存档恢复；核心会再做一次范围/上限校验，失败返回 false */
    restore(save: RunSaveV1): boolean;

    /** 保存面板展示用 */
    getRunSummary(): { time: number; level: number; kills: number };

    /** 调试用：快进 N 秒（按 1/60 步进），用于浏览器验收 */
    debugAdvance(seconds: number): void;

    /** 调试用：直接生成指定敌人/Boss，用于验收 */
    debugSpawn(kind: EnemyKind, count: number, elite?: boolean): void;

    /** 调试用：设置武器等级，用于逐武器验收 */
    debugSetWeapon(track: string, level: number): void;
}
```

### 6.5 每帧流程

```
输入采样（摇杆/键盘）
  → 若 phase != running：跳过逻辑
  → 累加器 += dt × 倍速；最多执行 3×倍速 个固定步
  → 每步后检查 phase：升级/胜负立即中断并清空累加器
  → drainEvents()：处理 levelup / boss / victory / defeat / 提示
  → 每 20 秒真实时间（与倍速无关）检查是否写档
  → renderer.sync(snapshot)
  → HUD 更新（仅数值变化时重画条；倍速文字变化时更新）
```

### 6.8 渲染同步约定

- `Graphics.clear()` 后按固定顺序重画；**不要**在循环里切换 `fillColor` 的频率高于必要（同色批量画）
- 同一帧内颜色相同的对象连续绘制，减少状态切换
- 敌人只在 `flash > 0` 时改用白色，其余用类型色
- 相机位置 = `clamp(-player, -(arena/2 - viewport/2))`，避免露出竞技场外
- 玩家节点世界坐标 = player 坐标，`World` 反向偏移；玩家旋转朝向最近敌人或移动方向（有移动时用移动方向）

### 6.9 场景搭建要点（MCP）

1. 场景 `Survivor.scene` 新建后，先搭静态节点树与 `@property` 绑定，再挂脚本
2. 所有按钮节点必须确认有 `cc.Button` 或走 Node 事件；`contentSize` 在 `spriteFrame` 之后设置（教训 C）
3. LevelUpPanel/PausePanel/ResultPanel 默认 `active=false`；在 `show()` 里先置内部标记再置 `active`（教训 D）
4. 面板遮罩必须挂 `UITransform` 并在 `TOUCH_START` 上吞掉事件，避免点面板时摇杆同时响应
5. 保存场景后 `validate_scene` + `lsp_diagnostics`

## 7. 存储

全部走 `StorageManager`；下表是**逻辑键**，`StorageManager` 会自动加 `tiny_games_survivor_` 前缀。

| 逻辑键 | 内容 | 写入时机 |
|--------|------|----------|
| `best_time` | 最佳存活秒数（击杀 Boss 记 999） | 结算 |
| `best_kills` | 最高击杀 | 结算 |
| `best_level` | 最高等级 | 结算 |
| `runs` | 总局数 | 结算 |
| `tutorial_seen` | 是否看过引导 | 引导结束 |
| `settings` | `{ lowFx: boolean, vibrate: boolean }` | 设置变更 |
| `run` | **当前局存档**（见 §7.1） | 见 §7.2 |

### 7.1 局内存档内容

> `RunSaveV1` 类型定义在 `SurvivorConfig.ts`（纯模块），核心只依赖类型；读写与校验在 `SurvivorSave.ts`。

```ts
interface RunSaveV1 {
    v: 1;                      // 版本；不匹配直接丢弃
    savedAt: number;           // Date.now()，仅用于展示「多久前」
    seed: number;              // 本局种子
    rngState: number;          // mulberry32 当前状态，保证读档后随机序列连续
    time: number;              // 逻辑秒
    phase: 'running' | 'levelup' | 'paused';   // paused 由游戏层写入
    kills: number;
    player: { x, y, hp, maxHp, speed, pickupRadius, iframe, facing, level, xp, xpNeed };
    weapons: Record<string, number>;   // { knife: 3, orbit: 1, ... }
    passives: Record<string, number>;  // { haste: 2, ... }
    temper: number;                    // 淬炼层数
    timers: {
        spawnAcc: number;
        nextEliteIndex: number;
        nextWaveTime: number;
        bossSpawned: boolean;
        bossEnrage: boolean;
    };
    enemies: CompactEnemy[];   // 只存 active；槽位索引 + 代际 id 一并保存
    bullets: CompactBullet[];
    gems: CompactGem[];
    boss: CompactEnemy | null;
    offers: UpgradeOffer[];    // phase === 'levelup' 时必须非空
}
```

- **紧凑数组**：敌人/子弹/宝石用定长数字数组（`[kind, x, y, hp, ...]`）而不是对象，减少 JSON 体积与序列化时间
- 目标体积 **< 100 KB**（300 敌人 + 320 宝石 + 120 子弹），远低于 `localStorage` 5 MB 限制
- 只保存核心状态；渲染对象、补间、临时特效不保存，读档后重新生成

### 7.2 保存与恢复流程

| 时机 | 行为 |
|------|------|
| 每 20 秒真实时间 | 后台保存一次（与倍速无关；低端机可放宽到 30 秒；见性能门槛） |
| 升级生成三选一 | 立即保存（保存 `phase='levelup'` 与 3 张卡） |
| 暂停 / 切后台 | 立即保存 |
| 返回大厅 | 先保存再跳转 |
| 胜利 / 失败 / 开新局 | **删除** `run` |
| 场景启动 | 读取 `run`：有效则弹「继续 / 新的一局」；无效或不存在则直接开新局 |

- 继续游戏时进入 **PAUSED**，显示「继续」覆盖层，玩家点击后才推进（不会一进来就被围）
- 若存档是 `levelup` 阶段：直接恢复三选一面板与保存的 3 张卡，选择后继续
- 恢复后必须校验：时间、等级、击杀、HP、武器等级、敌人数量与存档一致（±1 帧误差）
- **损坏处理**：JSON 解析失败、`v` 不匹配、字段缺失、数值越界、数组超过上限 → 删除 `run`，按新局启动，不弹错误
- **清理即失效**：不做云端、不做多存档槽；用户清空 `localStorage` 或换设备即没有存档
- 不做旧版本迁移：`v` 从 1 开始，后续结构变更直接丢弃旧档

### 7.3 核心接口

```ts
serialize(): RunSaveV1;              // 纯数据，不引用内部对象
restore(save: RunSaveV1): void;      // 校验由游戏层先做，核心再做一次范围检查
getRunSummary(): { time: number; level: number; kills: number };
```

> `serialize()` 在 `SurvivorCore` 内实现，保证逻辑状态完整；`localStorage` 读写由 `SurvivorGame` 负责，核心不碰存储。

#### 8.5.1 M1 实测调参记录（2026-11-02）

首轮 29 项自检中，第 20 项在原始经验曲线 `need = 6 + 4 × (level - 1)` 下不达标：跑位策略能存活满 480 秒，但 300 秒时只有 4–5 级（5 个种子：5/6(172 秒阵亡)/4/4/5）。交叉实验：

| 玩法风格 | 300 s 等级 | 结局 |
|---------|-----------|------|
| 只跑不捡（脱离接触） | 3–4 | 活满 480 s，但经验全留在身后 |
| 谨慎跑位 + 顺路捡（参照策略） | 4–5 | 活满 480 s |
| 站着打 + 高血量（压力测试） | 29–31 | 击杀 2000+，说明战斗数值本身不"过难" |
| 主动贴脸输出 | — | 30–90 秒阵亡（兽潮 + 包围） |

结论：**不是战斗强度问题，而是经验流速问题**——300 秒累计刷怪约 2040 只，6–14 级对应约 70–450 次击杀的经验，而参照策略只捡到其中一小部分。按规格"若断言失败说明基线过难或过易"的约定，只调经验曲线一个旋钮：

- `XP_CURVE_STEP`：4 → **3**（`need(level) = 6 + 3 × (level - 1)`），首次升级仍是 6 XP（10–15 秒）
- 代价与收益：升级更快 ⇒ DPS 成长更早 ⇒ 反而更不容易死。同一策略 5 个种子：**7 / 8 / 7 / 4 / 5**（6+3 曲线下），基准种子 2026 得 300 s 7 级、187 击杀，活满 480 s
- 未改动的旋钮：拾取半径（60）、宝石掉率（90%）、属性倍率、升级卡池

后续 M4 试玩若出现"等级涨太快、构筑提前定型"，优先回调 `XP_CURVE_STEP`（3.5 不可用，取 4 即回到初稿）。

| 2x（300/320/120） | 60.02 | **1.32 ms** | 2 | 5.20 s |
| 4x（300/320/120） | 59.94 | **1.09 ms** | 4 | 10.40 s |

结论：渲染耗时约为门槛（5 ms）的 1/4，三个倍速均未跌破 50 FPS，模拟时间比严格 1:2:4。**Gate B 通过，不启用备选方案 B/C。**

**交互验收**（浏览器真实输入）：大厅滚到底 → 点「午夜幸存者」→ 切到 `Survivor` 场景并进入 `running`；「返回」回大厅；按住 D 0.8 s 玩家 x +172（220 px/s）；按住 W 0.8 s y +180；`1/2/4` 切倍速、`X` 循环、`P` 暂停/恢复、`R` 重开均生效；相机跟随下玩家恒在屏幕中心。

**过程中修掉的两个问题**：

1. **玩家会飞出屏幕**：`World` 整体按 `-p` 平移做相机跟随，而玩家 `Graphics` 画在子节点局部 `(0,0)`。修法是渲染层每帧把玩家节点摆回 `(p.x, p.y)`（`SurvivorRenderer._drawPlayer` 首行）。场景搭建阶段就能看出来，属于结构性问题而非调参。
2. **压测读数被 `defeat` 污染**：第一批压测里混入了敌方子弹，玩家被打死后 `phase = defeat`，`_advance()` 每帧只跑 1 步——2x/4x 的帧率数字其实没经过多步逻辑。判据是 `stepsPerFrame` 恒为 1 且 `_steps = 1`。改成只用己方子弹 + 血量拉满后复测，步数才正确呈 1/2/4。

**本次压测的边界**：压测敌人都在屏幕外（半径 700+），单 Graphics 的**几何组装**成本被完整覆盖，但**填充率**（大量图元叠在同一屏幕区域）没有被测到；低端安卓的填充率风险留给 Gate C 真机验收。另外压测期间会自动选第一张升级卡（三选一面板在 M3）。

> 待办：`Survivor` 尚未进微信构建场景清单（`node tools/sync-build-scenes.js --check` 报 3 处待同步）。该脚本在编辑器运行时拒绝写入，需退出 Cocos Creator 后执行一次。

## 11. 已确认的实现约定（2026-11-02）

| # | 决定 | 实现约定 |
|---|------|----------|
| 1 | 中文名 **午夜幸存者** | 大厅 `GAME_LIST` 注册 `id: 'survivor'`、`sceneName: 'Survivor'`；不直接使用「吸血鬼幸存者」名称 |
| 2 | 单局 **8 分钟** + **1x/2x/4x** 倍速 | 倍速只放大累加器与步数上限；默认 1x；纪录按逻辑时间；低端机自动降一档 |
| 3 | **4 武器 + 4 被动，3 武器槽 + 2 被动槽** | 武器：飞刀/星环/落雷/回旋镖；被动：攻速/移速/拾取/体魄；每线 5 级 |
| 4 | **做本地局内存档** | `StorageManager` 键 `run`；每 20 秒真实时间 + 升级 + 暂停 + 切后台 + 退大厅保存；胜负/新局删除；坏档静默丢弃；不迁移旧版本 |
| 5 | **做特效开关** | 安卓首次默认关闭，iOS/桌面默认开启；暂停面板可切换并持久化；只影响表现，不影响数值 |

**如果后续想压缩排期**，可以按以下顺序砍（不影响核心循环）：倍速系统（−1 人日）→ 局内存档（−2 人日）→ 体魄被动（−0.5 人日）→ 回旋镖（−1 人日）。不建议砍掉 4+4 构筑与双重性能门槛。
