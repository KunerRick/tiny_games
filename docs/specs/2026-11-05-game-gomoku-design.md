## 1. 一句话玩法

15×15 棋盘的经典五子棋：黑先白后，先在横 / 竖 / 斜任意方向连成五子者胜；支持本地双人与三档 AI。

## 2. 目标体验

- **单局 1–5 分钟**，规则零学习成本，点交叉点即落子。
- 核心乐趣来自三件事：
  1. **读棋**：看对手的活三 / 冲四，决定攻还是防；
  2. **形成威胁**：做双三、四三，逼对手应不过来；
  3. **AI 有分寸**：新手能被业余玩家赢，困难档要真的会堵、会做杀。
- 不追求竞技级棋力（v1 不做禁手、不做联网），追求「点得准、反应快、输了想再来一局」。

## 3. 规则细则

### 3.1 棋盘与落子

- 棋盘 15×15 交叉点，坐标 `(row, col)`，`0..14`，左上为 `(0,0)`；内部用一维下标 `row * 15 + col`。
- 黑方先行，双方轮流在**空交叉点**落子；已有棋子的点不可落子。
- 点交叉点空白处容差：落点距离最近交叉点不超过 `0.6 × 格边长`，否则忽略。
- 棋盘为空时，AI 首手固定落在天元 `(7,7)`。
- **v1 不实现禁手**（长连、三三、四四都按普通五连判胜）。

### 3.2 胜负与平局

- 每次落子后，只沿落子点的四个方向（横 / 竖 / 主斜 / 副斜）双向统计连续同色子。
- 连续数 **≥ 5** 即判该方胜；胜线包含落子点两侧全部连续子，界面整条高亮（长连 6 子也整条高亮）。
- 棋盘所有交叉点填满且无人连五 → 平局。
- 胜负判定后禁止继续落子；允许「悔棋」回到终局前（见 §3.5）。

### 3.3 模式

| 模式 | 说明 |
|------|------|
| 人机 | 玩家执黑先行，AI 执白；三档难度可选；计入战绩 |
| 双人 | 同机轮流落子（黑 / 白），不计入战绩与 AI 相关统计 |

- 模式切换后立即重开。
- 模式偏好持久化。

### 3.4 难度（仅人机）

| 难度 | 棋力 | 行为 |
|------|------|------|
| 新手 | 很弱 | 候选点里 35% 纯随机，其余在启发式前 5 名里随机，会漏防 |
| 普通 | 中等 | 先判「自己能赢 / 对手下一手能赢」，否则取启发式最高分的点 |
| 困难 | 较强 | 在普通之上做 2 层搜索（我落子 → 对手最佳应手 → 再评估），能识别双威胁 |

- 难度按钮切换后立即重开；难度偏好持久化。
- AI 落子前有 0.25–0.45 秒「思考」延迟，期间状态条显示「AI 思考中…」并锁输入。

### 3.5 悔棋

- 人机模式：一次悔棋回退到**玩家上一手之前**——通常回退 2 步（AI 应手 + 自己上一步）；若玩家上一手已终局（AI 没再落子），只回退 1 步。
- 双人模式：一次悔棋回退 **1 步**。
- AI 思考中禁止悔棋。
- 悔棋需**精确还原**落子前的棋盘、当前手方、最后一步标记、终局状态与胜线（自检用状态深比较）。
- 终局后悔棋可撤销胜负，继续下棋；已计入的战绩同步回滚，重下终局后按新结果重新记录。
- 终局结算面板会盖住棋盘：**点面板外空白处可关闭面板**回到终局棋盘，此时「悔棋」可用（面板按钮只有「再来一局 / 返回大厅」）。

### 3.6 重开与返回

- 「重开」清空棋盘、当前手方回到黑方、手数归零；保留模式与难度。
- 左上返回按钮回大厅。
- 对局不做中途快照（v1 范围外），退出即弃局。

### 3.7 战绩

- 仅人机模式结算：胜 / 负 / 平分别累计，`localStorage` 持久化，顶栏与结算面板展示。
- 双人模式不改变战绩。

## 4. AI 设计

### 4.1 候选点剪枝

- 取所有空点中与任意已有棋子**切比雪夫距离 ≤ 2** 的点；为空则取天元。
- 候选点数量上限按难度截断：普通 60 个、困难 12 个（按启发式初排后截断）。
- 落点前先做两次快速判定：
  1. **必赢**：存在一点让我方成五 → 直接下；
  2. **必堵**：存在一点让对手成五 → 直接堵（多点时取启发式最高者）。

### 4.2 启发式评分

对候选点，分别以「我方落子」和「对手落子」计算四个方向的棋型分，相加：

| 棋型 | 判定 | 分值 |
|------|------|------|
| 成五 `FIVE` | 连续 ≥ 5 | 1,000,000 |
| 活四 `OPEN_FOUR` | 连续 4，两端皆空 | 100,000 |
| 冲四 `FOUR` | 连续 4，一端空 | 12,000 |
| 活三 `OPEN_THREE` | 连续 3，两端皆空 | 8,000 |
| 眠三 `THREE` | 连续 3，一端空 | 800 |
| 活二 `OPEN_TWO` | 连续 2，两端皆空 | 400 |
| 眠二 `TWO` | 连续 2，一端空 | 60 |
| 单子 `SINGLE` | 连续 1，两端皆空 | 10 |

- 候选点总分 = `我方棋型分 + 对手棋型分 × 1.15`（略偏防守，保证会堵活三 / 冲四）。
- 同分时用种子随机数打破平局，保证同种子完全可复现。

### 4.3 三档行为

- **新手**：35% 概率从前 20 个候选里纯随机选一点；否则在前 5 名里随机。不做「必堵」的强制判定（会漏防是设计意图），但仍不做非法落子。
- **普通**：必赢 / 必堵优先；否则取启发式第 1 名。
- **困难**：必赢 / 必堵优先；否则对前 12 个候选各模拟落子，再用普通策略估算对手最佳应手的分数，取 `我方分 - 对手应手分 × 0.9` 最高者。
- 所有难度返回的点**必须为空位且在盘内**；极端情况下（候选为空、棋盘已满）返回 `null`。

### 4.4 性能预算

- 困难档单步：12 候选 × 对手约 60 候选 × 评分 O(4×9)，预计 < 5 ms，浏览器与微信小游戏均可同步计算。
- 自检要求：新手 / 普通自我对弈合计 **500 局**、困难 **30 局**不崩溃、无非法落子，并输出耗时（实测约 1.2 s / 0.8 s）。

## 6. 交互流程

```
进入场景
  └─ onLoad：读模式/难度/战绩 → 建 UI → newGame()
点击交叉点
  ├─ 非人机回合 / AI 思考中 / 已终局：忽略
  ├─ 非空点：忽略（可选 toast 提示）
  └─ 落子 → 判定胜负 → 刷新棋盘
        ├─ 未终局且人机模式：状态「AI 思考中…」→ 计时到点 → AI 落子 → 判定
        └─ 终局：延迟 0.45s 弹结算面板，记录战绩
悔棋
  └─ 按模式回退 1 或 2 步 → 精确还原 → 若已终局则撤销终局
重开
  └─ 清盘 + 移回黑方先手 + 记手数 0（保留模式/难度）
```

## 8. 可玩性评估

- **上手成本**：零（会下五子棋就会玩），点交叉点即落子；两种模式覆盖单人与双人场景。
- **反馈密度**：每手都有视觉变化（棋子 + 最后一步红点 + 状态条），终局有胜线高亮与结算面板。
- **难度曲线**：新手档会漏防，普通档会堵冲四，困难档会算一层应手；三档之间是行为差异而非单纯随机，玩家能感知进步。
- **重玩动机**：战绩累计 + 一键重开 + 难度可切换；单局短，适合移动端碎片时间。
- **风险**：无禁手下困难 AI 可能长期无法取胜（双方都在堵），需要靠「双威胁」制造突破；2 层搜索在 15×15 上足够，不引入更深的搜索以免卡顿。

## 9. 技术要点与文件结构

```
assets/games/game_gomoku/
├── scenes/Gomoku.scene          # Canvas > Camera + GameRoot(GomokuGame)
└── scripts/
    ├── GomokuCore.ts            # 纯逻辑：棋盘、胜负、悔棋历史、AI（无 cc 依赖）
    └── GomokuGame.ts            # 场景主组件：全部 UI 代码构建
tools/verify-gomoku-core.js      # 纯逻辑自检（tsc 编译后 node 运行）
```

- `GomokuCore.ts` 不引用 `cc`，可被 Node 自检直接编译运行。
- 棋盘用 `Uint8Array(225)`；`0` 空 / `1` 黑 / `2` 白。
- 历史记录保存每步的 `{ index, player, winnerBefore, winLineBefore, fullBefore }`，悔棋按记录精确还原。
- `GomokuGame.ts` 参照 `IdiomGame.ts`：单节点挂组件，`onLoad` 建 UI，`Graphics` 画棋盘 / 棋子，`Node.EventType.TOUCH_START` 统一处理落点换算。
- AI 延迟用 `update(dt)` 计时泵（不依赖 `scheduleOnce` 自排期，避开引擎丢弃同回调的问题）。
- 事件 handler 全部具名；`onDestroy` 只清 JS 引用。
- 图标 / 文案不写变体选择符（U+FE0E / U+FE0F）。

## 11. 设计评审（2026-11-05）

评审方式：按「规则闭环 / 交互边界 / AI 可测性 / 渲染性能 / 与现有工程约定一致性」五项逐条自查，并对照路线图 §5.2 的 v1 范围。

| # | 评审问题 | 结论 / 修订 |
|---|---------|------------|
| 1 | 困难 AI 只做 2 层搜索够不够？ | 够 v1。路线图写的是「2 层搜索 + 评分」；再加深度会显著拉高移动端延迟，v1 不做 |
| 2 | 新手 AI 完全随机会不会下出「必输手」？ | 允许。新手档 35% 纯随机、不强制堵冲四，是刻意保留的可战胜性；仍保证合法性 |
| 3 | 悔棋在终局后是否允许？ | 允许，且必须撤销胜负与胜线，否则玩家点到终局后只能重开。历史记录带 `winnerBefore` / `winLineBefore` 解决 |
| 4 | 人机悔棋回退 2 步在 AI 首手前是否越界？ | **修订**：不能机械回退 2 步。玩家落子直接终局时 AI 没有应手，回退 2 步会退到 AI 回合（`current = WHITE`）。改为「回退到黑方回合，最多 2 步」；历史不足时按实际步数回退 |
| 5 | 平局如何测试？ | 用构造的满盘无五连棋盘直接喂给判定函数，不依赖 AI 下满 |
| 6 | 15×15 棋盘 648px 外框在 720 宽下是否够点？ | 左右各余 36px；格边长 44px，点容差 26px，实测手感足够 |
| 7 | 225 个棋子逐个建节点会不会重？ | 不建节点。棋盘与棋子各用一个 `Graphics` 整体重绘，节点数恒定 |
| 8 | 是否复用 `GameUIKit`？ | 复用按钮 / Label / toast / 配色；棋盘自绘 |
| 9 | 战绩是否包含双人模式？ | 不包含，避免自欺数据；与路线图「战绩存档」一致 |
| 10 | 与成语填字的实现约定是否一致？ | 一致：纯逻辑 + 自检脚本 + 代码建 UI + 极简场景 + 具名 handler |
