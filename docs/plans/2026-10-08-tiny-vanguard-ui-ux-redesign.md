> 方法：浏览器工具操作编辑器预览（`http://127.0.0.1:7456/`），用页内探针导出**每个节点的世界坐标包围盒、字号/行高、颜色、层级**，量化判定重叠、溢出与配色问题。

## 二、系统性问题（跨界面共性根因）

这些是 1–7 的共同成因，先解决它们，各界面修复才不回退。

### 2.1 无设计令牌：字号、行高、颜色、间距各自为政

实测字号分布（当前战斗场景）：`24/40`、`16/40`、`20/40`、`18/40`、`40/40`、`22/40`、`13/40` —— **7 种字号**，行高**一律写死 40**。

后果：
- `fontSize(48) > lineHeight(40)`（`ClassSelectPanel/TitleLabel`、`VictoryLabel`、`RunVictoryPanel/VictoryLabel`、`BattleStartTitle`）→ 文字被行高截断或视觉拥挤，**这是"上方说明文字挤在一起"的直接原因**。
- 颜色散落 15+ 种，同语义（如"可交互/成功"）在不同界面用了 `34,197,94`、`60,180,60`、`39,174,96`、`120,255,120`、`150,230,150` 五种绿。

### 2.2 布局靠手填坐标，没有容器与约束

- 面板用固定尺寸（`ClassSelectPanel` 280×300、`RunVictoryPanel` 260×180），子节点用绝对坐标摆放，**按钮高度 36 但包围盒含内边距 50、间距却按 40 排** → 系统性重叠 10px。
- 与画布尺寸不匹配：`VictoryPanel`/`DefeatPanel` **750×1334** 大于画布 720×1280。

### 2.3 信息重复与层级不清

战斗界面的阶段提示同时存在于 `DeployPrompt`、`PhaseLabel`、`UnitTurnLabel`、`ActionHintLabel` 四处，且文案几乎相同（"部署单位" / "放置单位"），又与 `PhaseBg` 重叠 —— 这是"上方说明问题和提示文字需要好好考虑"的核心。

## 三、设计令牌（建议统一采用）

> 以下为建议值，落在 `GameData.ts` 或新建 `Theme.ts` 中集中定义，各界面引用，**不再散落魔法数**。

### 3.1 色板（深色底 + 单一主强调色）

| 令牌 | 值 | 用途 |
|------|-----|------|
| `BG_OVERLAY` | `#000000` alpha 180 | 全屏遮罩 |
| `PANEL_BG` | `#1E2430` alpha 245 | 面板底 |
| `PANEL_BORDER` | `#3A4658` | 面板描边（1–2px） |
| `PRIMARY` | `#3B82F6` | 主操作（继续 / 确认） |
| `PRIMARY_DISABLED` | `#374151` | 禁用态 |
| `SUCCESS` | `#22C55E` | 可攻击/已完成/回血 |
| `DANGER` | `#EF4444` | 敌人/伤害/失败 |
| `WARNING` | `#F59E0B` | 高亮/金币 |
| `INFO` | `#06B6D4` | 能量/技能 |
| `TEXT_PRIMARY` | `#F3F4F6` | 正文 |
| `TEXT_SECONDARY` | `#9CA3AF` | 次要说明 |
| `TEXT_DISABLED` | `#6B7280` | 不可用文字 |

> 收敛后同语义只有**一种**颜色；`HighlightBorder` 等修饰元素改用描边（`Graphics` 或九宫格描边 Sprite），不再用整块色块覆盖。

### 3.2 字号阶梯（行高 = 字号 × 1.4）

| 令牌 | 字号 | 行高 | 用途 |
|------|------|------|------|
| `FONT_DISPLAY` | 40 | 56 | 通关/胜利大标题 |
| `FONT_TITLE` | 28 | 40 | 面板标题 |
| `FONT_BODY` | 20 | 28 | 正文/按钮文字 |
| `FONT_CAPTION` | 16 | 22 | 次要说明 |
| `FONT_TINY` | 13 | 18 | 单位名牌 |

**硬性约束：`lineHeight ≥ fontSize × 1.2`**（当前 48/40 必须废止）。

### 3.3 间距与尺寸

- 间距基准 **8**：`SPACE_XS=4 / SM=8 / MD=16 / LG=24 / XL=32`
- 按钮高度统一 **48**（当前 36/40/60 混用）；列表项间距 ≥ 8
- 面板留白：内边距 **24**，标题与内容间距 **16**
- 所有面板尺寸 **≤ 画布**（`720×1280`），推荐统一 `640×960` 内边距 24

## 四、逐界面改版方案

### 问题 1：职业选择（`ClassSelectPanel`）

**现状**：280×300 面板内塞 6 个元素，10px 重叠链式发生。

**方案**：
```
┌─ ClassSelectPanel  640×720（内边距 24）──┐
│  组建队伍            FONT_TITLE 28/40    │  ← y 由 760 下移，与副标题拉开 16
│  ┄┄┄┄┄┄┄┄┄┄┄┄┄ 分割线 ┄┄┄┄┄┄┄┄┄┄┄┄╌│
│  选择 3 个职业       FONT_CAPTION 16/22   │
│  ┌────────────────────────────────────┐  │
│  │  ⚔️ 战士    已选 2/3          ✓   │  │  ← 列表项高 64，间距 12
│  │  🏹 弓箭手                     ✓   │  │
│  │  🔮 法师                           │  │
│  │  💚 牧师                      🔒   │  │  ← 未解锁置灰 + 锁图标
│  └────────────────────────────────────┘  │
│  [      开始游戏 (3/3)      ]  高 48     │  ← 与列表间距 24
└──────────────────────────────────────────┘
```
- 选中态：**左侧 4px 竖条 + 描边**，不用整块 `HighlightBorder` 覆盖（消除 100% 重叠）
- 取消 `tween` 放大到 1.1（避免选中时与邻项重叠 64–80%），改用描边/亮度变化
- 「继续上局」独立成次要按钮，固定在面板下缘外（与「开始游戏」间距 ≥ 24）

### 问题 2：路线图（`RouteMapUI`）

**现状**：层级已对但节点半透明致连线透出；`content` 尺寸错误；节点只占两列。

**方案**：
1. **节点改为不透明卡片**：可用节点 `SUCCESS` 实心 + 发光描边；不可用节点用 `PANEL_BG` **实心** `#263041`（而非 128 半透明），彻底遮住线头；已完成节点打勾。
2. **连线绘制**：`lineWidth 3 → 4`，颜色用 `PANEL_BORDER` 实心；**可达段**用 `SUCCESS` alpha 220 + 箭头；在折线转折处加**圆点节点（路标）**，让走向可读。
3. **修正 `content` 尺寸**：按节点实际跨度设置（宽 ≥ 画布 − 32，高 ≥ 最底节点 y + 边距），否则 `ScrollView` 滚动范围错误。
4. **布局**：节点列距从 130 增至 **180**，整体居中（当前居中于 x=115/245，画布 720 右侧空）；或改为**三列蛇形**布局，充分利用宽度。
5. 顶部加**关卡进度条**（`已通关 3/10`）与图例（⚔️战斗 🏪商店 💤休息 ❓事件 🏆Boss）。

### 问题 3：胜利面板（`BattleUI/VictoryPanel`）

**现状**：「进入升级...」与「继续」按钮重叠 35px；面板 750×1334 超画布。

**方案**：
```
┌── VictoryPanel  560×620 ──┐
│        胜  利             │  FONT_DISPLAY 40/56  金黄
│  ───────────────────────  │
│   💰 金币    +10          │  行高 32，标签/数值分左右对齐
│   ⏱ 回合     1            │
│   ⚔ 伤害     15           │
│                           │
│   [   继续   ]  高 48     │  ← 唯一按钮，与上方统计间距 24
└───────────────────────────┘
```
- **删除 `ContinueLabel`**（"进入升级..."）—— 它是重复文案；按钮文字已表达动作
- 统计用**左右对齐的两列表格**，替代当前堆叠的四个独立 Label
- 面板尺寸收敛到画布内（≤ 720×1280）

### 问题 4：升级选技能（`UpgradeUI`）

**现状**：仅标题 + 3 张卡片，无进度、无跳过、无反馈。

**方案**：
```
┌── UpgradeUI  640×760 ─────────────┐
│  为 战士 选择强化      第 1/3 位   │  ← 加进度
│  [▓▓░░░] 已选 1/3                 │  ← 进度条
│  ┌─────┐ ┌─────┐ ┌─────┐          │
│  │ ⚔️  │ │ 🛡️  │ │ ❤️  │          │  ← 卡片 180×260，间距 20
│  │横扫 │ │反击 │ │+1血 │          │     分类色：技能蓝/被动紫/属性绿
│  │80%… │ │反弹…│ │最大…│          │
│  └─────┘ └─────┘ └─────┘          │
│  悬浮：上移 8px + 描边主色          │  ← 明确的选中反馈
│  [ 跳过本次升级 ]  次要按钮 高 44   │
└───────────────────────────────────┘
```
- 卡片加**图标 + 类型徽章**（技能/被动/属性），描述限 2 行
- 已学技能**置灰不可选**（同时修复验收报告中的"重复技能"问题）
- 加「跳过」与逐位进度

### 问题 5：战斗界面（`BattleUI`）

**现状**：四处提示信息重复 + 重叠；按钮字号/尺寸不齐。

**方案（分区重构）**：
```
┌ 顶部 HUD ─────────────── 高 64 ─┐
│ ⏱ 回合 1 第3轮        💰 120  │  ← 左：回合  右：金币（两端对齐）
└─────────────────────────────────┘
┌ 阶段条（仅一处） ─────── 高 40 ─┐
│  布阵阶段 · 点击前两行部署       │  ← 合并 PhaseLabel + DeployPrompt + ActionHintLabel
└─────────────────────────────────┘
              …棋盘…
┌ 单位信息 ── 左上浮动 ────────────┐
│ 战士   ❤️8/8   ⚡5/5            │
└─────────────────────────────────┘
┌ 行动栏 ───────────── 高 72 ─────┐
│ [攻击]  [技能▾]  [等待]  [结束] │  ← 统一高 48、等宽、字 20
└─────────────────────────────────┘
```
- **合并提示**：`PhaseLabel`（阶段）+ `DeployPrompt`/`ActionHintLabel`（操作提示）合成**一条阶段条**，文案唯一（"布阵阶段 · 点击前两行部署"），删除重复的 `DeployPrompt`
- `PhaseBg` 撤掉独立背景，改为阶段条自身底
- 行动栏按钮**统一高 48、字号 20**（当前 `AttackLabel 40` / `WaitLabel 40` / `EndTurnLabel 16`）
- 金币/回合 HUD 两端对齐，坐标由 `Widget` 锚定左上/右上（当前 `GoldLabel` 在 (648,1135) 右上、回合在别处，未成对）

### 问题 6：配色

**方案**：采用 §3.1 色板，且：
- **敌人**统一 `DANGER` 系（当前 `剑兵 100,180,255` 蓝、`unitSprite 255,100,100` 红混用）
- **玩家**统一 `SUCCESS`/`PRIMARY` 系
- **HP 条**：底 `#374151`、填充按血量变色（>50% 绿 / 20–50% 黄 / <20% 红）
- 移除霓虹青 `0,221,221` 等孤立色

### 问题 7：通关界面（`RunVictoryPanel`）

**现状**：`VictoryLabel` 框 100×100 装不下 48 号字；面板仅 2 个纯文字，无层次。

**方案**：
```
┌── RunVictoryPanel  560×640 ──────┐
│            🏆                     │  ← 图标
│          通  关  ！               │  FONT_DISPLAY 40/56 金黄
│  ──────────────────────────────  │
│   抵达第 9 关 · 荣誉 +100         │  正文 20/28
│   本局伤害 128 · 金币 55          │
│                                  │
│   [   返回大厅   ]   高 48        │  ← 明确的按钮（含背景框）
└──────────────────────────────────┘
```
- 每行文字用**自适应尺寸**（`Label` 开 `RESIZE_HEIGHT` 或按内容设宽），不再固定 100×100
- 「返回大厅」做成**有背景框的按钮**（`PRIMARY` 填充 + 圆角），当前只有裸文字
- 与 `GameOverPanel` 统一版式（同尺寸、同结构），保持一致性

## 六、走查中另外发现的问题（沿用可玩性验收）

来自 [`2026-10-08-tiny-vanguard-playthrough-acceptance.md`](./2026-10-08-tiny-vanguard-playthrough-acceptance.md)，属**逻辑**问题，建议与 UI 改版一并处理，因为其中两条直接造成 UI 观感问题：

1. **Boss 单位重复登记** → Boss 战出现两个「战争领主」（`BattleManager.ts:126-129`），UI 上表现为敌人列表重复。
2. **升级卡池未排除已学技能** → 技能栏出现重复项（`TinyVanguardMain.ts:646`）。
3. **`addSkill()` 无去重且满 3 个静默 pop**（`UnitController.ts:364-374`）。
4. **事件选项无金币校验**（`TinyVanguardMain.ts:848-850`）。

### 建议的修复方案

| # | 问题 | 建议改法 | 效果 |
|---|------|---------|------|
| 1 | Boss 单位重复登记 | 删掉 `if (bossUnit) { this._enemyUnits.push(bossUnit); }` 整段——`spawnEnemy()` 内部已 `push` 并 `return` 实例 | 一行删除；Boss 战恢复「1 boss + 2 杂兵」，敌方回合不再让 Boss 行动两次 |
| 2 | 升级卡池未排除已学技能 | `generateUpgradeOptions()` 先过滤：`skillPool.filter(id => !unit.data.skills.some(s => s.id === id))`；若过滤后不足 3 项，用属性增益项补位 | 杜绝重复技能；与 UI 改版的「已学技能置灰」互为兜底 |
| 3 | `addSkill()` 无去重 + 满 3 静默 pop | ① 已拥有则 `return`；② 满 3 个不再静默 `pop()`，改为**拒绝并提示**（或由 UI 让玩家选替换位） | 消除"选了没变化"；避免玩家在不知情时丢技能 |
| 4 | 事件选项无金币校验 | `EventUI` 生成选项时，若 effects 含 `spend_gold` 且 `gold < amount`，该选项**置灰不可点**；`spend_gold` 与 `learn_skill` 同组时统一判定 | 规则透明；与商店已有的 `gold < 10` 守卫保持一致 |

> 1–3 属同一条成长/战斗数据链，建议一并修改后复跑回归；4 为独立小改。

### 8.4 风险与注意

- **不要直接编辑 `.scene` JSON**（AGENTS.md 红线 2）。
- 面板类在 `onLoad` 里 `if (!_showCalled) node.active = false` 的懒初始化约定要保留；新增面板节点时确认 `show()` 先置 `_showCalled` 再置 `active`。
- 可点击元素优先 `@property({ type: Node })` + `Node.EventType.TOUCH_END`（红线 3）；新增按钮节点后必须补 `cc.Button` 或走 Node 方案。
- 场景重构与代码改动**同阶段成套做**，否则会出现"代码引用已删除节点"的运行时错误。
