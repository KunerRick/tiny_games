## 5. 未复现 / 已排除的疑点

1. **「414×896 下营地页签点不动」** —— 假警报。先 `setViewportSize` 再点，引擎输入用的画布矩形仍是 resize 前的（缓存未刷新），点击整体偏移：页签全部无反应，而点「返回」看似生效其实命中的是遮罩关闭路径。**在同一视口整页 reload 后，五页签逐一点击全部正常切换**。属预览工具 resize 时序问题，不是游戏缺陷；报告中的 414 交互结论均来自 reload 后的会话。
2. **「reload 后 `C` 键失效」** —— 复测两次：`closed → open → closed` 均正常，不依赖先点画布。此前是探针未注入/页面焦点导致的误判，未列为问题。
3. **「营地打开时点地图会让角色移动 / 触发节点」** —— 未复现。对地图节点位置真实点击后，`expedition` 与地图状态完全不变；点击实际落在营地自己的装备行上（`_selUid` 变化）。战斗输入冻结成立。
4. **「重铸在 Lv0 完全没有提示」** —— 不成立：页头与升级行都写明「尚未建造（升到 1 级解锁）」；只有按钮标签本身缺门槛说明（见 N52）。
5. **「料理只是 UI 文案，没进战斗」** —— 已证伪：真实战斗前后 `attackPower 18.627 → 16.9337`（正好 ÷1.1），并有结算行「料理结束：力量炖锅（下一场不再生效）」。
6. **N49 是否只是"读得太早"** —— 不是：弹窗打开后 600ms 仍为旧值，且必须等到关闭弹窗才刷新，可稳定复现。

## 7. 本轮未覆盖

1. **高等级设施行为**：铁匠铺 Lv2 锁 1 条 / Lv5 −50%，附魔台 Lv2–Lv5（2 条、保留源、材料减半、无视品质），训练场 Lv2 半价 / Lv3 免费 / Lv4–5 方案存读，厨房 Lv2 5 种 / Lv3 双 buff / Lv4 ×1.5 / Lv5 3 场，军需官 Lv2+ 与悬赏位 3→6 的实际生效 —— 当前存档设施为 Lv1–3、材料有限，本轮浏览器侧不可达；这些由开发者 `verify-mithril-camp.js`（337 项）覆盖，未在本报告中复核。
2. **Lv2→3 的 `霜晶 ×8`**：没有 Lv2 设施，未直接观测（其余档位均已实测）。
3. **附魔拒绝路径**（源=目标 / 目标词条已满 / 重复词条）与**重铸无重复/单词条必换**：本轮为控制真实存档消耗未逐条构造。
4. **满仓掉落折算金币**：背包 11/66，未构造。
5. **副本本体**（M6）与**悬赏本体**（M8）：按验收记录尚未实现，本轮只核对军需官的数值/文案。

## 8. 结语：营地值得用吗？最该修的三个点

**值得用，而且是 M5 里最有"成长感"的一块。** 五个设施把金币与三种材料分流得很清楚：升级只吃材料、金币只花在重铸/附魔/料理/洗点，玩家不会因为点了一次升级就没钱做核心操作。Lv1 就能摸到重铸、附魔、料理三条正反馈路径，且都不是空转——料理的 +10% 攻击强度在真实战斗里被量到 1.1×，Lv4 的「重铸 −25%」也确实把 112 金变成 84 金。界面在 1280 与 414×896 下都干净，页头把"当前/下一级"写在最显眼处，材料不足时直接说差多少，这几点比多数同类小游戏做得好。

最该修的三个点：
1. **N49：弹窗打开期间把顶栏生命一起刷新**（一处 `_hpLabel` 同步即可）。现在「事件结果」写着 189/354、顶栏还是 224/354，虽然不影响结算，但玩家最容易在此刻截图/判断要不要继续。
2. **N51：把玩家文案里的「M8」去掉**，换成「悬赏系统即将开放」。这是半个字的改动，却直接暴露"开发中"的痕迹。
3. **N52：Lv0 的设施按钮统一带门槛并置灰**（铁匠铺「重铸 / 分解」照训练场写成「需铁匠铺 Lv1」），并让"设施未建造"的判定优先于"先选一件装备"，避免新玩家在空档里点出一个与门槛无关的提示。

另附一条玩法观察（不是 M5 缺陷）：这批怪的远程「矿道幽魂」会拉开距离，站桩普攻会被磨死——本轮第一次接上开发者的旧局战斗时就这样真实阵亡（结算正常，材料/装备规则符合描述）。近战需要追着远程跑，建议后续在战斗教学或怪物分布上给一点提示，否则新手容易把"打不到"误读成"按钮没反应"。
