## 3. 复核中自查踩的坑（坐标 / 探针 / 状态）

1. **`browser_run_code_unsafe` 不能读文件系统**：`require` / 动态 `import('node:fs')` 均报错
   （`ReferenceError` / `ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING`）。改用
   `browser_evaluate` 的 `filename` 落盘，再用 shell `mv` 搬到 job tmp。
2. **`browser_evaluate` 的 `filename` 只能写允许根目录**（工程目录和 `.playwright-mcp`）；
   写 `$CLAUDE_JOB_DIR` 会被拒（"File access denied: outside allowed roots"）。
3. **懒初始化导致探针先返回 null**：成长页根节点在第一次 `open()` 前并不存在，
   直接按路径找会拿到 null。必须先真实点击打开面板，再注入探针。
4. **同坐标不同面板复用**：「返回」在成长页与装备页处于同一坐标，
   按坐标找节点必须用 `activeInHierarchy` 过滤，否则会抓到隐藏的那一个（开发者记录里同样踩过）。
5. **任务前提与实际存档不符**：任务描述假设点精英节点会弹「耗尽」确认卡，但本存档
   `exp.pos === 3` 正是该精英本身，而代码在 `node.id === exp.pos` 时**不进入确认分支**；
   于是改走「宝箱 6 → 副本 9」到达副本确认卡，同样覆盖到了耗尽分支。
   这不是缺陷，是前提与存档状态的偏差（详见 §4）。
6. **页面 reload 会清掉页内探针**，且恢复存档必须用 `page.addInitScript` 在 reload **之前**
   写入，否则卸载时 `_persist()` 会把当前状态盖回去。
7. `k` 标定：本轮用注入的 `pointerdown`/`mousedown` 监听实测 **k = 1**，与 dpr 一致；
   但按手册要求仍是现场标定而非假设。

## 5. 顺带发现的新问题（不编号，编号由主会话从全局台账取）

### P3 · 首领三行 Label 包围盒相邻重叠 ≈3.2 design px

- 位置：`MithrilWildMap.ts` 节点文本，首领行三行 y = −44 / −66 / −95。
- 量测：节点名与副标的 Label 框高约 25.2 design px（fs 16 + 行距），中心距仅 22 design px
  → 包围盒重叠 ≈3.2 design px。当前**字形 ink 未相碰**，截图 `r33v-12` 无叠字。
- 风险：桌面预览用系统字体，微信端字体度量不同（参见 `docs/tech/wechat-text-rendering.md`），
  行距偏紧可能在大字号 / 不同 DPI 下压字。建议把名/副标中心距拉到 ≥26（如 −44 / −70），
  或显式设 `lineHeight` 并收窄 Label 高度。
- 影响面：仅首领/精英节点三行排版；不阻塞本轮验收。

### 观察（非缺陷，供下一拍参考）

- `_hint` 提示行（y −308）与首领槽数行（y −95）之间留白充足，但**提示行 fs 16 为长句**，
  在 393 CSS 宽下接近满宽；若后续再加字需重新量宽（本轮未见截断）。
- N161 洗点按钮 260×52 与页脚 fs 15 的层级清楚，但页脚 fs 15 低于本轮统一的 16 下限，
  属声明内的既定值，未按缺陷记。
