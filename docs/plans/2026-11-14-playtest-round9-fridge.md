## 1. 方法与本轮的关键修正（坐标换算）

- 预览 `http://127.0.0.1:7456/`，浏览器视口 390×844。游戏画布被**信箱化**（letterbox）成
  393×796，顶部留 48px 黑边 —— 这正是上一轮「点 y 要 +52」的真相。
- **本轮标定出的正确换算（设计坐标 → CSS 坐标）**：

  ```text
  clientX = -1.5  + uiX × 0.5458
  clientY = 96.7  + (1280 − uiY) × 0.5458      # 0.5458 = 393 / 720
  ```

  标定方法：在 Canvas 节点上挂 `TOUCH_START` 捕获监听，读 `ev.getUILocation()` 反解。
  实测两组采样：client(100,400) → ui(186, 723.7)；client(195,700) → ui(360, 174.0)，
  斜率 1.8316 设计单位/CSS 像素（≈ 720/393），与公式一致。
  **不要用 `getBoundingClientRect()` 的 top 直接代入 1280 高度**，那会把点击整体抬高约 40–70px，
  落到空处后触发「点空白 → 开菜单」，表现为「点了没反应 / 菜单乱弹」。
- 操作仍全部走游戏自身输入路径：移动用页面内维护键盘 handler 同源的 `_keys` 集合，
  面板选择调用的就是按钮绑定的同一个方法（`onTreasurePick / onShopBuy / onAltarTake /
  onCorePick / onTreasureReroll`），炸弹与技能走 `useBomb()` / `useActive()`。
  **没有**改金币、血量、道具、核心、地图或怪物；状态一律用页内探针读回
  （`_core` 的 `phase/floor/roomId/kills/time/coins/items/stairs/secretOpened`、
  房间对象的 `cleared/doors`、`localStorage`），不只看截图。
- 本轮**没有修改任何 `.ts` / 场景 / 预制体**；自动化脚本在 `.playwright-mcp/`（gitignored）。

## 4. 本轮新增问题（均为 P3）

### N34（P3）满血时点「半心」商品，提示「金币不够」

- 复现：满血（hp == maxHp）进商店，点第一格的心。
- 现象：价格与卡片都已置灰，但**点击仍会透传**到购买逻辑，弹出 `金币不够`。
  玩家会以为自己缺钱，实际是满血买不了。
- 定位：`FridgeHud.ts:626 onShopCardTouch` 无条件调 `onShopBuy(idx)`，没有 `canBuy` 守卫；
  `FridgeGame.ts onShopBuy` 的失败分支只区分「已售罄」和「金币不够」，没有「生命已满」。
- 建议：HUD 在 `!canBuy` 时直接 return（满血/买不起都别弹误导文案），或 `buyShop` 返回
  失败原因枚举，让 toast 精确到「生命已满」。

### N35（P3）旧档是普通局时，开每日挑战也提示「已重新开始今日挑战」

- 复现：打一局普通模式 → 不做选择直接回大厅菜单 → 开「每日挑战」。
- 现象：toast「已重新开始今日挑战（上一局进度作废）」—— 作废的其实是一局普通局的档。
- 定位：`FridgeGame.ts startNewRun` 的 `const hadSave = !!loadRun()` 只看「有没有档」，
  不区分旧档模式。
- 建议：改成 `const old = loadRun(); const hadSave = !!old && old.mode === 'daily'`，
  普通档被覆盖时另给一句「普通局进度已丢弃」。

## 5. 好点子（设计建议）

按「构筑透明度 → 节奏与容错 → 元进度」排序，都是本轮实际玩下来最想要的东西。

1. **拾取时的协同预览（最想要的一条）**。宝箱/商店里在道具旁显示
   「点亮：冷热交替 / 熄灭：糖渣」的小字。现在玩家只能看标签颜色自己脑补，
   构筑乐趣被藏起来了。「图鉴升级」已经有组合数据，直接复用即可。
2. **楼层进度提示**。HUD 上加一句「本层剩余 2 间」或一枚迷你楼层图（已访问/未开）。
   四层结构里最容易挫败的时刻就是「不知道还差哪一间」。
3. **Boss 预警一屏**。进入 Boss 相邻房间时提示「前方：压缩机（460 HP）」，
   给玩家在商店花钱、换核心、调路线的机会，而不是推门即开打。
4. **满血的心给出路**（呼应 N34）。要么改成「+1 心上限，每层限 1 次」，
   要么干脆不在满血时上架；最差也要把 toast 改对。
5. **把炸弹的探索用途说出来**。炸弹能炸秘密墙这件事，玩家几乎不可能自己发现。
   炸弹按钮的长按说明里加一句「可炸开可疑的墙」，或在秘密墙相邻时给一点裂纹/音效暗示。
6. **死亡复盘面板**。结算只有分数、冰箱贴和「再来一局」；加上
   「死于第 2 层 · 商店旁战斗房」和「本局点亮：毒雾爆燃」，
   玩家下一局才有明确目标，而不是只记得自己死了。
7. **每日挑战的分享卡片**。每日种子已经固定了，只差一个出口：
   通关/阵亡后生成「种子 + 角色 + 得分」的分享文本（成语猜猜已有同款套路），
   好友可以复现同一张图 —— 这是零成本的社交钩子。
8. **热度模式说明前置**。解锁文案只写「带上 3 个诅咒开局，冰箱贴 +50%」，
   但 `HEAT_CURSES` 里三条诅咒的文案是现成的；在菜单里直接列出来，
   不然 60 贴的解锁容易被当成纯惩罚而劝退。

（另：电梯只写了「可以直接从第 2 层开始」，建议在电梯里顺带显示第 2 层 Boss 与推荐核心，
把跳层从「盲选」变成「备战」。冰箱贴目前 218 枚、已解锁 7/15 个节点，长尾还够，
但满解锁后仍需一个消耗出口。）
