## 二、发现的问题（待统一修复）

### 问题 1（中）：Boss 单位被重复登记，Boss 战出现两个「战争领主」

- **现象**：Boss 战敌人列表为 `[战争领主(20), 战争领主(20), 剑兵(6), 弩手(4)]`，四个条目；而设计上 Boss 战应为「1 boss + 2 杂兵」共 3 个敌人。
- **证据**：进入 Boss 节点后读取 `battleManager.enemyUnits`，得到上述 4 项，其中「战争领主」出现两次且血量相同。
- **根因**：`assets/games/game_tiny_vanguard/scripts/battle/BattleManager.ts:126-129`
  ```ts
  const bossUnit = this.spawnEnemy(BOSS_CONFIG as EnemyConfig, { row: 5, col: 3 });
  if (bossUnit) {
    this._enemyUnits.push(bossUnit);   // ← spawnEnemy 内部已 push，此处重复登记
  }
  ```
  `spawnEnemy()` 末尾本身就有 `this._enemyUnits.push(unitCtrl)` 并 `return unitCtrl`，调用方又 push 一次，导致**同一个 UnitController 引用在数组中出现两次**。
- **影响**：
  - 敌方 AI 回合可能让 Boss 行动两次；
  - 战斗结束判定、伤害统计、UI 列表等都以重复条目参与；
  - 与设计的 Boss 战配置不符。
- **建议**：删除 `if (bossUnit) { this._enemyUnits.push(bossUnit); }`（`spawnEnemy` 已负责登记）。

### 问题 2（中）：升级三选一的卡池未排除该单位**已学**技能

- **现象**：弓箭手在第一次升级选了「鹰眼」，第二次升级选项中**再次出现「鹰眼」**，再次选择后技能栏出现重复项。
- **证据**：升级完成后读取单位技能，得到 `["precise_shot", "eagle_eye", "eagle_eye"]`。
- **根因**：`assets/games/game_tiny_vanguard/scripts/TinyVanguardMain.ts:646`
  ```ts
  const skills = getRandomSkillsFromPool(classConfig.skillPool, 3);   // 未过滤该单位已拥有的技能
  ```
  `getRandomSkillsFromPool` 只是「洗牌后取前 N 个」，不感知单位已有技能。
- **影响**：升级机会被已学技能占用，玩家拿到重复技能（弱化成长）；重复视觉污染技能栏。
- **建议**：生成选项时按 `unit.data.skills` 过滤 `skillPool`；池内不足时再回退到「属性增益」类选项。

### 问题 3（中）：`addSkill()` 无去重，且技能满 3 个时**静默丢弃最后一个**

- **现象**：与问题 2 叠加，表现为技能栏出现重复项；玩家选择「学技能」有时看不出任何变化。
- **根因**：`assets/games/game_tiny_vanguard/scripts/battle/UnitController.ts:364-374`
  ```ts
  addSkill(skill: SkillConfig): void {
    if (!this._data) return;
    if (this._data.skills.length >= 3) {
      this._data.skills.pop();      // ← 静默挤掉最后一个技能，无任何提示
    }
    this._data.skills.push(skill);  // ← 不检查是否已拥有该技能
  }
  ```
- **影响**：
  - 同一技能可重复学习；
  - 技能达到上限后，新技能会**悄悄替换**掉已有技能，玩家在 UI 上看不到「被替换了什么」；
  - 与事件「花金币买随机技能」叠加时更明显（可能买到一个已学技能，金币白花）。
- **建议**：`addSkill` 增加「已拥有则跳过」；技能满时的替换/拒绝策略要么给玩家选择，要么明确提示。

### 问题 4（低）：事件选项没有金币校验，金币不足仍可点「花10金币」

- **现象**：金币只有 2 时，事件「流浪商人」仍显示可点击的「花10金币买随机技能」；点击后金币变为 0（被钳制），技能效果随机。
- **证据**：`gold=2` 时点击该选项，随后 `gold=0`，且三个单位技能列表无新增（随机到的技能被 `addSkill` 逻辑吸收或加了已学技能）。
- **根因**：
  - `TinyVanguardMain.ts:848-850` `spend_gold` 用 `Math.max(0, gold - amount)` 钳制，不做「余额不足则拒绝」；
  - `ui/EventUI.ts` 生成选项时**不校验**前置条件的金币是否足够（对比：商店的 `onShopBuySkill` 有 `if (this._runData.gold < 10) return;` 守卫）。
- **影响**：玩家用不足的金币"买"到随机技能（或什么都没得到），规则不透明。
- **建议**：事件选项若含 `spend_gold` 且余额不足，应禁用该选项（置灰）或点击时给出提示。

## 三、验收过程中的**误报**（已排除，勿计入修复）

本轮有两处曾疑似缺陷，经查证均为**我的探针/坐标问题**，如实记录以免污染修复清单：

1. **「Boss 节点（Node_9）点不到」——不成立。**
   真实点击多次未进入 Boss，但程序化 `emit('touch-end')` 正常，且 `hitTest` 对 Node_0 / Node_8 / Node_9 均返回 `true`。
   真因：**canvas 的 `getBoundingClientRect().height` 在本会话中由 654 变为 677**（视口变化），我沿用了过期的坐标 `(298,853)`，实际按钮已移到 `(298,880)`。改用当前坐标后**真实点击成功进入 Boss**。
   → 与游戏无关；已确认事件绑定与可达性判断都正常（`isReachable(9) === true`）。

2. **「事件标题/描述读到 null」——不成立。**
   是我第一版探针写法差异（节点自身带 `Label`），换用 `getComponent('Label')` 后读到「流浪商人 / 一个神秘的商人向你走来。」，显示正常。
