## 一、方法（以及本轮新踩的三个坑）

### 1.1 流程

1. 用 `cc.director.loadScene('<SceneName>')` 逐个切换 25 个场景，每个截图留证；
2. 探针遍历 `activeInHierarchy` 的节点，读 `cc.Label` 文案 / 字号 / 颜色 / 世界坐标、
   `cc.Button` 与 `cc.UITransform` 尺寸；
3. 需要交互的用真实鼠标点击（坐标由 `camera.worldToScreen()` 反算），点击后读运行时状态确认；
4. 每轮结尾读控制台。

### 1.2 坑 1：预览页的触摸通道会「变哑」，**重启页面才恢复**

某次排查 2048「设置」按钮时，`page.mouse.click` 连点三次都没反应，
探针显示**没有任何节点收到 `TOUCH_START` / `TOUCH_END`**，
合成 `TouchEvent` 被忽略，`MouseEvent` 只在 `Canvas` 上留下 mouse-down / mouse-up。

`page.reload()` 之后用同一套坐标点同一个按钮，**一次就命中**（`hits: ["start","end"]`，设置面板打开）。

> 判据：点击后如果所有节点都没收到 TOUCH 事件，**先 reload 再判定按钮是不是坏的**。
> 否则会稳定误报出"按钮点了没反应"。

### 1.3 坑 2：坐标必须用相机反算，且要做 canvas 的 CSS / 后备缓冲高比换算

本轮实测的 canvas 几何（视口 390×844）：

| 量 | 值 |
|---|---|
| CSS 矩形 | `left=-1.5, top=48, width=393, height=796` |
| 后备缓冲 | `canvas.width=393, canvas.height=796` |
| 设计分辨率 | 720 × 1280 |
| `cc.view.getScaleX()` | ≈ 0.5305 |

可复用的换算（本轮全部命中）：

```js
const scr = camera.worldToScreen(new cc.Vec3(worldX, worldY, 0));
const cssX = rect.left + scr.x;
const cssY = rect.top + (cvs.height - scr.y) * (rect.height / cvs.height);
```

注意 `cssY` 那一步的比例因子**不能省**：拉高视口后 CSS 高与后备缓冲高会不一致，
直接用 `rect.top + (designH - y) * scale` 会整列偏移，表现就是"点了没反应"。

### 1.4 坑 3：想验「新手第一次打开」，清存档要**整页 reload**

只 `localStorage.clear()` + `loadScene('Tetris')` 不够：旧场景实例在销毁前
把内存里的 `games_played=17` 又写了回去，提示条依旧按"老玩家"隐藏。
**整页 reload** 后同一场景立刻变成新手态（引导面板弹出、提示条三行全在）。

### 1.5 坑 4：探针要按 `activeInHierarchy` 过滤

未激活节点同样能读到 Label / UITransform，直接数会把隐藏内容算进来
（第三轮在大厅搜索上已经踩过一次，本轮在提示条上又遇到一次）。

## 四、本轮新发现（全部 P2）

### P2-1　7 款游戏的背景装饰圆读起来像「渲染污渍」，且左上那枚压在返回按钮下方

症状：成语填字 / 扫雷 / 缤纷消除 / 五子棋 / 小店日记 / 猜成语 / 数独 首屏左上都有一团
边界模糊的深色大圆，颜色和背景只差一点点，形状又不完整——第一眼像贴图没加载好。

定位（代码即设计，属程序化装饰 `Glow` 节点）：

| 游戏 | 位置 |
|---|---|
| 数独 | `SudokuGame.ts:217-227`（`glow.circle(-230, 320, 320)` / `(300, -400, 380)`） |
| 成语填字 | `IdiomGame.ts:292, 295` |
| 扫雷 | `MinesweeperGame.ts:310, 313` |
| 缤纷消除 | `Match3Game.ts:372` |
| 五子棋 | `GomokuGame.ts:394, 397` |
| 小店日记 | `IdleGame.ts:276` |
| 猜成语 | `WordleGame.ts:583` |

验证方式：按 `Canvas/GameRoot/Glow` 取到节点并 `active=false` → 圆立刻消失（`cc.find` 的路径写法不行，必须逐级 `getChildByName`）。

建议（不必全改）：① 左上那枚整体下移/右移，避开返回按钮的视觉重量区；
② 半径再大 20–30% 并把透明度再降一档，让它读成"光晕"而不是"脏块"；
③ 或统一改成右上/右下，左上留干净。

### P2-2　星际弹幕开始/结束遮罩把返回按钮压到近乎不可见

`ShmupGame.ts:413-422` 的 `StartOverlay` 是 **720×1280 全屏**遮罩，`fillColor = hex('#050A14', 226)`（89% 不透明），
且作为 `GameRoot` 的**后置兄弟节点**创建（探针：`GameRoot/Button/__backChevron` 在前，`GameRoot/StartOverlay` 在后），
于是返回按钮被整块压暗。

点击仍可达（实测点 (31,146) 回到大厅），纯视觉问题。

建议：`overlay.setSiblingIndex(0)`（画在按钮之下），或把遮罩矩形缩到顶栏以下，或在遮罩之上补画一枚亮色返回按钮。

### P2-3　猜成语开局 6×4 空盘格几乎看不见

- 空格填充 `COLOR.SLOT_EMPTY_BG = #141A24`（`UITheme.ts:60`），场景底色 `BG_SCENE = #0B1220`（`:24`）；
- 边框 `SLOT_EMPTY_BORDER = #2A3342`（`:62`），2px（`WordleGame.ts:803-804, 895`）。

两者对底色都只差几级明度，截图上棋盘"消失"，新手第一眼不知道从哪开始。

建议：空盘格边框改用 `PANEL_BORDER = #3A4658`（或给空格加极淡的内阴影），保持"空"但边界可见。

### P2-4　战争进化的返回按钮是深色 Sprite，没走统一皮肤

`WarEvo.ts:60` 的 `backButton` 节点（`Canvas/UI_Overlay/topBar/backButton`）尺寸仅 **60×50**，
组件是 `UITransform + Sprite + Button`，**没有挂 `BackButton`**。
全站其他游戏在 `BackButton.ts:44-56` 里会被统一换成"深蓝圆盘 + 白色 ‹"，这一款保留了旧的暗色贴图，
在深色战场背景下几乎看不出边界。

功能正常（实测点 (31,146) → 大厅）。

建议：给该节点挂 `BackButton` 组件（它会把节点内的 Label 隐藏、把 Sprite 关掉再画圆盘）；
若担心 60×50 太小球盘太小，先把节点调到 84×84 再挂。

### P2-5　泡泡龙「危险线 · 泡泡越线即失败」离虚线只有 5 设计像素，且字号仅 13

`BubbleGame.ts:259-264`：标签中心 `DANGER_DESIGN_Y - 16`、高 22 → 上沿在虚线下方 5 设计像素，
0.53 缩放下约 2.6 CSS 像素，视觉上文字直接贴着红线；字号 `FONT_TINY = 13`（探针读数 y=464, fs=13），
是全屏最小的一行却要承担"规则说明"。

对比：合合的同类说明留了 12 设计像素（`MergeGame.ts:695`），可读性明显更好。

建议：`- 16` → `- 24`，或把该说明改到板的右侧竖排；有条件的话把字号提到 16。

### P2-6　2048 仍在用已弃用的 `systemEvent`（也是本轮两条 warning 的来源）

`InputHandler.ts:1,29,35`：`systemEvent.on(SystemEvent.EventType.KEY_DOWN, ...)`。
引擎 3.4 起改用 `input.on(Input.EventType.KEY_DOWN, ...)`。
功能正常（键盘方向键可用），但每次进 2048 都会往控制台打两条弃用告警，
后续引擎大版本可能直接移除。

建议：换成 `input` / `Input`，与其它游戏保持一致。

## 五、撤回两处前几轮的误报

### 5.1「方块坠落底部手势提示不显示」——是设计行为，不是缺陷

`HintBar.ts:11-13, 100` 写明：**三个手势都学会、或累计玩满 3 局就整体隐藏**。
本轮存档 `tiny_games_tetris_games_played = 17`、`hint_used = button_notice,drop,move,rotate`，
因此 `rowsRoot.active=false` 是正确的。

清档 + 整页 reload 后复验（`localStorage.clear()` 会立刻被旧实例写回，必须 reload）：

- 新手首屏弹出「推荐：全屏手势」引导面板，5 条手势 + 「开始游戏」/「我习惯按键操作」，**完全可读**；
- `Canvas/HintBar` 的 `Row0/1/2` 三行均为 `active=true`，文案「拖动移动 / 轻点旋转 / 下拖加速」，
  世界坐标 y = 268 / 216 / 164，压在手势模式下棋盘的**下沿**上（`HintBar.ts:94-99` 注释已说明这是刻意取舍）。

结论：**新手能获得完整引导**，此前的"提示不可见"来自老存档。

### 5.2 多款游戏的「大圆污渍」——是程序化装饰，不是贴图损坏

见 P2-1。保留为视觉调优建议，不再是"渲染缺陷"。
