# 下一批游戏：纸牌接龙 / 吸血鬼幸存者 lite — 优先级与排期

- 日期：2026-11-01
- 范围：确定接下来两款新游戏的先后顺序、各自 MVP 边界与关键风险
- 关联：[纸牌接龙设计规格](../specs/2026-11-01-game-solitaire-design.md)
- 幸存者设计规格（评审稿）：[`2026-11-02-game-survivor-design.md`](../specs/2026-11-02-game-survivor-design.md)（4 武器 / 4 被动 / 3+2 槽、双重性能门槛）
- 结论：**先做纸牌接龙（P0），做完并微信真机验收通过后再启动吸血鬼幸存者 lite（P1）**。两者不并行。

---

## 1. 排序结论

| 顺位 | 游戏 | 代号 | 投入 | 耐玩来源 | 性能风险 | 美术成本 |
|------|------|------|------|----------|----------|----------|
| **P0** | 纸牌接龙 | `solitaire` | ~10.5 人日 | 规则组合空间 | 低 | 0 |
| P1 | 吸血鬼幸存者 lite | `survivor` | ~22–26 人日 | 构筑组合 + 随机构成 | **高** | 0（全形状） |

**一句话理由**：接龙是「确定性高、复用现有经验、能快速上线验证」的一步；幸存者是「上限更高、但会同时压性能、手感、内容三条线」的一步。先做前者，能顺带沉淀出后者需要的存档、设置、统计、对象池四项基础设施。

---

## 2. 为什么纸牌接龙排第一

### 2.1 补齐品类空缺

现有 8 款游戏的耐玩性只有两种来源：

| 来源 | 游戏 | 特点 |
|------|------|------|
| 操作/反应 + 程序随机 | 2048、贪吃蛇、方块坠落、合合大作战、数值冲刺 | 需要持续盯屏，中断即失败 |
| 关卡/词条内容量 | 小小先锋、砖块远征 | 靠持续产出内容续命 |

缺的是第三种：**规则本身深、不靠内容、可随时暂停**。接龙正好填这个位置，且和现有 8 款零重合。

### 2.2 投入产出比最高

- 零美术：`Graphics` + `Label` 即可，和 7/8 款现有游戏一致
- 约 1800 行，与 `砖块远征`(2032) 同级，低于 `方块坠落`(4720)
- 拖拽、点击、存档、设置面板这些基建，后面的幸存者直接复用

### 2.3 风险可控

接龙的所有规则都能写成纯函数并做 Node 侧自检（`tools/verify-solitaire-core.js`），能在不打开编辑器的前提下把规则层验证到位。这也是项目里已经验证过的模式（`verify-tetris-core.js`）。

---

## 3. 纸牌接龙：完成定义

完成定义 = 下列全部满足才算 P0 结束：

1. §8 的功能与交互验收项全部通过
2. 浏览器实测 10 个场景（发牌、抽 1、抽 3、重洗、整段移动、撤销、提示、自动移动、一键收牌、中断恢复）
3. 微信真机（iOS + Android 各一台）通过，`check-wechat-build.js` 9 项全绿
4. 大厅注册、构建场景清单同步、图标位占位可点
5. 无进行中对局时的冷启动 < 1.5s

**上线后再评估的 v2 项**（不阻塞 P0）：可赢局发牌、蜘蛛纸牌、空当接龙、每日挑战。

## 4. 吸血鬼幸存者 lite：MVP 边界

### 4.1 一句话玩法

单指摇杆移动，武器自动攻击，每 30 秒三选一升级，撑过 8 分钟击败 Boss。

### 4.2 v1 做 / 不做

| 做 | 不做 |
|----|------|
| 单指虚拟摇杆（复用贪吃蛇的摇杆实现） | 双摇杆、闪避、主动技能 |
| 3 把武器（飞刀 / 环绕 / 落雷） | 武器进化合成树 |
| 3 个被动（攻速 / 移速 / 拾取范围） | 局外养成、角色解锁 |
| 4 种敌人（直冲 / 绕行 / 远程 / 自爆）+ 1 个 Boss | 精英词缀、宝箱、事件房 |
| 8 分钟一局，每 30 秒升级 | 无尽模式、排行榜 |
| 经验宝石 + 吸附拾取 | 金币、商店、皮肤 |
| 全 `Graphics` 形状绘制 | 任何贴图 |

### 4.3 关键性能设计（决定项目成败）

这是项目里第一款「同屏几百个活动对象」的游戏，必须在 P0 之前就把架构定死：

| 项 | 方案 |
|----|------|
| 敌人上限 | 300（超出则复用最远的死亡槽位） |
| 绘制 | **一个 `Graphics` 画全部敌人/子弹/宝石**，不给每个对象建节点 |
| 空间查询 | 8×8 空间分桶，碰撞只查邻桶 |
| 对象池 | 敌人、子弹、宝石、飘字全部池化，零 `instantiate` |
| 时间步 | 固定 1/60 累加器，单帧最多追 3 步 |
| 逻辑与渲染分离 | `SurvivorCore.ts` 纯逻辑无 `cc` 依赖，可在 Node 侧跑 1 万帧压力测试 |
| 压力测试 | `tools/verify-survivor-core.js` 跑 300 敌人 × 600 帧，断言单帧纯逻辑 < 2ms |

**如果性能预算不成立，整个项目就要降级**（敌人上限砍到 150、同屏子弹减半），所以 M1 就要用 Node 压力测试验证，不能等画面做完再看帧率。

### 4.4 里程碑与预估

| 里程碑 | 内容 | 预估 |
|--------|------|------|
| M1 | `SurvivorCore`：移动、刷怪、碰撞、武器发射、经验结算 + 压力测试 | 4 人日 |
| M2 | 渲染层：批量 `Graphics`、相机跟随、对象池 | 3 人日 |
| M3 | 摇杆接入、升级三选一面板、暂停 | 3 人日 |
| M4 | 4 种敌人行为 + 波次节奏 + Boss | 4 人日 |
| M5 | 结算、存档、统计、设置 | 2 人日 |
| M6 | 手感打磨：受击、击退、飘字、屏幕震动、拾取吸附 | 3 人日 |
| M7 | 微信真机性能调优 + 构建验收 | 3 人日 |

合计 **22–26 人日**，是接龙的 2–2.5 倍。其中 M7 的变数最大：中低端安卓机的同屏绘制是硬瓶颈。

### 4.5 风险

| 风险 | 等级 | 对策 |
|------|------|------|
| 中低端安卓掉帧 | 高 | M1 就做纯逻辑压测；绘制合并为单 `Graphics`；提供「低特效」开关 |
| 升级选择没有构筑感 | 高 | 3 武器 × 3 被动先跑通，靠数值曲线而非数量制造 build 差异 |
| 8 分钟一局太长，微信场景留不住 | 中 | 先做 5 分钟版本验证留存，再决定是否加长 |
| 手感（受击、击退、拾取）打磨吃掉大量时间 | 中 | M6 单独留 3 人日，不塞进 M4 |

## 5. 共享技术资产

接龙阶段就会产出、幸存者可直接复用的东西：

| 资产 | 接龙里的用途 | 幸存者里的用途 |
|------|--------------|----------------|
| `StorageManager` 存档模式 | 当前局存档 + 统计 | 局外统计、设置 |
| 设置 / 统计面板 | 抽牌模式、自动收 A | 音效、震动、低特效 |
| 节点池化写法 | 52 张卡牌复用 | 敌人、子弹、宝石、飘字 |
| 纯逻辑 core + Node 自检脚本 | 规则层回归 | 战斗层压测 |
| 暂停 / 恢复 / 后台事件 | 切后台存盘 | 切后台暂停计时 |

**建议**：接龙的 `SettingsPanel` 与 `StatsPanel` 按「可复制到别的游戏」的标准写，不要为了省事把逻辑焊死在 `SolitaireGame` 里。

## 6. 排期建议

```
第 1 阶段（P0，约 2 周）
  接龙 M1 → M8 → 微信真机验收 → 上线

第 2 阶段（P1，约 5 周）
  幸存者 M1 压测（Go / No-Go 决策点）
    ├─ 通过 → M2 → … → M7
    └─ 不通过 → 降级到 150 敌人重做 M1，或改做轻量替代（如「塔防 lite」）

第 3 阶段
  根据上线数据决定：接龙 v2（可赢局/蜘蛛）或幸存者内容扩展
```

**Go / No-Go 判据**（幸存者 M1 结束时）：300 敌人 × 600 帧，纯逻辑单帧 < 2ms，且单 `Graphics` 批量绘制在目标机型上 ≥ 50 FPS。任一不满足，先降规模再继续。

---

## 7. 明确不做的事

- 两款游戏不并行开发——幸存者的性能问题会污染接龙的上线节奏
- 接龙 v1 不做可赢局发牌、不做皮肤、不做排行榜
- 幸存者 v1 不做局外养成——先把「一局 8 分钟好不好玩」验证掉
