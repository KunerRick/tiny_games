|---|----|------|------|
| F1 | 发牌 | 新局：`tableau` 长度 `[1,2,3,4,5,6,7]`、背面数 `[0,1,2,3,4,5,6]`、`stock=24`、全场 52 张无重复 | ✅ |

| F6 | 收牌 | 牌拖到收牌区：分数 +10；同一操作里来源列翻正再 +5。收牌区拒收错误点数（自检覆盖 A→K 顺序与单张） | ✅ |
| F7 | 翻牌 | 移动后来源列新底牌自动翻正且分数 +5 | ✅ |
| F8 | 撤销 | 浏览器内连续撤销 25 步，`stateHash` 与发牌后完全一致（分数/步数/翻面同步）；自检另跑「连续 50 步撤销回到初始」与「上限 50」 | ✅ |

| F10 | 自动移动 | 点击列顶/废牌顶：优先收牌区、其次合法列，落点与规格一致；**无处可去时顶牌横向抖动**（±6 设计像素、三个来回、回到原位），状态与分数均不变 | ✅ |
| F11 | 一键收牌 | 条件不满足时不出现；满足时按钮出现，点击后逐张入收牌区并进入 `won` | ✅ |
| F12 | 存档 | 存档 → 重载预览 → 大厅 → 重新进入：`stateHash` 与离开前一致，分数/计时/统计同源恢复（核心层另有序列化 round-trip 与坏数据回退新局的自检） | ✅ |

> 会连开两局、`played` 加 2 —— 与实现里的确认窗口条件一致。

## 7. 本轮新增

1. **重洗上限**（回应「抽牌可以无限抽」）：`MAX_RECYCLES = 3`，两种抽牌模式共用；`SolitaireCore.canDraw/canRecycle/recyclesLeft` 统一判定，
   用尽后点击牌堆不产生状态变化、只弹提示；顶栏运行时追加「重洗 N/3」常驻显示。自检 +3 项（共 89）。
2. **提示真正可用**（回应「提示无效」）：高亮改为呼吸脉动 + **浮层中文说明**（「把 梅花3 拖到 红桃4 上」），
   并把提示语从顶栏 `ModeLabel` 挪到牌区底部的独立提示条 —— 原先挤在「?」按钮底下，长句直接被压住看不见。
3. **新手引导**（回应「新手不知道怎么玩」）：首次进入弹「怎么玩」面板（目标 / 落牌规则 / 重洗上限 / 三种操作），
   一次即记住，顶栏「?」随时重看；面板打开时暂停计时并吞掉牌面触摸。
4. **发牌即结算自动收 A**：`_startNewGame()` 发牌后立刻 `sendAces()` 并刷新 HUD，修掉「分数标签 0、实际已 15」的错位。
5. **F10 抖动反馈**：`SolitaireCard.shake()`（±6 设计像素、0.18 s、结束必然回原位），
   在 `_finishTouch` 的失败分支与 `_doTap` 的无处可去分支调用；`moveTo/placeAt` 会先停掉抖动补间，
   `onDestroy()` 只清引用。实测抖动期间 `stateHash`、分数、步数均不变。
6. **预检脚本第 1b 项**：拦住「文件齐全但一个场景都没打进去」的空构建（详见 §5）。
   同步更新了 `AGENTS.md` 与 `docs/tech/wechat-build-pitfalls.md` 的检查项说明。
