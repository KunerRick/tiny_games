# 全站 24 款小游戏「玩家视角」试玩与优化报告

> 日期：2026-11-10
> 试玩环境：Cocos Creator 3.8.8 编辑器预览（`http://127.0.0.1:7456/`），浏览器视口 432×730，模拟 iPhone 14 Pro 竖屏
> 试玩方式：**只从大厅点进去玩，不读任何游戏脚本逻辑**；界面上的文案/数值全部通过读取运行中场景的 `Label` 文本与截图获得

---

## 0. 这份报告是什么

我以一个「刚下载这个 App 的普通玩家」的身份，把大厅里的 24 款游戏**逐个进、逐个点、尽量各打一局**（死亡/失败/过关都走一遍），记录三件事：

1. **界面布局** —— 该看的东西在第一眼是否看得见、看得清、摆得对
2. **交互** —— 手指下去有没有反应、反应是否符合直觉、卡住时有没有提示
3. **可玩性** —— 前 30 秒能不能上手、失败后知不知道为什么、有没有继续玩的理由

**约束**：全程不读代码，所以下面写的都是"玩家看到的现象"。个别现象背后可能有合理的设计原因，如果你确认是设计意图，直接划掉即可；但如果玩家看不出来，那它就是需要修的表达问题。

本文档不替代各游戏的 `specs/` 设计文档，只提供一份**横切的、按严重度排序的体验问题清单**。

## 2. 跨游戏的共性问题（优先按这批改，收益最高）

这 7 类问题几乎每款游戏都出现过，改一次能同时改善十几款。

### 2.1 返回大厅的入口不一致，且有 2 款根本没有

- **现象**：大厅 → 游戏没问题；回来时，多数游戏靠左上角一个**约 28px 的圆形「‹」**，尺寸偏小、位置贴边。
- **反例**：战争进化（`backButton` 未激活，完全出不去）、小小先锋地图页（无返回入口）、星际弹幕战斗中（无暂停、无退出，只能等被击落）。
- **建议**：
  - 统一成 `BackButton` 组件 + 固定 44×44 设计像素的可点区域（视觉 28px 可以保留，热区要放大）。
  - 战前/战斗中这类"半途"页面，统一提供「暂停 / 退出」二级入口，而不是要求玩家打完或死掉。
  - 加一个自动化自检：`tools/check-back-buttons.js`，遍历所有场景断言存在 `activeInHierarchy === true` 的返回节点。

### 2.2 HUD 的"数字没有单位/没有标签"

玩家看到的常见写法：

| 现状 | 玩家会怎么理解 | 建议 |
|---|---|---|
| `能量 105` | 什么能量？ | `金币 105` |
| `等级 1 / 行 0`（方块坠落） | 行是什么？ | `等级 1 · 消行 0` |
| `第 1 关·剩 21`（砖块远征） | 剩什么？ | `第 1 关 · 剩余砖块 21` |
| 雷霆战机关卡页右上角：金币图标 + 裸数字 `3` | 3 是什么？ | `金币 3` |
| 台球 `杆数 0/26` | 是"已用 0 杆 / 上限 26"还是"剩余"？ | `杆数 0 / 26` + 副标"上限 26" |
| 守卫塔楼 `生命 4` | 上限是多少？ | `生命 4 / 10` |
| 星际弹幕顶部那条蓝色进度条 | 完全不知道是什么 | 加标签"本波剩余 3/8"或去掉 |

**建议**：为 HUD 数值定一条规则——**凡是数字，前面必须有名词，有上限的必须有分母**。这条可以用 `docs/design/` 下的美术规范一起约定。

### 2.3 失败/死亡后不告诉玩家「为什么」

- **贪吃蛇**：撞了什么死的？没有提示。
- **守卫塔楼**：「防线失守」很到位，但没写"本波漏 8 只"。
- **数值冲刺**：全军覆没，但没写"被盾兵挡住"。
- **星际弹幕 / 雷霆战机**：被击落/任务失败，但没写"被第几波什么弹打中"。

**建议**：所有失败面板增加一行 `原因` 字段（撞墙 / 漏怪 8 只 / Boss 第二阶段弹幕），一行字成本极低，玩家感受差别巨大。这也是"再来一局"率的关键变量。

### 2.4 大面积无效留白（竖屏利用率低）

按屏幕高度粗算：

| 游戏 | 内容区占比 | 空在哪 |
|---|---|---|
| 纸牌接龙 | **~30%** | 牌桌以上，其余全是背景 |
| 台球 | **~44%** | 球桌以下全是按钮和空白 |
| 泡泡龙 | ~60% | 盘面下半部分，只有一条无说明的红虚线 |
| 方块坠落（默认手势模式） | ~75% | 屏幕下方 160px |
| 推箱子 | ~50% | 大外框套小棋盘，四周全空 |
| 冰箱底下 | ~65% | 屏幕下半 250px 只有一行说明 |

**建议**：这是 720×1280 竖屏，**纵向是稀缺资源**。逐款做一次"把玩区域撑到 70%+"的布局复核；同时把按钮和说明收进安全区底部，而不是让它们独占下半屏。

### 2.5 关键信息的对比度/字号不足

- **五子棋**：棋盘格线太淡，深色背景上几乎看不清交叉点（15×15 格距约 20px）。
- **推箱子**：目标点暗黄细圈、墙与地板同色。
- **守卫塔楼**：射程指示是虚线，深色地图上几乎不可见。
- **数值冲刺**：操作提示字小到像乱码。
- **泡泡龙 / 台球**：力度条静止时与背景同色。
- **冰箱底下**：主菜单统计行约 10px。

**建议**：定一条**最小可读字号**（正文 ≥ 22 设计像素 ≈ 手机 11pt）和**最小对比度**（关键元素与背景 ≥ 3:1），并在 `docs/design/2026-11-10-ui-art-style-guide.md` 的令牌里固化。舍入到令牌而不是逐处手调。

### 2.6 操作引导只写在角落一行小字里

多款游戏的核心操作只靠底部一行灰字说明：

- 砖块远征：「拖动挡板 · 点击发射」——进入后球不动，玩家不知道要点一下屏幕才能发射。
- 泡泡龙：「在盘面上拖动瞄准，松手发射」——玩家第一反应是摸发射器，摸了没反应。
- 数值冲刺：「拖动选门 · 点屏幕集火」——字太小。
- 冰箱底下：左右半屏分别对应移动/射击，没有图解。

**建议**：**首次进入**（存一个 `seen_tutorial_{gameId}`）用一次性的浮层提示（手指图标 + 一个箭头），而不是常驻角标小字。这也是本项目已有的 `StorageManager` 就够用的事。

### 2.7 「禁用/不可用」状态没有解释

- **冰箱底下**：「图鉴」按钮是暗色的，点了完全没反应（0/40 未解锁）——玩家会以为卡了。
- **雷霆战机机库**：买不起时按钮变灰，点了会弹「金币不足」（✅ 做对了，可以作为标准范例）。
- **小小先锋**：队伍没放满时「确认部署」点不动，且没有任何提示。
- **2048 设置**：改网格直接重开，没有二次确认，会丢当前局。

**建议**：统一「不可用三件套」——**置灰 + 锁图标 + 一句原因**（"图鉴需收集 1 种道具后解锁"）。点击时给 toast，而不是静默吞掉。

## 3. 逐游戏记录与建议

> 标记：🔴 P0（影响能不能玩）/ 🟠 P1（影响好不好玩）/ 🟡 P2（打磨）

### 3.1 大厅 Lobby

- 三列网格、24 款、需滚 8 行左右；无分类 / 搜索 / 收藏 / 最近排序以外的组织方式。
- 图标风格统一（彩色圆角方块 + 简笔图形），但**同色系成对出现**（如两款青色、两款紫色），缩略图尺寸小，区分度一般。
- 进入游戏后返回按钮约 28px，偏小。

🟠 建议：
1. 顶部加「搜索 / 分类标签」（休闲 / 益智 / 动作 / 成长），24 款已经超过一屏的舒适浏览阈值。
2. 图标形状加大、避免同色相邻（`tools/check-game-icons.js` 目前只查"有没有登记"，可再加一条"相邻色相距离"的判据）。
3. 返回按钮热区放大到 44×44。

### 3.2 冰箱底下 Fridge

- 主菜单：继续上局（灰）、开始冒险·布丁（青）、今日已挑战（灰）、热度模式（青）、角色/图鉴/解锁树（暗）。
- 暗色按钮无锁图标、无原因说明；点「图鉴」无任何反应。
- 房间 1/8 是空房间，没有"已清空"提示，容易以为要打怪。
- 战斗中角色能走到右上角「螺旋冲刺」按钮底下被遮住。
- 死亡面板：「点击任意处返回主菜单」与「再来一局」按钮冲突（点后者实际回主菜单）。
- 死亡后回主菜单，`DeadDim` 遮罩仍保持 active。
- 主菜单统计行字号约 10px。

🔴 死亡面板的按钮语义必须修：「再来一局」应该真的重开一局，或改文案为「返回主菜单」。
🟠 角色与按钮的层级：技能按钮放到安全区、角色移动范围裁剪在按钮下方。
🟠 「图鉴」等未解锁入口加锁图标 + 解锁条件。

### 3.3 2048

- 布局干净；两个分数卡、4×4 棋盘、底部「新游戏」。
- 设置可调 4~8 网格（好评），但「开始」直接重开、无二次确认。
- 提示与底部按钮之间有大段空白；无撤销。

🟠 设置里「开始」前加确认；加一步「撤销」（这是 2048 玩家的强预期）。
🟡 棋盘可以再放大 10–15%，吃掉一部分下方空白。

### 3.4 方块坠落 Tetris

- 默认全屏手势（左右滑 / 下滑），暂停菜单可切「虚拟按键」。
- 手势模式下屏幕下方约 160px 空白，只有切到虚拟按键才填满。
- HUD「等级 1 / 行 0」中"行"含义不明。
- 两侧「暂存 / 下一个」字号偏小。
- 暂停菜单完成度很高（操作方式 / 震动 / 操作说明 / 继续 / 返回大厅）。

🟠 「行 0」→「消行 0」。
🟠 手势模式补一个半透明的虚拟键或手势示意区，别让下半屏空着。
🟡 暂存/下一个预览放大。

### 3.5 战争进化 WarEvo

- 顶栏双方血条仅约 4px 高；底部三张购买卡；战场大面积空白绿底、单位很小。
- **无可用返回大厅入口**（`backButton` 节点 `activeInHierarchy=false`）。
- 点「全军冲锋」后弹出巨大横幅盖住战场中心约 8 秒。
- 卡片文案挤（"购买经验 45g → 25经验 ×6"）。

🔴 恢复返回大厅入口。
🟠 血条加粗到 ≥ 10px 并加数值；冲锋横幅改成顶部一条 2 秒的飘带，不遮挡战场。
🟠 单位放大 20–30%，战场加地形/边界。

### 3.6 贪吃蛇 Snake

- 开始界面满屏彩色圆点（绿/橙/蓝），**没有图例**。
- 「滑动屏幕开始」居中，需要一次滑动才真正开始。
- 蛇身很小，场地无边界感。
- 死亡弹窗只有得分与最高分，**无死因**；HUD 用「得分」、弹窗用「本期得分」，措辞不一致。

🟠 开始页加图例（食物=绿点、敌人=橙点、加速=蓝点）。
🟠 死亡加一行死因（"撞到边界" / "撞到自己" / "被别的蛇撞上"）。
🟡 统一文案为「得分」。

### 3.7 小小先锋 TinyVanguard

- 组队页四张职业卡，属性数字很小；「继续上局」做成细长条，像进度条不像按钮。
- 地图页节点图两列，「已通关 0/7」，地图窄、两侧大片空白，**没有返回大厅入口**。
- 战斗页布阵提示「点击前两行部署单位」，实际可部署区是底部两行（"前两行"歧义）。
- **战斗回合无法推进**：点绿色格、换单位、拖拽都无反应，回合停在「回合 1」。
- 单位信息面板浮在棋盘左上角，与棋盘重叠。

🔴 战斗回合推进（移动/攻击）必须可用——这是本作的核心循环。
🔴 地图页补返回大厅。
🟠 「前两行」→「底部两行」。
🟠 「继续上局」改成正常按钮尺寸；单位信息面板挪到棋盘下方。

### 3.8 砖块远征 BrickBreaker

- 顶栏「得分 / 第1关·剩21 / 生命3 / 暂停」。
- 进入后球不动，需要点屏幕发射，但只有一行很小的「拖动挡板·点击发射」。
- 挡板区在中部偏下，下方约 150px 空黑。
- 砖块全部橙色，只有 + 号砖和紫砖有区别。

🟠 首局在球旁加「点一下发射」的手指提示。
🟠 「剩 21」→「剩余砖块 21」。
🟠 允许砖块按行/种类分色（现在整屏一片橙）。

### 3.9 合合大作战 Merge

- 布局清晰，容器中央虚线指示落点、顶部红色危险线，合成飘字 +60/+150 很好。
- 「水果」用多边形 + 表情绘制（六边形/菱形/水滴），主题对不上，更像宝石/糖果。
- 容器很高、前期大半屏空；危险线位置偏上，很难判断何时会溢出。

🟠 危险线旁加「再放 2 个就溢出」的提示或剩余高度条。
🟡 美术改为水果剪影（同一个 `Graphics` 成本，形状换掉即可）。

### 3.10 数值冲刺 GateRunner

- 顶栏「队伍人数 40」「203m · 40km/h」，门是绿色条，队伍是蓝色方块阵列，直观。
- **操作提示字号太小**，手机上看起来像乱码。
- 撞上盾兵（424 血）后 40 → 25 → 0 约 5 秒，而「点屏幕集火」这个唯一解法没有明显引导。

🔴 操作提示字号至少提到 30+ 设计像素，首局用浮层演示"点屏幕集火"。
🟠 盾兵出现前给一次「盾兵！快点屏幕集火」的警告条。

### 3.11 纸牌接龙 Solitaire

- 牌面干净，提示 / 撤销 / 新局 / 设置齐全。
- **牌桌只占屏幕上方约 30%**，下部大片空白，卡牌偏小，拖牌距离长。
- 进入时「时间 5:51」而「步数 0 / 分数 0」——计时器像是延续了上次会话。
- 设置文案不白话（「底牌 0/0 (0%)」「抽1：最差 — 最少一步」）。

🟠 牌桌撑满可用高度（这是本次所有游戏里屏效最差的一款）。
🔴 计时器在"新局/继续"时归零。
🟠 设置项改白话（「抽 1 张 / 抽 3 张」「是否允许无限重洗」）。

### 3.12 午夜幸存者 Survivor

- 直接进战斗，无开场说明；玩家是蓝色箭头、敌人红点圈、经验绿点。
- HUD 只有「生命 120/120」「Lv.1 / 击杀」，**没有经验条**。
- 升级卡面板优秀（分类标签 + 图标 + 数值 + 等级点）。
- 场景里残留一段调试文本节点（"FPS 60 步 1 渲染 0.00ms / Lv.1 HP 100/100 击杀 0 …"），当前未显示但仍在层级里且会被预览读取。

🟠 补经验条（玩家不知道离升级多远，直接影响 build 决策节奏）。
🟡 顶部加一个 10 行以内的开场提示（自动攻击 / 三选一 / 撑到 8 分钟）。
🟡 清掉调试节点。

### 3.13 扫雷 Minesweeper

- 界面干净，三档难度，数字配色清晰，首点安全 + 和弦齐全。
- 格子约 34px 偏小；「插旗模式：关」看起来像状态而不是按钮。

🟠 9×9 的格子可以再放大约 25%（屏效有富余）。
🟡 「插旗模式：关」改成一个明显的开关（带滑块或高亮态）。

### 3.14 数独 Sudoku

- 完成度最高的一款：难度三档、剩余个数、同区高亮、笔记/擦除/撤销/提示/新局齐全。
- 选中格与同区高亮颜色接近，层次可再拉开。
- 顶部提示「选一个空格开始」在开始填之后仍显示，不随状态更新。

🟡 选中格用更高亮（如青色描边）区分于同区淡蓝填充。
🟡 顶部提示随状态更新（"还差 12 个数字"）。

### 3.15 成语填字 Idiom

- 上手流程顺：点格子 → 「第 6 条 · 纵向 · 还差 3 字」+ 候选字（含 1 个干扰字）。
- 未选格子时候选区是空的，只有一行小字引导。
- 顶栏「用语 / 填错 / 失误 / 提示」四个指标的小字难分辨。

🟠 「用语 vs 失误」这两个词在中文里几乎同义 —— 改成「完成 / 错误 / 提示」等明确词汇。
🟡 未选格时在候选区放一行占位提示（"先点一个空格"）。

### 3.16 五子棋 Gomoku

- 人机/双人 + 三档难度 + 胜/负/平，结构完整，落子有红色「最后一手」。
- **棋盘格线太淡**，深色背景上几乎看不清交叉点；15×15 格距约 20px，容易点偏。
- 顶部胜/负/平三个小统计字号偏小。

🔴 格线加深（这是"看不清棋盘"，不是审美问题）。
🟠 落子点加吸附半径 + 触摸时高亮交叉点。

### 3.17 小店日记 Idle

- 界面清爽：金币 / 每秒与每次点击产出 / 四张升级卡 / 超大「点我赚钱 +1」。
- 升级卡显示「下一级」预览，比同类放置游戏友好。
- 等级用 5 个小圆点表示，偏小且无数值强调。

🟡 等级改成「Lv.3 / 5」数字 + 圆点。
🟡 加一个"离线收益结算"的弹窗（本作已有离线系统，但主界面看不出来）。

### 3.18 缤纷消除 Match3

- 目标 + 进度条 + 步数齐全；无效交换会提示且不扣步数（好）。
- 8 色高饱和 + 图形标记（星/圆/三角/菱形），色盲友好，但整体视觉非常花。
- 提示只高亮一块，不告诉你往哪个方向换。
- 「得分 0」夹在棋盘和按钮之间，位置尴尬。

🟠 降低配色饱和度/减少同时出现的颜色数到 5–6 种。
🟠 提示时加一个箭头直接指出交换方向。
🟡 「得分」移到顶栏，和步数并排。

### 3.19 守卫塔楼 TowerDefense

- 建造面板与升级面板做得极好（四塔带白话定位；升级面板给出伤害/射程/间隔与退款额）。
- **起始 180 金只够 1 座塔，而第 1 波 6 只、第 2 波 8 只怪**；只有一座塔时第 2 波必掉光生命（实测 10 → 0）。
- 射程指示是虚线，深色地图上几乎看不见。
- 建塔面板从底部弹起，遮住下半张地图。
- 塔身极小，四种塔只能靠颜色区分；无暂停；「1x」的含义只能靠猜。
- 失败面板完整但没写"本波漏 8 只"。

🔴 起始金币调到 260–300（够 2 座塔），或第 1 波只出 3 只怪，让第一波能"教会"玩家而不是"惩罚"玩家。
🟠 射程圈改成实心半透明填充 + 亮边。
🟠 建塔面板改成贴着所选塔位弹出的气泡，而不是从底部盖住半张地图。
🟠 失败面板加「本波漏 X 只」。
🟡 「1x」改成「倍速 1x」并可点击循环 1x/2x。

### 3.20 台球 Pool

- 瞄准/拉杆手感正确：虚线瞄准 + 木色球杆 + 力度条随拖动增长（45% 变橙），松手出杆。
- **球桌只占屏幕上方约 44%**，球直径约 8px；力度条静止时与背景同色。
- 进球只体现为「分数 +100 / 剩余球 -1」，没有飘字、没有音效。
- 两个换关按钮都叫「换关」；关卡名「双层进击」与实际单层桌面对不上。
- 未说明白球落袋、连击等规则。

🟠 球桌撑满中部（可放大 30%+）；进球加飘字 + 音效 + 一次轻微镜头反馈。
🟠 「◀ 换关 / 换关 ▶」→「上一关 / 下一关」。
🟡 首次进入用浮层说明违规处理与连击。

### 3.21 成语猜猜 Wordle

- 流程干净：点 4 字 → 提交 → 结算（含复制战绩、再来一局）。
- 随机对局下的三档难度在每日挑战下隐藏，**切换页签时网格整体上下跳**。
- **「连续 1 天」这行状态文字被「清除/换一局/提交」按钮行压住**（状态行 y≈450、按钮顶边 y≈454），文字被切掉一半。
- 同一行三个按钮高度不一致（提交 60、删除 52）。
- 猜测网格的 6 行之间画了竖线连接点，看起来像"填字竖列"而不是 6 次独立猜测。
- 每日挑战完成后「再来一局」仍然出现，与「今日已猜中·明天再来」冲突。

🔴 修状态行与按钮行的重叠（`Wordle.scene` 中把状态容器整体上移 ≥ 40 设计像素，或按钮行下移）。
🟠 去掉网格行之间的连接线，改成 6 条独立横槽。
🟠 统一三个按钮高度。
🟡 每日挑战已完成时把「再来一局」改成「去随机对局」。

### 3.22 泡泡龙 Bubble

- 瞄准虚线实时跟随、松手发射、剩余次数正确递减。
- **「第 1 关 / 共 30 关」被顶部泡泡压住**，只露出下半截。
- **从底部发射器按下拖动完全没反应**，必须从盘面按下（提示写了"在盘面上"，但玩家第一反应一定是摸发射器）。
- 盘面下半部分约 40% 永远空着；一条无说明的红虚线（危险线）。
- 「NEXT」标签与下一个泡泡在右下角、离当前泡泡很远；「得分 0」位置随意。
- 无暂停、无关卡目标；发射后偶尔残留一个空心白圈。

🔴 标题行与盘面重叠。
🔴 允许从发射器上也发起拖动（扩大手势监听节点到整个场地）。
🟠 红虚线加标注「危险线：泡泡越过即失败」。
🟠 NEXT 挪到发射器旁边；补关卡目标（如"清空所有泡泡"）。
🟡 排查残留空心白圈（疑似吸附后的指示未清理）。

### 3.23 推箱子 Sokoban

- 规则干净（第 1 关 1 步过关、结算、撤销正确、滑动也能推）。
- **墙壁与地板同色**，玩家不知道哪里是墙，规划无从谈起。
- **目标点是暗黄空心细圈**，第 2 关在角落几乎看不见。
- 棋盘 7×3 / 7×5 却套在一个大得多的外框里，四周大面积留白。
- 方向键十字中 ▶ ▼ 比 ◀ ▲ 大一号。
- 「步数 0 · 最少 5」悬在方向盘上方空白处。
- 无选关入口；无"推错/无解"的提示。

🔴 墙壁用明显不同的颜色/厚度（这是本作最基础的可读性）。
🔴 目标点改成高对比度的实心标记（如黄色圆环 + 内点）。
🟠 方向键统一尺寸、紧贴成一整块十字。
🟠 加选关列表（20 关，没有选关很劝退）。

### 3.24 星际弹幕 Shmup

- 开始页三行玩法说明写得清楚。
- **开始页漏出战斗 HUD**（分数/火力/生命/波次/蓝色进度条全部压在标题页上）。
- 战斗中玩家与敌机都是三角形、靠颜色区分；生命图标是没标签的小尖角。
- 顶部蓝色进度条没有说明。
- 无暂停、无中途退出（只能被击落才有结算）；站着不动 10 秒内即被击落。

🔴 开始页隐藏整个战斗 HUD 层（用同一个 `active` 管理器统一控制）。
🟠 补暂停按钮 + 暂停菜单（继续 / 重开 / 返回大厅）。
🟠 给进度条加标签（"本波 3/8"）。
🟡 生命图标改成心形/飞机图标并加数字。

### 3.25 雷霆战机 Thunder

- 关卡页 2 列 10 关，锁定原因写明（"通关第 N 关解锁"），机库四条升级线信息完整、买不起会弹「金币不足」。
- 战斗中右上「II」圆钮与右下「炸弹 1」巨大橙色圆钮**比飞船更抢眼**；生命是没标签的蓝色小三角。
- 数值节奏：飞 15 秒被杀只拿到 10 分 / 3 金币，而最便宜升级要 100 金币 —— **约 30+ 局才能升一级**。
- 打击感弱：没有爆炸、没有震动、没有飘字，几乎感知不到打中了什么。

🔴 前期金币产出与升级价格的比值失衡（建议失败也给 30–50 金币，或首关通关奖励 ≥ 150）。
🟠 加击中/击毁特效与数字飘字（这是"射击游戏好不好玩"的核心）。
🟠 「炸弹」按钮缩小到与普通按钮同级，避免抢视觉焦点。
🟡 生命图标加数字；关卡页裸数字「3」改成「金币 3」。

## 5. 可复现的复查方式

每条问题都可以在预览页按下面方式复现（坐标换算见 `docs/tech/browser-verify-cocos-preview.md`）：

```js
// 浏览器控制台 / 页内 eval
const c = document.querySelector('canvas');
const r = c.getBoundingClientRect();
const s = cc.view.getScaleX();               // 本机 0.53046875
const toCss = (x, y) => [r.x + 6 + x * s, r.y + (679 / s - y) * s];
// 例：把任意 Label 的设计坐标转成 page.mouse 的点击坐标
```

- **返回按钮是否存在且激活**：遍历场景找 `Button` 节点，打印 `activeInHierarchy`。
- **文案/数值是否溢出**：读取同一父节点下所有 `Label` 的 `worldPosition` 与 `UITransform.height`，检查矩形是否相交（本报告里"状态行被按钮压住""标题被泡泡压住"就是这么确认的）。
- **布局留白**：截图后按内容区上下边界量占比。
