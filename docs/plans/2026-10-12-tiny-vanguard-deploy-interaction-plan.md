## 1. 背景

上一轮修复战斗界面后，遗留两个体验问题：

1. **血条视觉反常**：掉血时填充从两端同时向中心收缩，读感像"血条从中间被吃掉"。
2. **布阵交互单一**：只有"点卡片 → 点格子"两步点击；不记忆上一场布局；左侧兵牌在已上阵后没有"兵还在、已上场"的反馈。

---

## 2. 现状核实（浏览器探针实测）

### 2.1 血条：当前是"居中收缩"

`UnitController.updateHealthBar()` 把 `HpBar`/`HpFill` 锚点设为 `(0.5, 0.5)`、`x = 0`，只改宽度。实测（战士 8 血，血条世界范围 `[55, 105]`）：

| 血量 | 填充范围 | 宽度 | 填充中心 |
|------|---------|------|---------|
| 8/8 | `[55, 105]` | 50 | 80 |
| 6/8 | `[61.3, 98.8]` | 37.5 | 80 |
| 4/8 | `[67.5, 92.5]` | 25 | 80 |
| 2/8 | `[73.8, 86.3]` | 12.5 | 80 |

**中心恒为 80** → 两端同时内收。这是上一轮修"血条偏右 27px"时一并设成居中的副作用，非设计决定。

### 2.2 布阵：不记忆、无拖拽、无站台反馈

| 项 | 现状 | 证据 |
|----|------|------|
| 布局记忆 | **无** | `BattleManager.startBattle()` 里 `_deployedPositions = []`；单位起始 `{row:i, col:-1}`（棋盘外）；`RunData` 无布阵字段 |
| 拖拽 | **无** | 全项目 `grep TOUCH_MOVE / TOUCH_START` 零命中；交互仅 `onDeployCellClicked` |
| 兵牌 | 运行时创建的 110×64 卡片，纵向三行 | `PlatoonCard_0..2` 世界 `x∈[40,150]`，`y` 分别 `[408,472]/[484,548]/[560,624]` |
| 站台容器 | **声明的 `DeployUnitList` 从未被使用** | `active=false`、`children=0`；卡片实际挂在 `BattleUI` 根下 |
| 兵牌背景 | **`spriteFrame = null` → 背景不可见** | 卡片 `Sprite` 只设了 `color` 却从未设贴图，实测 `spriteFrame: null`；实际只有 `IconLabel`/`NameLabel` 两个文字可见（与 `HpBar` 同类缺陷） |
| 既有重叠 | 兵牌与棋盘第 0 列**重叠 30px** | 兵牌 `x∈[40,150]`，棋盘 col0 `x∈[120,200]` |

### 2.3 可直接复用的现成能力

- **`positionToGrid()` 已就绪**：入参为**相对 `Grid` 节点的本地坐标**。实测 `cell(0,0)` 本地 `{-200,-200}` → `{row:0, col:0}` ✓。拖拽落点判定无需新写换算。
- **棋盘格带 `Button`（`transition=SCALE`）会吞触摸** → 拖拽必须走**坐标换算**，不能依赖事件命中格节点。
- `getUILocation()`（设计分辨率坐标）在本项目等于世界坐标（实测画布中心 `(360,640)`、范围 `[0,720]×[0,1280]`）。
- 默认九宫格贴图 uuid：`7d8f9b89-4fd1-4c9f-a3ab-38ec7cded7ca@f9941`（格子与单位都在用）。

## 3. 方案设计

### 3.1 血条：左端固定、右端收缩

保持**容器 `HpBar` 居中于单位**（锚点 `(0.5,0.5)`、`x=0`、宽 50），把**内部 `HpFill` 改为左端贴合容器左缘**：

| 属性 | 现在 | 改为 |
|------|------|------|
| `HpFill` 锚点 | `(0.5, 0.5)` | `(0, 0.5)` |
| `HpFill` 位置 x | `0`（居中） | `-25`（= 容器左缘） |
| `HpFill` 宽度 | `50 × ratio` | `50 × ratio`（不变） |

结果：`8/8 → [55,105]`、`4/8 → [55,80]`、`2/8 → [55,67.5]` —— **左缘恒为 55，右端随血量后退**。

### 3.2 布阵布局持久化

`RunData` 新增可选字段，兼容旧存档（缺失则走默认阵型）：

```ts
export interface RunData {
  // ...既有字段
  /** 上次布阵结果（按 playerClasses 下标）；null=该单位未上阵 */
  deployLayout?: ({ row: number; col: number } | null)[];
}
```

- **写入**：`onConfirmDeploy()` 成功时把当前布阵回写 + `SaveManager.saveRun()`。
- **读取**：`startBattle()` 时按 `deployLayout` 落位。
- **兜底**（任一不满足即整体回退默认阵型，避免半失效状态）：数组长度与单位数一致、`row ≤ 1`、不在两单位间冲突、不与敌人初始位置冲突。

### 3.3 拖拽：兵牌 ↔ 棋盘双向 + 棋盘内换位

职责划分：**`BattleUI` 管触摸与视觉，`BattleManager` 管规则**。

```ts
// BattleManager 暴露（规则层，无视觉）
canPlaceAt(unitIndex: number, pos: GridPosition): boolean   // row<=1 且未占用（排除自身）
placeUnit(unitIndex: number, pos: GridPosition): void        // 复用 onDeployCellClicked 的落子分支
unplaceUnit(unitIndex: number): void                         // 复用 selectDeployUnit 的撤回分支
swapUnits(indexA: number, indexB: number): void              // 新增：场上两兵互换
```

`BattleUI` 的手势状态机（命名方法，满足 AGENTS 红线 5）：

| 阶段 | 行为 |
|------|------|
| `TOUCH_START` | 提起"幽灵"节点跟随手指；原单位/槽位置为拖拽态（半透明） |
| `TOUCH_MOVE` | `getUILocation()` → `convertToNodeSpaceAR` → `positionToGrid()`；高亮落点（可放 = `GRID.DEPLOYABLE` 绿，不可放 = `GRID.DEPLOY_DISABLED` 灰）；`TOUCH_MOVE` 超过阈值（约 8px）才判定为拖拽，避免误伤点击 |
| `TOUCH_END` | 落在合法格 → `placeUnit` / `swapUnits`；落在兵牌区 → `unplaceUnit`；否则回位 |
| `TOUCH_CANCEL` | 回位，不改变状态 |

**保留点击作为兜底**：点卡片选中 → 点格子放置（现有路径不动）。拖拽是叠加能力，不替换。

### 3.4 站台槽位：已上阵显示"空站台"

左下角从"卡片列表"改为**固定槽位**（复用那个空置的 `DeployUnitList` 作为容器，或直接命名 `DeploySlot_i`）：

| 状态 | 外观 |
|------|------|
| `unplaced`（未上阵） | 实心 `SURFACE` 底 + 单位图标 + 名字 |
| `selected` | `PRIMARY` 底/描边（现有） |
| `placed`（已上阵） | **空站台**：底色压暗、图标与名字淡化，边框用该单位**职业色**描边表示"兵还在、已上场" |

> **一处资源约束需明示**：真正的"虚线框"需要一张虚线贴图，项目当前**没有**该资源。两个选项：
> - **(a)** 用 4 条细 `Sprite` 拼**实线**边框（无需新资源，推荐）；
> - **(b)** 若要真虚线，需先补一张 9-slice 虚线贴图（新增美术资源）。
> 方案默认 **(a)**，若你要 (b) 请告知。

### 3.5 顺带修掉兵牌与棋盘的重叠

兵牌改槽位时把宽度收到 100、中心左移到 `local x = -300`（世界 `[10,110]`），与棋盘 col0 `[120,200]` 留出 10px 间隙。左侧可用区仅 120px 宽，属**紧贴排布**，需在验证时确认不越界。

## 6. 风险与验证

| 风险 | 说明 | 对策 |
|------|------|------|
| 棋盘格 `Button` 吞触摸 | `transition=SCALE` 的格节点会拦截 `TOUCH_*` | 拖拽全走坐标换算，不依赖格节点事件 |
| 拖拽与点击冲突 | 轻触会被误判成拖拽 | `TOUCH_MOVE` 位移超阈值（≈8px）才算拖拽 |
| 单位选中缩放 tween 干扰 | 拖动时 `setSelected` 的 1.08 缩放 tween 会拽动节点 | 拖拽期间停止该 tween，结束后恢复 |
| 旧存档兼容 | `deployLayout` 缺失 | 字段可选 + 校验失败整体回退默认阵型 |
| 左侧空间紧张 | 兵牌区仅 120px 宽 | 槽位宽 100；验证时确认不越界、不与棋盘重叠 |
| `HpFill` 锚点写入 | MCP 写 `anchorPoint.x = 0` 会被吞（仅影响 MCP 场景侧） | 本方案在**代码**里 `setAnchorPoint`，不受影响 |

**验收口径**（每阶段复跑）：
1. 血条：`8/8 → 4/8 → 2/8`，填充**左缘恒定**、右端单调后退。
2. 布阵记忆：打一场 → 撤回路线图 → 再进战斗，布局与上次一致；清存档后走默认阵型。
3. 拖拽：兵牌→棋盘、棋盘→兵牌、场上 A↔B 换位三条路径，落点高亮正确、非法落点回位。
4. 站台：上阵后槽位显示空站台 + 职业色描边；撤回后恢复实心。
5. 量化审计：战斗各态**重叠 0 / 越界 0 / 字号违规 0**。
6. `tsc --noEmit` 通过；`git diff --check` CLEAN。

## 7. 实施偏差（2026-10-17 复查补记）

实施与上表逐条对齐验证时，发现四处**落地时有意偏离**。本节是唯一的现状口径，**下文与本节冲突时以本节为准**。

| # | 方案原文 | 实际实现 | 原因 |
|---|---------|---------|------|
| 1 | §3.4 / §5 #4 / 验收 4：`placed` = 底色压暗 + 图标名字淡化 + **职业色描边** | **纯地面空格**：暗色凹坑（`SLOT_EMPTY_BG` + `SLOT_EMPTY_BORDER`）+ **隐藏图标与名字** | 见下 |
| 2 | §3.3：`TOUCH_CANCEL` = 回位、不改变状态 | 桌面（`navigator.maxTouchPoints === 0`）把 CANCEL 当作**手势正常结束**照常结算；真机才回位 | 桌面拖拽抬起**没有** `TOUCH_END`，照搬"取消即回位"会让桌面拖拽永不生效（[`../tech/browser-verify-cocos-preview.md`](../tech/browser-verify-cocos-preview.md) §11.1） |
| 3 | §3.3：`TOUCH_START` 即"提起幽灵" | **位移超阈值后**才创建幽灵 | 否则轻触会闪一下幽灵；阈值分支另记录瞬时态 |
| 4 | §3.3："轻触会被误判成拖拽 → 阈值 ≈8px" | 阈值 8 **设计**像素（≈4.3pt）+ **"落空"手势显式退回点击回调** | 光靠阈值不够：实测横移 5 CSS 像素（≈9.2 设计像素）即越阈值，点击又被消费标记吞掉 → **点兵牌完全没反应**。详见同手册 §11.6 |

**偏差 1 的理由**：槽位与单位是**强绑定**的（槽位 `i` 恒等于 `playerClasses[i]`，一局内不可买卖替换），
所以"看到 slot0 空了"本身就说明是哪个兵上了场，再叠职业色描边属**冗余标识**；棋盘上的单位另带
职业图标可对照。撤回也不要求精确命中原槽位（拖到兵牌区任意位置即可）。`BattleUI._deployIcons` /
`_deployClassIds` 另留一份供**拖拽徽章**取职业色与图标 —— 徽章是方形的（72×72，与棋盘阵营光环同值），
即"落下去会变成的那个形状"。

> 若后续要恢复"职业色描边"，改 `setDeploySlotState` 的 `placed` 分支即可（数据已经在
> `_deployClassIds` 里）；但**不要**恢复图标/名字，那是偏差 1 真正要修的部分。
