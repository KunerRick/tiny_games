## 0. 使用方式（先读这一节）

1. **每款游戏必须按 ① 玩法收敛 → ② 美术优化 → ③ 效果复核 的顺序推进**，不允许先做美术再回头补玩法：美术是表现层，玩法结构一变，所有排版与特效都要返工。
2. 本文档是**排期 + 验收基线**，不是实施细则。开工某一款时，先在该款章节下补一份「本轮范围」小清单（只做列出的项），再动代码。
3. 每完成一款，回填本文档 §5 的进度表（状态 / commit / 复核结论），不要另起散落的临时记录。
4. 阶段三的「复核」是签收门槛，**没有浏览器实测截图与探针记录 = 未完成**，不因"代码看起来对"而放过（AGENTS.md 教训 D）。

### 0.1 三条铁律

| # | 铁律 | 说明 |
|---|------|------|
| 1 | **不扩品类、不加新系统** | 本轮目标是"把已有玩法做完整、做清楚"，不是加内容。任何"顺便加个新模式"的念头一律记到 §7 待议，不进本轮 |

### 0.2 统一验收口径（Definition of Done）

一款游戏"做完"必须同时满足：

- **玩法**：从大厅进入 → 完整一局 → 结算 → 重开/返回，全程无卡死、无死锁、无"只能杀进程"的状态；单局时长落在该游戏目标区间内（见各款章节）。
- **美术**：与 GameUIKit 色板一致（深蓝底 `#0B1220` / 面板 `#151F33` / 主色 `#38BDF8` / 主按钮 `#2563EB`）；关键元素 3 秒内可辨识；720 宽下正文 ≥ 20px、标题 ≥ 28px；无文字压线、无互相遮挡。
- **复核**：`tsc --noEmit` 通过；`project_refresh_assets` 后预览实测通过；浏览器 console 无 error；关键节点截图留档到 `docs/assets/`；涉及构建产物时补跑 `node tools/check-wechat-build.js`。
- **文档**：回填 §5 进度表；若推翻了原设计，补一段「与设计文档的差异」。

## 2. 阶段一：游戏玩法收敛完善

### 2.0 本阶段的定义

"收敛"= 砍掉半成品与低价值系统 + 补齐核心循环缺失的反馈 + 把数值调到能通关。具体只做四类事：

1. **闭环**：保证「开始 → 进行 → 胜负 → 重开」每一步都有明确状态与出口；
2. **决策**：每个关键节点让玩家做一次有意义的选择（不是纯等待）；
3. **节奏**：单局内每 30 秒至少有一次可感知的事件（收益、威胁、成长、选择）；
4. **数值**：给出目标单局时长，并用至少 3 局实测/模拟校准。

**明确不做**：新玩法模式、跨局养成、排行榜、联网、音频。

### 2.1 逐款任务

#### 2.1.1 战争进化（P0）

**目标单局时长：5–8 分钟。**

| # | 任务 | 做法要点 | 验收 |
|---|------|----------|------|
| G1 | 解决"无脑买经验" | 现在 50 金币买 20 经验可无限刷（`BUY_EXP`）。改为**每次购买价格递增**（如 `50 × 1.15^n`）或**每时代限购 N 次**，让"攒钱出高级兵"和"抢先进化"形成取舍 | 模拟/实测：两种策略胜率都不为 0，且无一种明显碾压 |
| G2 | 给玩家一个主动指令 | 增加**一次性「全军冲锋」**（冷却 45s）：8 秒内己方单位移速 +60%、攻速 +30%。只有一个按钮，不加新面板 | 按钮状态（可用/冷却）清晰；冲锋期间有全屏可感知反馈 |
| G3 | 战线纵深 | 现在所有单位挤在 `BATTLE_Y = 60` 一条线。按兵种给**渲染层**纵向偏移（近战 ±40、远程 ±70），逻辑坐标不变；同时让远程单位在进入射程后停步，不再继续前压 | 20+ 单位混战时能看出前后排；无逻辑行为变化（回归 `tools/verify-battle-fixes.js`） |
| G4 | AI 难度与节奏 | AI 出兵间隔加一档（普通/困难），困难档在玩家进化后 10s 内跟上；避免"玩家已未来时代、AI 还在原始"的单边碾压 | 困难档 5 局中玩家胜率约 30–50%；普通档约 50–70% |
| G5 | 失败可读 | 城堡被打爆时，结算面板明确显示**失败原因**（兵种克制 / 经济落后 / 城堡血量），并给一句下一次建议 | 结算文案不再只有"失败" |
| G6 | 统一进化口径 | 设计文档写"经验 + 金币"双门槛，但 `playerEvolve()` 只校验 `expRequired`，`AGE_CONFIGS.goldRequired` 实际未被消费。二选一：**真正扣金币**（并同步 UI 提示），或**删掉该字段**，避免配置误导后续调参 | 代码、UI、设计文档三处口径一致 |

**收尾判据**：连续 3 局（普通档）玩家可赢 1–2 局，单局 5–8 分钟，无单位卡在城堡内/互相重叠到看不见。

##### 战争进化 本轮范围（2026-11-07）

- **现状问题**：战场只占屏幕中部约 1/3；兵种渲染是纯色矩形，混战后不可辨；攻击无前摇/命中反馈；
  50 金币买 20 经验可无限刷，"攒钱出高级兵"与"抢先进化"没有取舍；AI 单一档位且玩家进化后不追赶；
  失败结算只有一句"失败"；`AGE_CONFIGS.goldRequired` 写在配置里但从未被消费。
- **本轮只做**：
  - 玩法：G1 买经验改为**价格递增 + 每时代限购 6 次**（`BUY_EXP`，`45 × 1.28^n`）；G2 新增「全军冲锋」按钮
    （冷却 45s / 持续 8s / 移速 ×1.6 / 攻速 ×1.3，含横幅 + 单位金色光环）；G3 近战 / 远程渲染层纵向分行
    （`UNIT_ROW`，逻辑坐标不变，远程进入射程后停步）；G4 AI 两档难度 + 玩家进化后的追赶窗口；
    G5 结算面板给出失败诊断 + 一句建议；G6 进化**真正扣金币**并返还 +200 进化奖励，三处口径统一。
  - 美术：V1 战场重排到屏幕纵向约 40%–55%（`Battlefield.ts` 运行时绘制天空/地面/跑道/暗角/时代装饰）；
    V2 六兵种 Graphics 剪影（`UnitArt.ts`）+ 脚下阴影 + 城堡放大 1.45 + 旗帜/护盾弧；
    V3 战斗反馈（攻击前摇挤压、命中闪白、远程弹道线、死亡碎裂、飘字）；
    V4 HUD 重排（运行时构建，大字号读数 + 图标/名称/价格/冷却的底部按钮）；
    V5 进化仪式（全屏扫光 + 时代横幅 + 按钮变色）。
- **明确不做**：新玩法模式、无尽模式、音频、贴图美术替换纯 Graphics、跨局养成。
- **目标单局时长**：5–8 分钟（普通档）。
- **验收用例**：
  1. 连续 3 局（普通档）玩家可赢 1–2 局，单局 5–8 分钟；
  2. 困难档 5 局玩家胜率约 30–50%，且玩家进化后 AI 不再长期停留在旧时代；
  3. 买经验按钮在满 6 次或金币不足时禁用，价格随次数递增可见；
  4. 冲锋按钮：可用 → 按下后进入 45s 冷却（读秒），期间全屏横幅 + 参战单位光环；
  5. 20+ 单位混战时能看出前后两排，且远程单位在射程边缘停步；
  6. 失败结算显示诊断（兵种 / 经济 / 城堡血量）+ 建议，重开与返回大厅均可用；
  7. 进化需要同时满足经验与金币，扣款后 +200，HUD 与设计文档口径一致。
- **实测记录**（2026-11-07，桌面预览 `http://127.0.0.1:7456/`，普通档）：
  - **平衡标定**：每档 8 局加速模拟（`w.update(0.05)` 紧循环；玩家侧策略完全镜像 `AI.ts`——保留 120 金币进化储备、60% 出最便宜兵、经验与金币同时够才进化、冲锋一就绪就用）。城堡血量三档对比：

    | `CASTLE_CONFIG.HP` | 胜率 | 单局中位数 | 时长区间 |
    |---|---|---|---|
    | 4800 | 7/8 | 7.0 分钟 | 3.7–11.0 分钟 |
    | **5200（采用）** | **4/8** | **6.1 分钟** | **3.7–8.5 分钟** |
    | 5500（初版） | 5/8 | 8.5 分钟 | 5.3–10.0 分钟 |

    5200 是唯一「胜率进 50–70% 且中位数进 5–8 分钟」的一档，因此定稿为 5200。
    **注意**：胜率对策略极敏感——同版本换成「见钱就出兵」（不留储备）的策略，8 局全负且 0 次进化。这正说明 G1 的取舍生效（抢科技 vs 爆兵），但也意味着**普通人机对抗下玩家必须学会攒钱进化**，否则必输。
  - 对局 1：**7.3 分钟，玩家胜**（中世纪 vs 原始时代，击杀 116，剩余金币 21）→ `docs/assets/2026-11-07-war_evo-result.png`
  - 对局 2：**8.7 分钟，玩家负**（敌方城堡剩约 1.3k，失败诊断正常显示「兵种整体落后一个时代」+ 建议）→ `docs/assets/2026-11-07-war_evo-lose.png`
  - 对局 3（流程实测，真实鼠标点击）：大厅 → 进入 → 强制打爆己方城堡 → 失败结算 → 「再来一局」（金币回 100、城堡回满 5200、单位清空）→ 再次失败 → 「返回大厅」（回到 Lobby）。**全程 console 0 error**。
  - **20+ 单位双排**：常态对局同屏峰值只有 6–10 个单位，故用 17v17（9 近战 + 8 远程/侧）构造场景验证：近战行 y≈42、远程行 y≈138，两排清晰可辨 → `docs/assets/2026-11-07-war_evo-mid.png`
  - **本次复核发现并修复的缺陷**：`WarEvo.onDestroy()` 里 `_backNode.off(...)` 在返回大厅时抛 `Cannot read properties of null (reading 'off')`——缓存的返回按钮节点已被场景先行销毁，`Node.off` 内部 `_eventProcessor` 为 null；每帧重复刷屏，实测一次返回大厅刷出 1200+ 条 error。改为 `if (isValid(this._backNode, true))` 后再解绑，复测 console 归零。

##### 战争进化 美术升级记录：卡通贴纸风 + 技能表现（2026-11-07）

上一轮（`a999b9d`）把玩法与版面收敛住了，但画面被反馈为「像色块」：兵种只在 39 个设计像素里作画、
两军**朝同一个方向**站立、整套配色只有一层平涂。本轮在「零贴图 / 零音频」红线内重做表现层。

**四条画法（`UnitArt.ts` 顶部注释即规范）**

| # | 规则 | 具体做法 |
|---|------|----------|
| 1 | 统一厚描边 | 主体 3.2pt、四肢 `width + 2.8pt` 深色描边（`#080E1A`），任何背景上都有硬轮廓 |
| 2 | 三色分层 | 由阵营混合色推导 `shade = mix(fill, 黑, 0.4)` / `light = mix(fill, 白, 0.5)`，靠明度而非撞色出体积 |
| 3 | 夸张比例 | 头部半径 11、武器外扩到 x≈28；地面 `y=-26`、头顶 `y=+26`，**吃满 56×56 画布**（旧版只用了 39pt 高，等于免费放大 1.33 倍） |
| 4 | 朝向镜像 | 一律「面向右」绘制，敌方在 `Unit.buildVisual()` 里对**剪影子节点** `setScale(-1,1,1)` —— 镜像子节点而不是根节点，避免激光兵的 `Label` 文字被翻成镜像、也不会打断已有的根节点挥砍补间 |

**六兵种的可辨识特征（关掉颜色也应分得清）**

| 兵种 | 剪影抓手 |

##### 战争进化 攻击动作（2026-11-07 追加）

美术重做后兵种「站着不动也能打」，反馈是「挨打和出手看起来一样」。这一轮给六个兵种都加上**挥击动作**，
需求原话是「穴居人的棒子可以挥动，举一反三」—— 所以目标是让每个兵种的武器按自己的方式动起来，
而不是统一抖一下。

**分层：武器必须能单独转**

`Graphics` 在 Cocos 3.8 **没有变换栈**（`cc.d.ts` 里只有 `Node.translate`），整张图一次性画死就再也转不动了。
因此把单位拆成两层节点：

```
Unit
└─ silhouette（剪影节点，承载阵营镜像 setScale(±1,1,1)）
   ├─ Graphics：drawUnitBody()   —— 躯干 / 头 / 腿 / 盾 / 盔缨等不动的一切
   └─ weapon（子节点，原点 = 手 / 肩关节）
      └─ Graphics：drawUnitWeapon() —— 只画武器，静止姿态即 +x 朝前
```

- 武器节点是**剪影节点的子节点**，所以敌方的镜像会自动继承 —— 同一个角度在两个阵营里天然左右对称，
  `Unit` 里不需要任何「敌方取反」的分支。
- 身体倾斜是直接写剪影节点的 `angle`，镜像会把角度翻向，**这一处才需要按阵营取反**
  （`leanSign = side === 'player' ? -1 : 1`）。
- `drawUnitSilhouette()` 仍然保留（身体 + 静止姿态武器合成一张），底部兵种按钮图标继续用它，不必改成双节点。

**为什么不用补间**

1. 同屏最多 20 个单位，每个单位挂一条攻击补间就正好顶到美术原则 A5 的「单屏 ≤ 20 补间」，再加上本来就有的
   受击闪白 / 伤害数字补间必然超；
2. 武器与身体是两级节点，两条补间会互相抢同一帧的属性；
3. 由 `tick()` 每帧按进度**求值**写进节点，天然可重入 —— 连击 / 换目标时只要重置 `_atkTimer` 即可，不用 stop 补间。

**三段时间轴**（`ATTACK_WINDUP_END = 0.34` / `ATTACK_STRIKE_END = 0.52`，`_atkDur = clamp(cooldown × 0.7, 0.18, 0.40)`）

| 段 | 进度 | 曲线 | 表现 |
|---|---|---|---|
| 蓄力 | 0 → 0.34 | `easeOutQuad` | 武器反向拉开到 `windAngle`，身体后仰 2.5° |
| 挥出 | 0.34 → 0.52 | `easeInQuad` | 过冲到 `hitAngle`，身体前倾到 5.5°（这一段的加速感是「有力量」的关键） |
| 收势 | 0.52 → 1 | `easeOutQuad` | 回落到静止姿态 |

**六兵种的挥击参数**（角度相对静止姿态，正 = 逆时针；`hitShift` 是挥出瞬间沿身前方向的位移）

| 兵种 | 关节 | 蓄力 | 挥出 | 动作读感 |
|---|---|---|---|---|
| 穴居人 | (10, −2) | +40° | −78°，+4px | 大棒从肩上抡到身前，幅度小了像抽搐 |
| 猛犸 | (21, 1) | +28° | −34° | 长鼻抬起再朝前甩下 |
| 骑士 | (3, 1) | −7°，−6px | +3°，**+10px** | 回抽 → 前刺，以位移为主 |
| 弓箭手 | (13, 0) | −16° | +5°，+3px | 拉弦时弓身后仰，撒放瞬间回弹 |
| 机甲 | (12.75, 0) | +16° | **+88°** | 垂着的拳头抡成上勾拳 |
| 激光兵 | (4, −3) | 0°，+1px | +6°，**−4px** | 几乎不动，靠枪口上跳 + 后坐 |

**特效要等「挥出」那一刻**

原来 `tryAttack` 一进函数就放挥砍弧 / 弹道，结果蓄力还没做完箭已经飞出去了。现在把 `playAttackMotion()`
提前到结算之后、弹道之前调用，并把 `_atkDur × 0.34` 作为延迟传给 `spawnProjectile()` / `spawnSwingArc()`：
箭矢、激光束、枪口火花都在武器真正挥到位时才出现（延迟路径用 `opacity = 0` + `delay().to(0.001, …)` 显式点亮，
不能只写淡出，否则永远不会显示）。

**顺带修的：受击闪白糊成白团**

闪白原本把身体与武器**连描边一起**刷成纯白，正好盖住挥击命中那一帧 —— 玩家只看见一团白块，反而看不出谁挨打。
现在只把填充提亮到暖白（`rgb(255,246,232)`），描边保持深色，单位在闪白期间仍然可辨认。

**验收记录（浏览器实测）**

- `tsc --noEmit` 通过；真实对局跑 20s + 6s，`console` / `pageerror` **0 条**。
- 真实战斗采样到完整角度序列：`0° → +39°（蓄力）→ −37°（挥出）→ 0°`，`_atkDur = 0.40s`。
- 节点无泄漏：`UnitContainer` 共 47 个节点 / 5 个存活单位 ≈ 9.4 个/单位（单位固定骨架 9–11 个）。
- 逐兵种放大到 1.85× 定格复核：六个兵种的挥击姿态都能一眼读出，敌方镜像自动对称。
- 截图：蓄力瞬间 → `docs/assets/2026-11-07-war_evo-attack-windup.png`；
  挥出瞬间 → `docs/assets/2026-11-07-war_evo-attack-strike.png`。

## 3. 阶段二：美术优化

### 3.0 统一美术原则

| # | 原则 | 落地要求 |
|---|------|----------|
| A1 | **一套色板** | 所有新绘制元素从 `GameUIKit.UI` 取色；阵营色固定：玩家/友方 `#38BDF8`、敌方 `#EF4444`、奖励 `#F59E0B`、成功 `#22C55E` |
| A2 | **剪影优先** | 单位/物件先保证"关掉颜色也能靠外形分清"；颜色是第二层信息 |
| A3 | **层级靠明度** | 背景最暗（`#0B1220` / `#111B2E`），实体中亮，反馈最亮；不靠高饱和撞色制造层级 |
| A4 | **反馈三件套** | 任何命中/受击/获得：① 闪白或缩放 ② 数字/文字飘出 ③ 短促位移或粒子（≤ 0.3s） |
| A5 | **动效克制** | 单屏同时运行的补间 ≤ 20 个；循环动效（呼吸光）只用于关键可点击元素 |
| A6 | **性能** | 同屏对象 ≥ 100 时仍保持 60 FPS；批量绘制优先，不为每个敌人建独立节点（幸存者已有此约束） |

## 6. 排期与批次

> 每批内严格按 ①→②→③ 推进；一批做完并签收后再开下一批，避免同时改 8 款导致回归无法定位。

| 批次 | 内容 | 预估 | 理由 |
|------|------|------|------|
| **A** | 战争进化（玩法 + 美术 + 复核） | 3–4 人日 | 玩法与画面短板都最明显，改完收益最高 |
| **B** | 数值冲刺（补复验 + 修标签）、合合大作战（玩法 + 美术） | 2–3 人日 | 一款是欠账，一款是纯表现层投入产出高 |

## 8. 风险与红线

| 风险 | 规避 |
|------|------|
| 改 `.ts` 后预览仍跑旧代码，误判修复无效 | 每次改完先 `project_refresh_assets` 再重载（教训 D） |
| 面板懒初始化导致 `onLoad` 不执行 | `show()` 里先置标记再 `active = true`；事件在 `show()` 绑定 |
| 拖拽/手势在桌面结束事件是 `TOUCH_CANCEL` | 手柄、挡板、牌堆、布阵拖拽统一同时监听 `TOUCH_END` + `TOUCH_CANCEL`；监听挂共同父级 |
| 匿名 lambda 无法解绑 | 全部用具名方法（红线 5） |
| `onDestroy` 访问 `@property(Node)` 崩溃 | `onDestroy` 只清理 JS 引用（红线 4） |
| 同回调自排期被引擎丢弃 → 回合卡死 | 用「时间点 + `update()` 泵」+ 看门狗（教训 F） |
| 中文 `.ts` 被 PowerShell 重编码 | 只用 UTF-8 文件工具编辑（红线 1） |
| 场景/预制体被直接改坏 | 一切场景改动走 MCP（红线 2）；改前 `begin_undo_recording`，改后 `validate_scene` |
| 一次改太多无法定位回归 | 一批不超过 2 款；每款按 玩法 → 美术 分两次提交 |
