## 4. 方法与数据说明

### 4.1 视口与坐标（现场标定）

| 项 | 值 |
|---|---|
| 视口 | 1280 × 720（iPhone 14 Pro 模拟） |
| `canvas` rect | `{x:443.5, y:41.45, w:393, h:678.55}` |
| canvas 缓冲 | 393 × 679 |
| 设计 → CSS 比例 | `scale = 720 / 393 = 1.832`，`padY = (678.55×1.832 − 1280)/2 = −18.43` |
| 点击入参 | 直接用 CSS 坐标（`page.mouse.click`，本轮 k = 1，未出现偏移） |

世界坐标（Canvas 中心为原点）→ CSS：`cssX = rect.left + wx/scale`、`cssY = rect.bottom − (wy + padY)/scale`。关键点位实测：饰品页签 (424,1118)、两槽 (200/520,1040)、装备到槽 (255,100)、卸下 (465,100)、返回 (628,1180)、列表行 y = 810/750/690/630，与简报给的设计坐标一致。

读 `GameRoot` 上 `MithrilGame`（`_save`、`_mode`、`_core.trinkets`、`_lastSnapshot`）、`EquipMenu` 上 `MithrilMenu`（`_tab`、`_slotSel`、`_tPage`、`_tSlotBtns`、`_tRowRoot`、`_tSynergyLabel`、`_tDetailBody`、`_tHintLabel`、`_tEquipBtn`/`_tUnequipBtn`）、HUD（`_procLabel`、`_resultTitle/Body`）。饰品协同颜色读 `_tSynergyLabel.color`（不依赖 Button 过渡色）。

## 5. 未复现 / 已排除的疑点

1. **「落雷是一条贯穿全屏的紫线」——不是缺陷**：设计即「竖线紫电」，从屏幕顶部落到命中点，`r16-05-proc-0.png` 可见；HUD 文案同时为中文。
2. **「HUD 协同文案短暂为空」——不是缺陷**：`_procs` 有「协同 · 雷音」时 `_procLabel` 有一次采样为空，下一次采样即显示；属 1.5s 淡出刷新时序，不是漏文案。
3. **「已拥有 4/20 但 trinketBag 只有 2 件」——不是缺陷**：bag 只存未装备，已装备的两件在 `trinkets`，UI 计数为并集。
4. **「卸下后协同栏不是『空』而是提示句」——符合预期**：熄灭后回灰色提示「两件不同 tag 的饰品同时装备可点亮（共 12 条）」，颜色 `(156,163,175)`。
5. **「同一件装两格」——已被拦截**：提示「装备失败：同一件不能占两格 —— 先卸下另一格」，存档未变。
6. **N53（上轮）已修**：副本内阵亡结算现在明确写「本次远征结束：本程节点进度不保留，需回路线图重新「开始远征」」，与 `expedition = null` 一致（`r16-08-death-settle.png`）。
