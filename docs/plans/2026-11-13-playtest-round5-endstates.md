## 一、方法（以及本轮新踩的三个坑）

### 1.1 流程

1. `cc.director.loadScene('<SceneName>')` 进场景；
2. 为省时间，**先直接驱动游戏内部状态**把局面推到终局（例如 `core.player.hp = 0`、
   `core._killEnemy(boss, true)`、`w._hitPlayer()`），而不是真的打满 8 分钟；
3. **面板出现后一定不偷懒**：用 `camera.worldToScreen()` 反算屏幕坐标，
   对每个按钮做真实 `mousedown`/`mouseup`，再读回场景名 / 面板 `active` 确认结果；
4. 每个面板截图留证到 `.playwright-mcp/r5-*.png`（不进 git）。

> 原则：**"面板长得对" 不算验过，按钮点下去之后状态变了才算**。
> 本轮 P1 恰恰是"长得对但点不动"，只截图会完全漏掉。

### 1.2 坑 1：`_startBattle()` 会换掉整个 world 对象

雷霆战机 `ThunderGame.ts:598` 的 `_startBattle()` 里 `this._world = new ThunderWorld(...)`。
我先把 `g._world` 存进变量 `w`，再调 `_startBattle()` 换关，之后一直读旧的 `w` ——
于是 `w.lives` 永远是旧值，"复活没生效 / 血量被重置"的结论全是假的。

> 判据：`g._world !== w` 就说明你手上的引用已过期。
> **任何"重开一局 / 换关 / 换难度"的入口之后，必须重新取一次组件内部对象。**

### 1.3 坑 2：强制结束要打中正确的穴位

- **幸存者**：胜利只由 Boss 被击杀触发（`SurvivorCore.ts:1017-1021`）。
  把 `core._time` 推到 479.5 不会赢 —— `BOSS_TIME = 450`（`SurvivorConfig.ts:408`）
  只是"刷 Boss 的时间点"，不是"游戏结束的时间点"。
- **扫雷**：`_onCellTap()` 里 `_flagMode` 与 `flagged[i]` 的分支会把点击吃掉，
  选了一个已插旗的格子，状态一直是 `playing` —— 第一次"点了没反应"是我的筛选条件写错了。

### 1.4 坑 3：截图默认落在仓库根目录

`browser_take_screenshot` 不传 `filename` 时文件写进当前目录，
`git status` 立刻多出一坨 png。统一显式写成 `.playwright-mcp/r5-*.png`。
（本轮已把一张误落根目录的图 `mv` 走，`git status` 恢复干净。）

## 四、本轮新发现

### P1-1　四款游戏的结算面板吞掉返回按钮，且面板里没有「返回大厅」

**症状**：扫雷 / 数独 / 成语填字 / 缤纷消除 一旦出结算，
左上角返回按钮**画得清清楚楚**，但点下去毫无反应；面板上只有
「再来一局」「换个难度 / 下一关」—— 想回大厅只能先重开一局，再退出。

**根因**（四款代码结构完全一致）：

| 游戏 | 遮罩创建 | 吞事件注册 | 面板按钮 |
|---|---|---|---|
| 缤纷消除 | `Match3Game.ts:695` `_showResult` | `:699`（handler `:257-261`） | `:731` 下一关 / `:737` 重来 / `:744` 再玩一次 |
| 扫雷 | `MinesweeperGame.ts:642` `_showOverlay` | `:651`（handler `:96-98`） | `:699` 再来一局 / `:710` 换个难度 |
| 数独 | `SudokuGame.ts:597` `_showOverlay` | `:604`（handler `:75-76`） | `:653` 再来一局 / `:664` 换个难度 |
| 成语填字 | `IdiomGame.ts:624` `_showOverlay` | `:632`（handler `:81-82`） | `:689` 再来一局 / `:701` 换个难度 |

四点叠加才构成"锁死"：

1. 遮罩是 **720×1280 全屏**节点（不是只有面板那块 580×470）；
2. 它作为 `GameRoot` 的**后置兄弟**创建，盖在返回按钮之上；
3. 它监听 `TOUCH_START` 并设 `ev.propagationStopped = true` ——
   触摸根本不会分发到同级的返回按钮（**同级节点之间也没有冒泡**）；
4. 面板里**没有**返回大厅按钮，于是没有任何一条代码路径能离开这个场景。

**实测证据**：缤纷消除里按 Esc / 点返回键均无响应；
点「下一关」把遮罩销毁后，同一个坐标点返回键**立刻**回到大厅 ——
说明返回按钮本身是好的，纯粹是遮罩挡的。

**建议（二选一，优先 ①）**：

- ① **补一枚「返回大厅」按钮**，和五子棋 `GomokuGame.ts:672-760`、
  台球 `PoolGame.ts:291-355`、推箱子 `SokobanGame.ts:589-670` 保持一致。
  四款的 helper 已经有 `createButton(panel, {...})`，加一个按钮就是几行，
  且能顺带统一"结算三件套"的观感。
- ② 若想保留"全屏遮罩 + 只有两个按钮"的版式：
  把遮罩 `setSiblingIndex(0)` 画到返回按钮**之下**，并且
  只对面板区域（580×470）设 `propagationStopped`，让面板外的点击漏给返回键。
  注意仅改 ② 不改 ① 的话，玩家仍然没有显式的"回大厅"出口，只是能点左上角。

> 影响面：这四款恰好是"一局很短、结算频繁"的类型（扫雷、数独、三消），
> 玩家连续玩几局的概率最高，被锁在结算页的体感最差，因此判 P1 而非 P2。

### P2-1　纸牌接龙首次发牌不计入「局数」，战绩读出「胜局 1 / 0（0%）」

**症状**：新玩家第一局赢下后，战绩面板显示 `胜局 1 / 0（0%）` —— 分子大于分母。

**根因**：

- `SolitaireGame.ts:464-486` 的 `_restoreOrDeal()` 在**没有存档**时也直接
  `this._startNewGame(false)`（`:486`），传 `countAsPlayed = false`；
- `_startNewGame(countAsPlayed)` 只在为 `true` 时 `this._stats.played += 1`（`:512`）；
- 而 `_onWin()` 无条件 `this._stats.won += 1`（`:1477`）；
- 显示在 `:1644-1651`：`胜局 ${won} / ${played}（${rate}%）`。

也就是说**首局是"凭空发"的**：赢了算胜局，输了不计局数；
只有玩家主动点「新游戏」（`:1398-1409` 传 `true`）才开始正确计数。

**建议**：`_restoreOrDeal()` 里"确实没有存档、需要新发一局"的分支改成
`_startNewGame(true)`；如果作者的意图是"恢复存档那次不重复计数"，
那就把判断写清楚（有存档走 restore 分支，无存档走 `true`），别用同一个 `false` 兜两种语义。
另外战绩面板建议加一道 `won = Math.min(won, played)` 的防呆，旧存档里已经被污染的
`won > played` 数据也能自愈。

### P2-2　冰箱死亡结算文案 5 行、34 号字、几乎顶满 720 宽

**实测读数**（`FridgeHud.ts:149` 的 `Dead` 标签）：

```
字号 34，节点宽 676.21，overflow = NONE
行长度（字符）：5 / 28 / 7 / 12 / 22
最宽一行：第 1 层 · 得分 5 · 击杀 0 · 坚持 1 秒
```

文字节点声明宽 640（`_makeLabel('Dead', 0, 40, 34, HAlign.CENTER, 640)`），
但 `overflow = NONE` 会按内容撑开，实际 676 —— 在 720 宽的设计画布上
**左右各只留 22 设计像素（≈12 CSS 像素）**，截图 `r5-fridge-death.png` 里
最宽一行基本贴边。而这段文案是死亡后**唯一的信息块**（`:322-326` 拼 5 行），
信息密度也偏高：档位 / 得分 / 击杀 / 时长挤一行，"冰箱贴 +1（失败折半）"
和操作提示各占一行。

**建议**：
① 把第 2、3 行合并成两行短句（如 `第 1 层 · 坚持 1 秒` / `得分 5 · 击杀 0`），
② 或把整块字号从 34 降到 26–28 —— 死亡摘要不需要这么大声；
③ 顺手给第 4 行「冰箱贴 +1（失败折半）」单独换个强调色，
现在 5 行同色同字号，玩家扫不出重点。

### P2-3　结算遮罩下的底层按钮仍然发亮，看起来能点但点不动

**症状**：扫雷 / 数独 / 成语填字 出结算后，遮罩是 84% 左右不透明的深色，
底下的「插旗模式：关」「重开一局」等底栏按钮**颜色只暗了一档，轮廓依旧清晰**，
读起来像"还能点"。加上 §P1-1 的吞事件，玩家会先点几次底栏、再点左上返回，
连续几次"没反应"后才去找面板上的按钮。

**判据**：这不是独立 bug，是 P1-1 的观感放大件 —— 遮罩要么足够暗（≥92%）
让底层彻底退到背景里，要么就别盖住底栏（缩到顶栏以下）。

**建议**：与 P1-1 一起改。若选 P1-1 的方案 ②（遮罩缩到面板区），本条自动消失。

### 观察项（不建议改）

- 雷霆战机失败结算页底下仍露出顶栏「生命 ×2」：这是强推终局造成
  （真实路径下死亡时血量归零，顶栏会显示 ×0），属测试产物。
- 扫雷强推胜利时「最佳 00:00」：亚秒通关的产物，真实游玩不会出现。
- 数独强推胜利时顶栏状态文字未刷新：同上，属探针绕过 `_checkEnd()` 的产物。
